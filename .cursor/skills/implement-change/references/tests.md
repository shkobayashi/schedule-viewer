試験名の節は、その節が偽のときに失敗する断言にする。`if` や `if let` の中だけに断言を置き、条件が偽のとき成功させない。あるクラスが付いていないことは、描画されている要素で断言する。要素が出ない状態の `null` だけでは、そのクラスが付いていないことの証拠にしない。回帰文書の `自動:` は、その行の手順を実行し、期待の文を断言する試験だけを書く。項目が違うツールの試験を、その行へ付けない。成功時に必ず出る見出しの有無だけでは、その手前の編集が結果に出たことにしない。失敗した断言を消したり、手動テストへ落として緑にするだけの変更はしない。本体の不具合を直すか、期待が誤っていると分かったときだけ断言を変える。

回帰文書の「自動:」参照は、その行の手順どおりの操作を実行し、期待を断言しているテストに限る。同じ機能 ID のテスト名を行へまとめて貼らない。`test.skip` で合格にするテストは自動済みに数えない。`#[ignore]` の試験も `自動:` に書かない。一部手動で `自動:` が無い行は手動のままへ移す。ignore と skip の試験名は `自動:` と Windows CI の切替一覧に書かない。待ちが上限まで失敗した試験は、上限を伸ばして無視しない。他の schedule-viewer を見つけたら、シグナルを送らず、ツールも引数も送らず失敗する。試験名の節が、外部仕様の前面順と違う窓を待っているときは、仕様の窓に直す。手順数は、その時点の `docs/regression.md` に書いてある本数から引き、98 から引き直さない。短い通しから引いた分数は、全体の見積からも同じ分数だけ引く。手順への分数の割り振りは見積として PR 本文にも書く。

新しい GitHub Actions のジョブには、実測した所要に基づく `timeout-minutes` を書く。Playwright の `globalTimeout` はテストプロセスだけを止めるので、依存の導入までその値で止まると書かない。タイムアウト時は進捗と原因を確認せず上限を伸ばさない。実行されなかったステップを、権限や成功の確認として書かない。Issue の終わりの条件のうち、その pull request では観測できないものが残るときは、本文を `Refs` にし、次に確かめることを書く。

`check-regression-coverage` の skip と ignore は、参照ファイルのその試験だけを見る。コメントや同名の別スイート・別ファイルでは落とさない。`describe.skip` の内側は落とす。偽陽性と見逃しを fixture で両方見てから通す。構文解析が万能ではないと文書に書く。実施範囲の索引と記録テンプレートは、含める手順の規則を同じ文にし、テンプレートの ID はその規則で数えた見出しと一致させる。

ブラウザ回帰を「自動済み」にする前に、テスト名の各節が本文で画面操作と断言に対応しているかを 1 本ずつ見直す。断言できない節は名前から外し、回帰文書の区分を手動のままか一部手動へ戻し、`手動のまま:` に残る確認を一文で書く。名前だけ合わせて自動済みにしない。ボタンを押せなくする試験は、外す前に同じ条件で押せることも見る。
