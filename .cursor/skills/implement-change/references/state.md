## 状態・モデル・描画・Tauri（原則 1 · 2 · 3 · 5 · 6 · 8）

画面の手順が変わらなくても、状態、計算、描画、ファイルの橋渡しを変える。

1. 検証、行、履歴、書き出す内容は `src/model/` の純粋関数に置く。ファイルの読み書きは Tauri 側に残す
2. 構成、状態、Tauri コマンド、描画の流れが変わるときは [docs/internal-spec.md](../../../../docs/internal-spec.md) を同じ変更で更新する
3. 純粋関数を変えたときは、対応する `src/model/*.test.ts` を更新する。`src-tauri/` のパス検査を変えたときは Rust のテストを更新する。バイト上限のある標準入力は、上限を超えた分を読み続けない。`take` などで読む上限は最大バイト数より 1 バイト大きくし、超えた入力のテストを同じ変更で置く
4. 非同期処理は、多重実行と `await` 中の状態変更を考慮し、処理中の ref または世代番号で古い結果を反映しない。明示の最新結果を画面へ載せたあと、同じ経路で保留していた古い自動結果を捨てる。計画が起動復旧のダイアログのあいだは起動復旧の拒否文を返すと書いているときは、`startupSettled` を下ろしたあともその文を先に返す。MCP の置き換えでは、編集拒否と保存形式が同じで何もしない成功を同じ戻り値にまとめず、拒否は `isError`、同じ内容は差分テキストの成功に分ける。状態と同時に参照する ref は同じ処理内で更新する。公開しているフックの戻り値を保ったまま、独立した状態機械は分割前に境界のテストを置いてから分ける。計画が、ダイアログを閉じてもコンポーネントが残り state が残ると書いているときは、親が開いているあいだだけマウントしていないかを見る。外しているときは、閉じたあとも残す値をコンポーネントの外に置く。処理を始めない条件に入ったときも世代を進め、進行中の結果を捨てる。早期 return だけでは捨てたことにしない。MCP で `discardInProgress` が無い拒否のあとは、`mcp_reply` の応答のあとにウィンドウ世代を進め、日付バーの離す確定、詳細パネルの blur 確定、一覧覆いの保存が古い世代を反映しない。`set_view` は渡した項目だけを替え、折りたたみは渡した種類だけを更新する。計画が明示のフラグを見え方の入力にすると書いているときは、そのフラグを純粋関数の引数にし、自動の空結果で明示を消さないことと、パス変更で表示を捨てることをテストする。計画が、確定と同じ呼び出しで JSON と提案ファイル名を更新すると書いたときは、両方をその呼び出しで更新した参照から読む。計画が、ダイアログを閉じるのを文書を置く処理と同じ同期処理にすると書いたときは、クリックの先頭でダイアログを閉じない。`await` の前に閉じると、失敗したときに中身が空のまま残る
5. ブラウザ版とデスクトップ版の両方にある入力は、サイズ上限、検証、エラー処理の差を意識したものか確認する。読み取りを共通化するとき、ブラウザでは空文字を欠落（null）にしていた処理を、`== null` や `?? null` だけにまとめない。デスクトップでは空文字を JSON 解析へ進めて形式エラーにしていた側と、欠落にしていた側が分かれないことを、同じ変更のテストで見る
6. チャートへ描き足すときは Konva の Layer を増やさず、既存の Layer の中の Group に足す。説明半透明（`explain_overlay`）のベールと抜きだけは、日付ヘッダー、マイルストン帯、本体それぞれの Stage 最上段に専用 Layer を載せてよい
7. チャートの x を日へ切り捨てるときは、日の左端が浮動小数で前日にならないようにする
8. 並べ替えの挿入位置は、動かしている要素を除いたあとの位置にする。受けない位置は、文書を変える関数が元を返すだけでなく、候補を決める関数でも外す
9. ディレクトリを入れ替えるときは、失敗しても元の中身を残す。親がシンボリックリンクのときはリンク先へ書かず、消さない。リンク自体を外すとき、リンク先は消さない。外す処理も、置くときと同じ親の検査を先に通す。検査に落ちたときは何も消さない
10. 文字の切り詰めと段の占有幅は、描画と同じ開始位置から測る。表示状態が覚える ID は、対象が文書から消えたときに外し、新しく現れた対象は表示する。文字幅を割合で見積もるときは、描く太さと表示サイズの範囲で実測し、見積もりが実幅を下回らない余裕にする。長い文字列だけでなく、幅の広い文字を含む文字列も見る。右へ足す日数とマイルストン名のホバー折り返しは、画面に出す文字列を、切り詰めと同じ見積もり（太字の余裕を含む）で測る。ホバーの位置は、乗った瞬間の座標ではなく、スクロール後の座標から決める
11. 複数のウィンドウが同じファイルを開くときは、控えの書き込みと削除はそのパスの前面のウィンドウだけが行う。終了は、各ウィンドウの閉じる確認がすべて済んでから閉じ、キャンセルしたときはどれも閉じない。終了で控えを書くウィンドウは、閉じ始める直前の前面に固定する。追加ウィンドウへ渡した内容は、起動時の復旧より先に載せる
12. 自動更新の破棄確認を開いたあと、戻り値だけをキャンセル扱いにしない。確定とキャンセルを待つ。控えの書き手は、終了と同じく全ウィンドウが受け入れたあとに固定し、そのあと各ウィンドウが書く。再起動で閉じるときは破棄確認を出さない。`latest.json` に今の OS が無い確認は失敗の知らせにしない。`Update` を持つウィンドウと「入れ直す」を押したウィンドウが違うときは、持つウィンドウがまだ開いていればそのウィンドウが `request_application_update` から進める。持つウィンドウを閉じたあとだけ、残ったウィンドウが再確認し、知らせの版と一致するときだけ未保存の処理へ進む。中断したら `cancel_application_update` で共有の `updating` を戻す。入れ直し中は「更新を確認」で通信しない
13. 最も早い日が後ろへ動いて、スクロールが左端でそれ以上戻せないときは、描画の原点を据え置き、他のバーを動かさない。全体表示とズームの最大スクロールは、据え置いた原点から、右へ足した日を含む終端までの日数で決める
14. 変更履歴は起動時のダイアログや `pending-release-notes.json` では出さない。デスクトップ版の設定「更新」が、同梱の CHANGELOG を欄内スクロールで出す
15. 自動更新で `downloadAndInstall` が処理を戻して失敗したとき、失敗の知らせはダウンロードまたは入れ直しの失敗だけに出す
16. `#[cfg(windows)]` の MCP 待ち受けをスレッドへ移すときは、セキュリティ記述子の生ポインタをスレッドの外で作って `Send` させない。名前付きパイプのハンドルも同じで、待つスレッドの外で作って渡さない。待つテストは、そのスレッドの中でパイプを作り、準備できたことを知らせてからクライアントを繋ぐ。応答を書いたあと、クライアントが読み終わる前にパイプを切らない。切ると、まだ読んでいない本体が os error 233 になる。クライアントが閉じるまで待ってから切る。名前付きパイプが使用中の次の接続は、ウィンドウが開いていない旨にしない。短い間隔で接続を試し直し、応答待ちと同じ秒数を過ぎたら応答が無いときと同じ文にする。使用中を一度見たら、そのあとの名前なしやハンドル状態の失敗も同じ期限まで試し直す。待ち受けがパイプを作り直すあいだに名前が消える。使用中の再接続を試すテストは、2回目の接続を切る前にクライアントがハンドルを閉じるまで待つ。先に切ると `SetNamedPipeHandleState` が失敗し、ウィンドウが無い旨になる。Windows の名前付きパイプのテストは、テストごとにパイプ名を分ける。macOS の `cargo test` ではこのコードはコンパイルされない
17. スキル本文へ実行ファイルの呼び方を書き込むとき、Windows でそのパスが Local AppData 配下なら、絶対パスを書かない。コマンド例は `"$LOCALAPPDATA/"` に続く相対パスと `--screen` とツール名を同じ1行にする。本文に `\AppData` を残さない。それ以外の絶対パスは、シェル引用で包まず、実行ファイルの行と `--screen` とツール名の行に分ける。パスと引数を同じ行のコマンド例に書かない
18. 取り消しややり直しで出す帯は、次の取り消し1回に結び付けない。戻した文書がその操作の直前であるときだけ出し、やり直した文書がその操作の直後であるときだけ消す。起点が動いたあとは、覚えていたディスク内容を捨てる
19. Windows では、既存 WebView のコマンドの中で `WebviewWindowBuilder::build()` をその場で待たない。追加ウィンドウは async コマンドと `run_on_main_thread` で作り、メインスレッド上で `build()` を同期的に呼ばない
20. 計画が、起動復旧の確認ダイアログのあいだは待って拒否文を出さない、と書いているときは、起動完了の通知と同じ時点で外部ドロップを配らない。ダイアログを閉じたあとに配り、待ちのあいだはキューを進めない
21. 同じ起動の二度渡しだけを1回にすると書いた重複排除は、処理し終えたあとの同じ入力まで捨てない
22. 2つ目のプロセスの引数は実行ファイルのパスを先頭に含む。落としたファイルの件数には、その先頭を数えない。ディレクトリは件数を数える前に除かない
23. キューを1件進める応答は、配りを受けたウィンドウが1回だけ送る。転送先は送らない
24. ダイアログが開いているあいだは拒む、と計画が書いたときは、ファイル操作の確認だけでなく、その時点で開いているダイアログを見る。詳細パネルの入力は、計画が除くと書いたときだけ除く
25. OS によって列挙子が無い Tauri のイベント（macOS だけの `RunEvent::Opened` など）は、その列挙子がある OS の `cfg` の中だけで参照する。その参照だけが呼ぶ関数は、他の OS で未使用警告になる。`cfg_attr` で `dead_code` を許し、`cargo clippy -- -D warnings` が Linux と Windows で通るようにする
26. 計画が失敗文を指定したときは、その文を返す処理が CLI の解析結果から `run_screen_cli` などの呼び出し元へ届くようにする。解析で `None` にして汎用の使い方の文だけにすると、計画どおりの文は出ない
27. 計画がツールの引数を触らないと書いたときは、別ツール用の引数整形（例: 読み取りの `window` を外す）をそのツールへ掛けない
28. 計画が同じ規則を MCP のツール説明とスキルの両方に書くと書いたときは、両方に置く。MCP だけに書いてスキルに無いと、MCP 利用時に規則が欠ける。計画が MCP のツール説明と read-screen の両方に置くと書いた語は、ツール説明のテストが通っても read-screen の本文に同じ連続した文字列があることを同じテストで確かめる。共有文の句は `MCP_VIEW_IN_READ_TOOLS` 定数と read-screen の両方に同じ連続した文字列があることを Rust のテストで確かめる。新しく足したツールの description 全文が read-screen にあることは、既存の句のテストとは別に確かめる。計画が同じ連続した文字列として語を並べたときは、その語を別の言い方に置き換えない。照合する句も、その語を含む
29. Windows API を `windows-sys` で呼ぶときは、`Cargo.toml` に書いた版のクレートで、その関数があるモジュールと feature を見てから使う。別の版にあるモジュール名だけで feature を足さない。`#[cfg(windows)]` の中は macOS の Clippy ではコンパイルされない。unsafe な関数は unsafe ブロックで呼び、Windows の `cargo clippy -- -D warnings` が通る形にする
30. 計画が文書の入口を関数名で挙げたときは、同じフックで文書を差し替える残りの関数も照合し、同じ片付けや副作用が抜けていないかを見る
31. `src/model/` でシンボルを再エクスポートするときは、import ブロックの途中に `export` を挟まない。import をまとめたあとに `export { ... } from` を置く（`tasks.ts` の `forEachTask` / `mapTasks` と同型）。**ガード:** P-AG-06（review-implementation「model の export 配置」）
