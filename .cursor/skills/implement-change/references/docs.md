## 文書（原則 1 · 4）

どの文書を同じ変更に含めるかは [docs/agents-doc-update-map.md](../../../../docs/agents-doc-update-map.md) に従う。通常の不具合修正では [docs/PLANNING.md](../../../../docs/PLANNING.md) は更新しない。利用者に見える変更をリリースへ入れるときは [CHANGELOG.md](../../../../CHANGELOG.md) も更新する。計画が REVIEW.md の指摘を扱うときは、対応または見送りを同じ変更で REVIEW.md に書く。

既存の段落へ別機能の制約を足すときは、うしろの文の主語が新しい機能に掛からないよう、段落を分ける。

同じ段落の前の文が、今回の挙動と食い違うときは、うしろへ足すだけでは終えず、前の文も直す。

ツールの個数を書いた文は、表に行を足した同じ変更で、本文の数も数える。

計画が開いている画面ではファイルを書かない例外を名指ししているときは、スキルの「ファイルを書くとき」がその例外を読まないように、例外を同じ節へ書く。

計画が名指しした文書を足したあとは、同じ文書の古い表と手順が新しい形と食い違っていないかを見る。チュートリアルが名指しされているときは、スキルの個数と、アプリを起動しない書き方も揃える。

MCP-01 のツール文（説明文や表の1行）を変えたときは、同じ挙動を書いている機能節と [feature-checklist.md](../../../../docs/feature-checklist.md) の外向き行を同じ変更で読み直し、パーサが拒否する解除の形を書かない。

計画が読み取りの応答のうち載せないと書いたツールやキーがあるときは、載せる文のあとに、そのツール名やキーを書いて載せないと書く。別のキーを足さないと既に書いてあっても、今回載せたキーを書いたことにはしない。

既存の文へ追記するときは、その文に既にある語を重ねて足さない。

計画が文を変えずに移すと書いたときは、移した文を移す前の文と照合し、一語でも違えば戻す。`.github/workflows/ci.yml` の対象パスを変えたときは、[docs/development.md](../../../../docs/development.md) の CI の箇条書きを、先に当たる `case` と同じパスにする。計画が「同じ文言で書く」の指す先を変えると書いたときは、移した節だけ指す先を変える。
