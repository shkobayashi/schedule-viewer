## 画面と操作（原則 1 · 4 · 5 · 6 · 7 · 8）

利用者に見える挙動、操作、表示を変える。

1. `src/components/`、`src/hooks/`、`src/App.tsx` のうち、計画が指す箇所を変える
2. [docs/external-spec.md](../../../../docs/external-spec.md) を同じ変更で更新する
3. 操作の入口（ラベル、ショートカット、パレット、☰、macOS メニュー、右クリック、MCP 名）を増やす・変えるときは、[docs/agents-doc-update-map.md](../../../../docs/agents-doc-update-map.md) の「操作の入口」行どおり [docs/operation-entries.md](../../../../docs/operation-entries.md) と [docs/feature-checklist.md](../../../../docs/feature-checklist.md) を更新する。同じ変更で `npm run check:operation-entries` が通ること（P-CI-06）
4. 利用者の手順が変わるときは、[docs/agents-doc-update-map.md](../../../../docs/agents-doc-update-map.md) の「画面の挙動」行どおりマニュアル・README を更新する
5. 変えた操作を最後まで行う。ブラウザ版（`npm run dev`、ポート 5173）で確かめられる操作はそこで確認する。ファイルダイアログなど Tauri のウィンドウでないと確かめられない操作は、確認できなかったことを結果に書く
6. 入力欄と選択欄には読めるラベルを付け、動的なエラーは支援技術へ通知する。ダイアログ内の候補一覧などが Escape を処理したときは、親ダイアログまで閉じない
7. 操作の対象や手順を変えたときは、計画が挙げる文書のほか、ショートカット一覧と、その場だけ出す帯（線を引くモードなど）と、マニュアルでその操作を説明する文も揃える
8. ショートカットの修飾キーは Ctrl、⌘、Alt、Shift だけを指し、文字キーの名前とは分けて書く
9. 既存の操作の文に入口を足すときは、文末の動詞を新しい入口に合わせて全体へかけない。うしろの「これら」が指す文も、挿入で範囲がずれないように置く。ゾーンや場所で規則が違うときは、前の文の条件が別のゾーンまで掛からないように、ゾーンを主語に書く。挿入した文の直後の文を読み、主語が新しい入口に掛かっていたら、元の入口の主語に戻す
10. 同じ面に左クリックと右クリックがあるときは、Konva の `click` が右ボタンの mouseup でも届くので、主ボタン以外では左クリックの処理をしない。pointerdown の cancelBubble は mousedown を止めない。チャートのパンを始める mousedown は、タスクバーと期間のハンドルを対象から外す。線を引くモードでは、タスクバーの `pointerdown` が始めた監視を、本体の `mousedown` がスペースや中ボタンで空きの監視に置き換えない。期間端の幾何当たりは、モード中は空きのパンを止めない
11. しきい値で向きを分けるドラッグは、押したときに受け側がポインタを取る。子は、自分の向きが先と分かるまで取らない。取らないままでは、ポインタが要素の外へ出たあとの移動が届かない。ドラッグでその行が画面の外へ出る、または固定の行に切り替わって要素が無くなるときは、ポインタは残っている親が取る
12. 画面の部品を足すときは、ダイアログとメニューも含めて、文字と寸法に `--s` を掛け、色は `src/model/palette.ts` の値から取る。CSS では `:root` に定義してあるカスタムプロパティか、その値だけを使う。定義のない名前は置かない。色を足すか変えたときは、ライトとダークの両方で、文字は 4.5:1、バーや枠などの図形は 3:1 以上のコントラスト比があるかを確かめる
13. Konva と書き出しの文字は `src/model/fontStack.ts` のフォント指定を使い、CSS と同じ並びに揃える
14. 子がキーを扱うオーバーレイでは外側への伝播を止める。コマンド実行のあとフォーカスを移すときは、背景の `inert` を先に外す。ドラッグの Escape はキャンセル登録でドラッグを止め、離したときに確定しない
15. 期間端の当たりはドラッグ専用にし、クリックで選択や詳細パネルを開かない。チャートのカーソルは `grab` のままにし、端で切り替えない。macOS の WebKit はカーソルを切り替えると、矢印と手のひらが点滅する。並べ替えの握りも、握りと行や透過した子で `cursor` が切り替わらないようにする。握り内の `svg` は `pointer-events: none` にする。並べ替え可能な握りの上にポインタがあるあいだは、`canReorder` が一瞬 false になっても `can-reorder` クラスと掴むカーソルを握りから外さない。握りから出たときだけ外す。左一覧の `canEditDocument` は `startupSettled` に揃え、ref だけを読んで再描画しない。起動復旧の effect はマウント時に一度だけ走らせ、`applyOpenedFile` の参照が変わっても `startupSettled` を往復させない。並べ替えの握りは `pointerdown` でポインタを取ったあいだ、握りでも `pointermove` を受ける。一覧の `sidebar-viewport` へ取り直したあとの `lostpointercapture` では、並べ替え中はドラッグを取り消さない
16. 並べ替えの握りはドラッグ専用にし、クリック、右クリック、しきい値以内の操作で選択、詳細パネル、メニューを開かない
17. 固定メニューと右クリックメニューのビューポート内へのずらしは、補正前のアンカー座標と `offsetWidth` / `offsetHeight` から `menuShiftForRect` で一度だけ計算する。表示後の `getBoundingClientRect` で再計算しない
18. 無効なボタンは `opacity` だけで薄くしない。文字色はパレットの二次色を直接指定し、`appearance: none` と `-webkit-text-fill-color` を同じ色にする
19. ☰ のファイル操作項目は、メニューを開いた瞬間のロック状態で `disabled` を固定する。ロックは `fileBusy` または起動復旧未完了。開いたまま両方が解けたら有効に戻す。起動復旧は `fileBusy` を立てず `blockDocumentEditsRef` だけ使う
20. タスクバー本体の移動確定は `pointerup` で一度だけ行う。Konva の `mouseup` だけに頼らない
21. タスクバー本体の `pointercancel` は Escape と同様に確定しない
22. 詳細パネルのフォーカス外れは、保存時点の文書を土台に、利用者が変えた項目だけを書く。開始日と終了日は日付欄を変えたときだけ含める
23. 固定幅の列に余白付きの札を置くときは、列の幅は行で揃え、札は内側の要素で文字と余白の幅にする。列の文字数に余白を足した幅を、札自身の幅にしない
24. Enter で確定する文字入力は、変換中（`isComposing`、または `keyCode` が 229）の Enter では確定しない。候補を矢印で動かす欄は、変換中は矢印を一覧が扱わない。同じ理由を支援技術へもう一度出すときは、一度消してから出し直す。Escape で入力を閉じるときは、閉じたあとに届く blur では確定しない
25. 件数を超えたら一覧の中だけスクロールする欄は、最大の高さを文字サイズだけで置かない。チェックの余白を含む1行の高さと行間から決める。JavaScript で足した行間は、一覧の CSS の `gap` と揃える。`box-sizing: border-box` の枠は、上下の太さを最大高さに足す。ブラウザ版で、収まる件数と1件多いときの両方を見る
26. `GuideDialog` の案内文（`guideContent.ts`）は、書いてある入口の名前や場所が変わったときだけ同じ変更で直す。ツールバーを眺めただけでは存在が分からず、興味が無くても作業に必要な操作だけ1文足す。色、状態バーの知らせ、設定の奥で既定がオフのものも同じ基準である。版ごとの差分は SET-06 の設定「更新」に任せ、案内へ版差分は入れない。手順の全文は操作マニュアルのままにする
27. 重ねないと仕様にある二つのダイアログは、中のボタンだけでなく、macOS のメニューなど `inert` が届かない入口から開くときも、開く側で相手を閉じる。長い本文を内側だけスクロールするダイアログは、その要素を最初にフォーカスし、キーで末尾まで読めるようにする
28. チェックやラジオの行で上下のマージンを 0 にするクラスは、外側のフィールドのクラスが同じ要素に付いている行の上下まで消える。同じ詳細度でうしろにある `margin: 0` が、フィールドの上下マージンに勝つ。二つのクラスが付く行は、両方を指定したセレクタでフィールドと同じ上下マージンを戻す。fieldset の中だけの行は 0 のままにする。fieldset の枠と左右の内側余白を消すとき、`padding` を一括で 0 にすると凡例と最初の印が接する。凡例にはブラウザ既定の左右 padding があり、印の左端とずれる。その fieldset は縦の flex にし、行同士と同じ `gap` を凡例と各行にかける。凡例の padding は 0 にする。flex の gap が凡例に付かないときは、凡例の下マージンを同じ間隔にする
29. ダイアログの一部だけをスクロールして、外の操作やチェックを画面内に残すときは、`max-height` をビューポートからの引き算だけで決めない。表示倍率が大きいと式が 0 以下になり、ダイアログ全体が伸びる。ダイアログを縦の flex にし、見出しの下を `flex: 1` と `min-height: 0` で縮め、スクロールする要素だけ `overflow: auto` にする。段階的に出す項目は、まだ見えないものを `inert` にし、ダイアログのフォーカストラップの対象から `inert` の内側を外す。出現の待ちは JavaScript と CSS の二重に掛けない
30. ショートカットを抑止するときも、検索欄、入力欄、選択欄、編集できる領域では操作しない。それ以外では `preventDefault` する。ダイアログが開いているあいだと線を引くモードのあいだは、開く処理と並べ替えを実行しない
31. [docs/internal-spec.md](../../../../docs/internal-spec.md) のキーボードの節へ文を挿入するときは、うしろの「このキー」が前の操作のまま残るように、文を分ける
32. 操作マニュアルの 19 図（`docs/user-manual/images/` の `ui-overview.png`、`ui-menu.png`、`ui-filter.png`、`ui-colors.png`、`ui-task-detail.png`、`ui-settings.png`、`ui-peer-notice.png`、`ui-update-offer.png`、`ui-diff.png`、`ui-export.png`、`ui-context-menu.png`、`ui-task-duplicate.png`、`ui-task-note.png`、`ui-task-add.png`、`ui-settings-members.png`、`ui-settings-calendar.png`、`ui-settings-updates.png`、`ui-settings-mcp.png`、`ui-settings-skills.png`）のどれかに写る見た目が変わるときは、同じ変更で `npm run capture:manual-screenshots` を実行し、出た PNG を含める。図の説明文が画面とずれたときは、[docs/user-manual/getting-started.md](../../../../docs/user-manual/getting-started.md)（`ui-overview.png`）または [docs/user-manual/features.md](../../../../docs/user-manual/features.md)（そのほか 18 図）のその文も直す。撮り直した図の説明が、図に無い部品を言っていないか見る。マニュアルの文章だけを直す変更や、18 図に写らない操作だけの変更では撮影しない。撮影スクリプトのボタン名や待いの要素が画面と合わなくなったときは、スクリプトを直してから撮影する。図を増やす、図をやめる、節への配置を変えることは、計画がそれを指定したときだけ行う。ポート 5173 か 5174 が使用中で Vite が起動できないときは、その開発サーバを止めてから実行する。撮影できなかったときは、理由を結果に書く。続けて複数の図を撮るときは、前の図のために出した要素を消してから次を撮る。撮影スクリプトが複数の図をまとめて書き出すときは、計画が撮り直す図を名指ししているときも、その変更で写る文言が変わった図だけを残す。この変更で写る見た目が変わった図だけをコミットに残し、それ以外の PNG は元に戻す。戻したファイル名を結果に書く
33. 出ていないあいだも高さを残すときは、その部品の外寸を `min-height` にし、別の行の高さを流用しない。padding が `--s` に掛からない部品は、表示倍率の下限でも隣の欄がずれないことをブラウザ版で見る
34. 別のしきい値を超えてから既存のパンを始めるときは、パン自身の 3px を重ねない。確定した位置は、押した位置を原点に今のパンの差分へ一度入れ、閉じた手もその時点で出す。確定と同じ操作で離したとき、パンの `window` 監視が付く前でもパンを終える。`pointercancel` でも終える
35. しきい値未満のクリックを `pointerup` で発火するときは、既存の `click` が `detail` で捨てる 2 回目も捨てる。`pointercancel` では線を足さない
36. パン中にポインタがチャートの外へ出ても、線を引くモードの追随する線の終点は消さない。終点は `useTimelinePointer` と同じクライアント座標の計算にする
37. 一覧の中の行を見える位置へ送るときは、スクロールする要素の表示矩形を基準にする。`position: relative` の親に対する `offsetTop` を、その子の `scrollTop` に入れない。候補ボタンの長い文字を折り返すときは `white-space: normal` を指定する。共有クラスを使う欄だけ変えるときは、欄用のクラスで限定する。全文選択のあと最初の文字で表示を置き換える欄は、表示を戻して焦点が残るときにも全文を選び直す
38. 候補一覧の強調行は、一覧を描く前に決める。開いたあとや検索語が変わったあとの effect で決めると、最初の描画とスクロールが別の行を見る
39. 最大高さを描画のあとで足す一覧は、その高さが付いてから、スクロールする要素の表示矩形で目的の行を見える位置へ送る
40. 候補が無いときは空の一覧を出さない。絶対配置で重ねる一覧では、件数超過と一致なしの文言をスクロールする要素の外に置き、パネルの高さは増やさない
41. 選択欄を候補の入力欄に置き換えるとき、今の値と同じ行では親の更新を呼ばない
42. キー判定と `useAppKeyboard` の effect の依存は、単一の `selectedTaskId` だけでなく選択集合（件数と id 配列）に揃える。Alt+矢印と Delete は件数で有効にする。計画が並べ替えのドラッグ中は置き換えを拒むと書いているときは、挿入位置のプレビューが付く前でも、しきい値を超えて並べ替えモードに入ったあいだを拒否に含める
43. 選択を移す入口（↑↓ など）では、クリック選択が行を見える位置へ送っているなら、同じ `revealTaskRow` を移動後の `activeId` にも通す
44. 一括パネルの「変更しない」と「空を書く」（割り当てなしなど）は、`<option>` の `value` を分ける。空文字を書かない下書きと、空を書く下書きを同じ値にしない
45. 件数でパネルを付け替えるときの破棄の知らせとフォーカス移動は、消えるパネルの内側ではなく、残る `App` 側の `aria-live` とフォーカス先に置く。「入力をクリア」では破棄の知らせを出さない
46. 複数ドラッグの確定は、`pointerup` 時点の選択ではなく、ドラッグ開始時に保持した id 配列を渡す
47. 初期フォーカスをボタンに置くダイアログで、計画が Enter で確定しないと書いているときは、そのボタンの `keydown` で Enter を止める。ブラウザの既定では、フォーカスがあるボタンを Enter が押す
48. 計画が既存の寄せと同じと書いたときは、その関数のスクロール計算を使い、今の `scrollY` を渡す。見えている行で縦位置が変わらないテストを置く
49. 計画が印を付けると書いたときは、描くコンポーネントがその状態を読む
50. テキスト欄を、入力欄でもボタンでもない一覧に替えるときは、その一覧のフォーカス中もガント向けのキーを `decideAppKey` で止める
51. 説明半透明（`explain_overlay`）の吹き出し配置とスクロールは `explainOverlayLayout.ts` で決める。マイルストン帯の絞り込みは `explainView.ts` の `resolveExplanationMilestoneBand` で決め、`useSchedule` の `visibleMilestoneGroupIds` と `milestonesForBandLayout` に載せる。星の印と帯の行の印の穴は `milestoneDiamondRectInBand` と `milestoneBandBlockRectInBand` の戻り値だけを使う。試しの計画の星の日付変更は `buildExplanationTrialMilestoneLayouts` とマイルストン帯の試し Layer で描き、`patterns` の `milestoneChanges` を `applyExplanationPatternToDocument` で `applyMilestoneEdit` と同じ更新に含める。マイルストン帯の試し Layer は半透明ベールのうしろ（上）に載せ、ひし形の `RegularPolygon` は `MilestoneMark` と同じ向きにする。星と帯の行の吹き出しはマイルストン帯の DOM ホストに出す。日付ヘッダーの吹き出しは日付ヘッダーの矩形の外へ出さない。
52. 読み取りの印と `milestoneChanges` の文を変えるときは、`MCP_VIEW_IN_READ_TOOLS`、`read-screen/SKILL.md`、`mcp_stdio.rs` の照合句を同じ連続した文字列で揃える。タスク棒、日付列、マイルストン菱形の抜きと、TaskBar・期間ハンドル・リンク用アンカーは、描画側が呼ぶ `taskBarLayout.ts` の関数の戻り値だけを使い、同じ式を説明用に別途書かない。試しの計画（`patterns`）の棒と印の穴も同じ戻り値だけを使い、状態は `explainOverlayPatterns.ts` で文書の外に置く。
53. 選んだパターンを計画へ入れるのは `apply_explanation_pattern` で、`applyExplanationPatternToDocument` が `afterTaskId` の直後へ試しタスクを挿し、`changes` を適用する。成功は `replaceScheduleDocument` 経由で未保存・取り消し1段・説明の消去になる。`consultation-flow.md` では、入れる手順を先に消す順に書かない。試しの計画が画面に残っているあいだに `apply_explanation_pattern` を呼ぶ。先に消すと拒否される。MCP と read-screen には判断の例を写さない。
