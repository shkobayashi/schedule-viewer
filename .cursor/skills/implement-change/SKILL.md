# implement-change（schedule-viewer の実装）

計画に書かれた変更を、このリポジトリのアプリへ入れる。JSON を作る作業と、スキーマの形を変える作業は、このスキルの対象外である。

計画が節を指定しているときは、その節と「着手前」だけに従う。操作の文へ入口を足す変更でも、節の指定が「画面と操作」の 1 から 4 だけのときは、その 8 の動詞の掛かりを見る。

## 着手前

1. [AGENTS.md](../../../AGENTS.md) の表で、この変更に合う文書を読み、場所を絞ってからソースを開く
2. 機能 ID がある変更は、[docs/external-spec.md](../../../docs/external-spec.md) のその節に合わせる
3. 画面の組み立て、状態、モデル、Tauri、描画のどれを触るかを決める。依存はコンポーネントからフック、フックからモデルである。モデルはコンポーネントを参照しない。Rust は JSON の意味を解釈しない
4. 計画がスキルの節番号を列挙していても、計画本文の出し入れ、主語の掛かり、手動テストの各条件は照合する。照合結果は実装の結果に残す
5. `next` があるとき、変更を載せる統合ブランチは [docs/development.md](../../../docs/development.md#1x-を出しながら次のメジャーを進める) の「1.x を出しながら次のメジャーを進める」で決める。1.x のまま出せる変更は `develop`、公開する契約を壊す変更は `next` である。計画がブランチを書いていても、この節と照合し、結果は実装の結果に残す

## 画面と操作

利用者に見える挙動、操作、表示を変える。

1. `src/components/`、`src/hooks/`、`src/App.tsx` のうち、計画が指す箇所を変える
2. [docs/external-spec.md](../../../docs/external-spec.md) を同じ変更で更新する
3. 利用者の手順が変わるときは、内容に合う [docs/user-manual/getting-started.md](../../../docs/user-manual/getting-started.md)、[docs/user-manual/tutorial.md](../../../docs/user-manual/tutorial.md)、[docs/user-manual/features.md](../../../docs/user-manual/features.md) を更新する。読み方だけ変えるときは [docs/user-manual.md](../../../docs/user-manual.md)。README の機能説明が変わるときは [README.md](../../../README.md) を更新する
4. 変えた操作を最後まで行う。ブラウザ版（`npm run dev`、ポート 5173）で確かめられる操作はそこで確認する。ファイルダイアログなど Tauri のウィンドウでないと確かめられない操作は、確認できなかったことを結果に書く
5. 入力欄と選択欄には読めるラベルを付け、動的なエラーは支援技術へ通知する。ダイアログ内の候補一覧などが Escape を処理したときは、親ダイアログまで閉じない
6. 操作の対象や手順を変えたときは、計画が挙げる文書のほか、ショートカット一覧と、その場だけ出す帯（線を引くモードなど）と、マニュアルでその操作を説明する文も揃える
7. ショートカットの修飾キーは Ctrl、⌘、Alt、Shift だけを指し、文字キーの名前とは分けて書く
8. 既存の操作の文に入口を足すときは、文末の動詞を新しい入口に合わせて全体へかけない。うしろの「これら」が指す文も、挿入で範囲がずれないように置く。ゾーンや場所で規則が違うときは、前の文の条件が別のゾーンまで掛からないように、ゾーンを主語に書く。挿入した文の直後の文を読み、主語が新しい入口に掛かっていたら、元の入口の主語に戻す
9. 同じ面に左クリックと右クリックがあるときは、Konva の `click` が右ボタンの mouseup でも届くので、主ボタン以外では左クリックの処理をしない。pointerdown の cancelBubble は mousedown を止めない。チャートのパンを始める mousedown は、タスクバーと期間のハンドルを対象から外す。線を引くモードでは、タスクバーの `pointerdown` が始めた監視を、本体の `mousedown` がスペースや中ボタンで空きの監視に置き換えない。期間端の幾何当たりは、モード中は空きのパンを止めない
10. しきい値で向きを分けるドラッグは、押したときに受け側がポインタを取る。子は、自分の向きが先と分かるまで取らない。取らないままでは、ポインタが要素の外へ出たあとの移動が届かない。ドラッグでその行が画面の外へ出る、または固定の行に切り替わって要素が無くなるときは、ポインタは残っている親が取る
11. 画面の部品を足すときは、ダイアログとメニューも含めて、文字と寸法に `--s` を掛け、色は `src/model/palette.ts` の値から取る。色を足すか変えたときは、ライトとダークの両方で、文字は 4.5:1、バーや枠などの図形は 3:1 以上のコントラスト比があるかを確かめる
12. Konva と書き出しの文字は `src/model/fontStack.ts` のフォント指定を使い、CSS と同じ並びに揃える
13. 子がキーを扱うオーバーレイでは外側への伝播を止める。コマンド実行のあとフォーカスを移すときは、背景の `inert` を先に外す。ドラッグの Escape はキャンセル登録でドラッグを止め、離したときに確定しない
14. 期間端の当たりはドラッグ専用にし、クリックで選択や詳細パネルを開かない。チャートのカーソルは `grab` のままにし、端で切り替えない。macOS の WebKit はカーソルを切り替えると、矢印と手のひらが点滅する。並べ替えの握りも、握りと行や透過した子で `cursor` が切り替わらないようにする。握り内の `svg` は `pointer-events: none` にする。並べ替え可能な握りの上にポインタがあるあいだは、`canReorder` が一瞬 false になっても `can-reorder` クラスと掴むカーソルを握りから外さない。握りから出たときだけ外す。左一覧の `canEditDocument` は `startupSettled` に揃え、ref だけを読んで再描画しない。起動復旧の effect はマウント時に一度だけ走らせ、`applyOpenedFile` の参照が変わっても `startupSettled` を往復させない。並べ替えの握りは `pointerdown` でポインタを取ったあいだ、握りでも `pointermove` を受ける。一覧の `sidebar-viewport` へ取り直したあとの `lostpointercapture` では、並べ替え中はドラッグを取り消さない
15. 並べ替えの握りはドラッグ専用にし、クリック、右クリック、しきい値以内の操作で選択、詳細パネル、メニューを開かない
16. 固定メニューと右クリックメニューのビューポート内へのずらしは、補正前のアンカー座標と `offsetWidth` / `offsetHeight` から `menuShiftForRect` で一度だけ計算する。表示後の `getBoundingClientRect` で再計算しない
17. 無効なボタンは `opacity` だけで薄くしない。文字色はパレットの二次色を直接指定し、`appearance: none` と `-webkit-text-fill-color` を同じ色にする
18. ☰ のファイル操作項目は、メニューを開いた瞬間のロック状態で `disabled` を固定する。ロックは `fileBusy` または起動復旧未完了。開いたまま両方が解けたら有効に戻す。起動復旧は `fileBusy` を立てず `blockDocumentEditsRef` だけ使う
19. タスクバー本体の移動確定は `pointerup` で一度だけ行う。Konva の `mouseup` だけに頼らない
20. タスクバー本体の `pointercancel` は Escape と同様に確定しない
21. 詳細パネルのフォーカス外れは、保存時点の文書を土台に、利用者が変えた項目だけを書く。開始日と終了日は日付欄を変えたときだけ含める
22. 固定幅の列に余白付きの札を置くときは、列の幅は行で揃え、札は内側の要素で文字と余白の幅にする。列の文字数に余白を足した幅を、札自身の幅にしない
23. Enter で確定する文字入力は、変換中（`isComposing`、または `keyCode` が 229）の Enter では確定しない。候補を矢印で動かす欄は、変換中は矢印を一覧が扱わない。同じ理由を支援技術へもう一度出すときは、一度消してから出し直す。Escape で入力を閉じるときは、閉じたあとに届く blur では確定しない
24. 件数を超えたら一覧の中だけスクロールする欄は、最大の高さを文字サイズだけで置かない。チェックの余白を含む1行の高さと行間から決める。JavaScript で足した行間は、一覧の CSS の `gap` と揃える。`box-sizing: border-box` の枠は、上下の太さを最大高さに足す。ブラウザ版で、収まる件数と1件多いときの両方を見る
25. `GuideDialog` の案内文（`guideContent.ts`）は、書いてある入口の名前や場所が変わったときだけ同じ変更で直す。ツールバーを眺めただけでは存在が分からず、興味が無くても作業に必要な操作だけ1文足す。色、状態バーの知らせ、設定の奥で既定がオフのものも同じ基準である。版ごとの差分は SET-06 の設定「更新」に任せ、案内へ版差分は入れない。手順の全文は操作マニュアルのままにする
26. 重ねないと仕様にある二つのダイアログは、中のボタンだけでなく、macOS のメニューなど `inert` が届かない入口から開くときも、開く側で相手を閉じる。長い本文を内側だけスクロールするダイアログは、その要素を最初にフォーカスし、キーで末尾まで読めるようにする
27. チェックやラジオの行で上下のマージンを 0 にするクラスは、外側のフィールドのクラスが同じ要素に付いている行の上下まで消える。同じ詳細度でうしろにある `margin: 0` が、フィールドの上下マージンに勝つ。二つのクラスが付く行は、両方を指定したセレクタでフィールドと同じ上下マージンを戻す。fieldset の中だけの行は 0 のままにする。fieldset の枠と左右の内側余白を消すとき、`padding` を一括で 0 にすると凡例と最初の印が接する。凡例にはブラウザ既定の左右 padding があり、印の左端とずれる。その fieldset は縦の flex にし、行同士と同じ `gap` を凡例と各行にかける。凡例の padding は 0 にする。flex の gap が凡例に付かないときは、凡例の下マージンを同じ間隔にする
28. ダイアログの一部だけをスクロールして、外の操作やチェックを画面内に残すときは、`max-height` をビューポートからの引き算だけで決めない。表示倍率が大きいと式が 0 以下になり、ダイアログ全体が伸びる。ダイアログを縦の flex にし、見出しの下を `flex: 1` と `min-height: 0` で縮め、スクロールする要素だけ `overflow: auto` にする。段階的に出す項目は、まだ見えないものを `inert` にし、ダイアログのフォーカストラップの対象から `inert` の内側を外す。出現の待ちは JavaScript と CSS の二重に掛けない
29. ショートカットを抑止するときも、検索欄、入力欄、選択欄、編集できる領域では操作しない。それ以外では `preventDefault` する。ダイアログが開いているあいだと線を引くモードのあいだは、開く処理と並べ替えを実行しない
30. [docs/internal-spec.md](../../../docs/internal-spec.md) のキーボードの節へ文を挿入するときは、うしろの「このキー」が前の操作のまま残るように、文を分ける
31. 操作マニュアルの 19 図（`docs/user-manual/images/` の `ui-overview.png`、`ui-menu.png`、`ui-filter.png`、`ui-colors.png`、`ui-task-detail.png`、`ui-settings.png`、`ui-peer-notice.png`、`ui-update-offer.png`、`ui-diff.png`、`ui-export.png`、`ui-context-menu.png`、`ui-task-duplicate.png`、`ui-task-note.png`、`ui-task-add.png`、`ui-settings-members.png`、`ui-settings-calendar.png`、`ui-settings-updates.png`、`ui-settings-mcp.png`、`ui-settings-skills.png`）のどれかに写る見た目が変わるときは、同じ変更で `npm run capture:manual-screenshots` を実行し、出た PNG を含める。図の説明文が画面とずれたときは、[docs/user-manual/getting-started.md](../../../docs/user-manual/getting-started.md)（`ui-overview.png`）または [docs/user-manual/features.md](../../../docs/user-manual/features.md)（そのほか 18 図）のその文も直す。撮り直した図の説明が、図に無い部品を言っていないか見る。マニュアルの文章だけを直す変更や、18 図に写らない操作だけの変更では撮影しない。撮影スクリプトのボタン名や待いの要素が画面と合わなくなったときは、スクリプトを直してから撮影する。図を増やす、図をやめる、節への配置を変えることは、計画がそれを指定したときだけ行う。ポート 5173 か 5174 が使用中で Vite が起動できないときは、その開発サーバを止めてから実行する。撮影できなかったときは、理由を結果に書く。続けて複数の図を撮るときは、前の図のために出した要素を消してから次を撮る。撮影スクリプトが複数の図をまとめて書き出すときは、この変更で写る見た目が変わった図だけをコミットに残し、それ以外の PNG は元に戻す
32. 出ていないあいだも高さを残すときは、その部品の外寸を `min-height` にし、別の行の高さを流用しない。padding が `--s` に掛からない部品は、表示倍率の下限でも隣の欄がずれないことをブラウザ版で見る
33. 別のしきい値を超えてから既存のパンを始めるときは、パン自身の 3px を重ねない。確定した位置は、押した位置を原点に今のパンの差分へ一度入れ、閉じた手もその時点で出す。確定と同じ操作で離したとき、パンの `window` 監視が付く前でもパンを終える。`pointercancel` でも終える
34. しきい値未満のクリックを `pointerup` で発火するときは、既存の `click` が `detail` で捨てる 2 回目も捨てる。`pointercancel` では線を足さない
35. パン中にポインタがチャートの外へ出ても、線を引くモードの追随する線の終点は消さない。終点は `useTimelinePointer` と同じクライアント座標の計算にする
36. 一覧の中の行を見える位置へ送るときは、スクロールする要素の表示矩形を基準にする。`position: relative` の親に対する `offsetTop` を、その子の `scrollTop` に入れない。候補ボタンの長い文字を折り返すときは `white-space: normal` を指定する。共有クラスを使う欄だけ変えるときは、欄用のクラスで限定する。全文選択のあと最初の文字で表示を置き換える欄は、表示を戻して焦点が残るときにも全文を選び直す
37. 候補一覧の強調行は、一覧を描く前に決める。開いたあとや検索語が変わったあとの effect で決めると、最初の描画とスクロールが別の行を見る
38. 最大高さを描画のあとで足す一覧は、その高さが付いてから、スクロールする要素の表示矩形で目的の行を見える位置へ送る
39. 候補が無いときは空の一覧を出さない。絶対配置で重ねる一覧では、件数超過と一致なしの文言をスクロールする要素の外に置き、パネルの高さは増やさない
40. 選択欄を候補の入力欄に置き換えるとき、今の値と同じ行では親の更新を呼ばない
41. キー判定と `useAppKeyboard` の effect の依存は、単一の `selectedTaskId` だけでなく選択集合（件数と id 配列）に揃える。Alt+矢印と Delete は件数で有効にする。計画が並べ替えのドラッグ中は置き換えを拒むと書いているときは、挿入位置のプレビューが付く前でも、しきい値を超えて並べ替えモードに入ったあいだを拒否に含める
42. 選択を移す入口（↑↓ など）では、クリック選択が行を見える位置へ送っているなら、同じ `revealTaskRow` を移動後の `activeId` にも通す
43. 一括パネルの「変更しない」と「空を書く」（割り当てなしなど）は、`<option>` の `value` を分ける。空文字を書かない下書きと、空を書く下書きを同じ値にしない
44. 件数でパネルを付け替えるときの破棄の知らせとフォーカス移動は、消えるパネルの内側ではなく、残る `App` 側の `aria-live` とフォーカス先に置く。「入力をクリア」では破棄の知らせを出さない
45. 複数ドラッグの確定は、`pointerup` 時点の選択ではなく、ドラッグ開始時に保持した id 配列を渡す
46. 初期フォーカスをボタンに置くダイアログで、計画が Enter で確定しないと書いているときは、そのボタンの `keydown` で Enter を止める。ブラウザの既定では、フォーカスがあるボタンを Enter が押す
47. 計画が既存の寄せと同じと書いたときは、その関数のスクロール計算を使い、今の `scrollY` を渡す。見えている行で縦位置が変わらないテストを置く
48. 計画が印を付けると書いたときは、描くコンポーネントがその状態を読む
49. テキスト欄を、入力欄でもボタンでもない一覧に替えるときは、その一覧のフォーカス中もガント向けのキーを `decideAppKey` で止める
50. 計画が表示文言を解析しないと書いたときは、札と名前と場所をブロックのフィールドにし、コピー用の全文は今の文字列のままにする
51. 編集を始める effect は、要求の番号だけを依存にする。タイトルなどを閉じた開始関数を依存にすると、確定のあと入力が開き直る
52. 計画が、開いている入力を操作の前に確定すると書いたときは、その操作を実行する入口のすべてで同じ確定を先に呼ぶ。ボタンだけに置かない
53. 名前のうしろへ縮めない表示を足すときは、既存のラベルが `flex: 1` などで余白を取ると、表示は行の右端へ離れる。間隔を `--s` の余白だけにするときは、ラベルと表示を一つの塊にし、ラベルは内容の幅まで縮め、足りない幅は名前だけを省略する。行に `overflow: hidden` がありラベルに `min-width` があるときは、一覧の最小幅でもその表示が切れないことをブラウザ版で見る

## 状態・モデル・描画・Tauri

画面の手順が変わらなくても、状態、計算、描画、ファイルの橋渡しを変える。

1. 検証、行、履歴、書き出す内容は `src/model/` の純粋関数に置く。ファイルの読み書きは Tauri 側に残す
2. 構成、状態、Tauri コマンド、描画の流れが変わるときは [docs/internal-spec.md](../../../docs/internal-spec.md) を同じ変更で更新する
3. 純粋関数を変えたときは、対応する `src/model/*.test.ts` を更新する。`src-tauri/` のパス検査を変えたときは Rust のテストを更新する。バイト上限のある標準入力は、上限を超えた分を読み続けない。`take` などで読む上限は最大バイト数より 1 バイト大きくし、超えた入力のテストを同じ変更で置く
4. 非同期処理は、多重実行と `await` 中の状態変更を考慮し、処理中の ref または世代番号で古い結果を反映しない。計画が起動復旧のダイアログのあいだは起動復旧の拒否文を返すと書いているときは、`startupSettled` を下ろしたあともその文を先に返す。MCP の置き換えでは、編集拒否と保存形式が同じで何もしない成功を同じ戻り値にまとめず、拒否は `isError`、同じ内容は差分テキストの成功に分ける。状態と同時に参照する ref は同じ処理内で更新する。公開しているフックの戻り値を保ったまま、独立した状態機械は分割前に境界のテストを置いてから分ける。計画が、ダイアログを閉じてもコンポーネントが残り state が残ると書いているときは、親が開いているあいだだけマウントしていないかを見る。外しているときは、閉じたあとも残す値をコンポーネントの外に置く。処理を始めない条件に入ったときも世代を進め、進行中の結果を捨てる。早期 return だけでは捨てたことにしない。計画が明示のフラグを見え方の入力にすると書いているときは、そのフラグを純粋関数の引数にし、自動の空結果で明示を消さないことと、パス変更で表示を捨てることをテストする。計画が、確定と同じ呼び出しで JSON と提案ファイル名を更新すると書いたときは、両方をその呼び出しで更新した参照から読む
5. ブラウザ版とデスクトップ版の両方にある入力は、サイズ上限、検証、エラー処理の差を意図したものか確認する
6. チャートへ描き足すときは Konva の Layer を増やさず、既存の Layer の中の Group に足す
7. チャートの x を日へ切り捨てるときは、日の左端が浮動小数で前日にならないようにする
8. 並べ替えの挿入位置は、動かしている要素を除いたあとの位置にする。受けない位置は、文書を変える関数が元を返すだけでなく、候補を決める関数でも外す
9. ディレクトリを入れ替えるときは、失敗しても元の中身を残す。親がシンボリックリンクのときはリンク先へ書かず、消さない。リンク自体を外すとき、リンク先は消さない
10. 文字の切り詰めと段の占有幅は、描画と同じ開始位置から測る。表示状態が覚える ID は、対象が文書から消えたときに外し、新しく現れた対象は表示する。文字幅を割合で見積もるときは、描く太さと表示サイズの範囲で実測し、見積もりが実幅を下回らない余裕にする。長い文字列だけでなく、幅の広い文字を含む文字列も見る。右へ足す日数とマイルストン名のホバー折り返しは、画面に出す文字列を、切り詰めと同じ見積もり（太字の余裕を含む）で測る。ホバーの位置は、乗った瞬間の座標ではなく、スクロール後の座標から決める
11. 複数のウィンドウが同じファイルを開くときは、控えの書き込みと削除はそのパスの前面のウィンドウだけが行う。終了は、各ウィンドウの閉じる確認がすべて済んでから閉じ、キャンセルしたときはどれも閉じない。終了で控えを書くウィンドウは、閉じ始める直前の前面に固定する。追加ウィンドウへ渡した内容は、起動時の復旧より先に載せる
12. 自動更新の破棄確認を開いたあと、戻り値だけをキャンセル扱いにしない。確定とキャンセルを待つ。控えの書き手は、終了と同じく全ウィンドウが受け入れたあとに固定し、そのあと各ウィンドウが書く。再起動で閉じるときは破棄確認を出さない。`latest.json` に今の OS が無い確認は失敗の知らせにしない。`Update` を持つウィンドウと「入れ直す」を押したウィンドウが違うときは、持つウィンドウがまだ開いていればそのウィンドウが `request_application_update` から進める。持つウィンドウを閉じたあとだけ、残ったウィンドウが再確認し、知らせの版と一致するときだけ未保存の処理へ進む。中断したら `cancel_application_update` で共有の `updating` を戻す。入れ直し中は「更新を確認」で通信しない
13. 最も早い日が後ろへ動いて、スクロールが左端でそれ以上戻せないときは、描画の原点を据え置き、他のバーを動かさない。全体表示とズームの最大スクロールは、据え置いた原点から、右へ足した日を含む終端までの日数で決める
14. 変更履歴は起動時のダイアログや `pending-release-notes.json` では出さない。デスクトップ版の設定「更新」が、同梱の CHANGELOG を欄内スクロールで出す
15. 自動更新で `downloadAndInstall` が処理を戻して失敗したとき、失敗の知らせはダウンロードまたは入れ直しの失敗だけに出す
16. `#[cfg(windows)]` の MCP 待ち受けをスレッドへ移すときは、セキュリティ記述子の生ポインタをスレッドの外で作って `Send` させない。名前付きパイプのハンドルも同じで、待つスレッドの外で作って渡さない。待つテストは、そのスレッドの中でパイプを作り、準備できたことを知らせてからクライアントを繋ぐ。応答を書いたあと、クライアントが読み終わる前にパイプを切らない。切ると、まだ読んでいない本体が os error 233 になる。クライアントが閉じるまで待ってから切る。名前付きパイプが使用中の次の接続は、ウィンドウが開いていない旨にしない。短い間隔で接続を試し直し、応答待ちと同じ秒数を過ぎたら応答が無いときと同じ文にする。使用中を一度見たら、そのあとの名前なしやハンドル状態の失敗も同じ期限まで試し直す。待ち受けがパイプを作り直すあいだに名前が消える。使用中の再接続を試すテストは、2回目の接続を切る前にクライアントがハンドルを閉じるまで待つ。先に切ると `SetNamedPipeHandleState` が失敗し、ウィンドウが無い旨になる。Windows の名前付きパイプのテストは、テストごとにパイプ名を分ける。macOS の `cargo test` ではこのコードはコンパイルされない
17. スキル本文へ実行ファイルの呼び方を書き込むとき、Windows でそのパスが Local AppData 配下なら、絶対パスを書かない。コマンド例は `"$LOCALAPPDATA/"` に続く相対パスと `--screen` とツール名を同じ1行にする。本文に `\AppData` を残さない。それ以外の絶対パスは、シェル引用で包まず、実行ファイルの行と `--screen` とツール名の行に分ける。パスと引数を同じ行のコマンド例に書かない
18. 取り消しややり直しで出す帯は、次の取り消し1回に結び付けない。戻した文書がその操作の直前であるときだけ出し、やり直した文書がその操作の直後であるときだけ消す。起点が動いたあとは、覚えていたディスク内容を捨てる
19. Windows では、既存 WebView のコマンドの中で `WebviewWindowBuilder::build()` をその場で待たない。追加ウィンドウは async コマンドと `run_on_main_thread` で作り、メインスレッド上で `build()` を同期的に呼ばない
20. 計画が、起動復旧の確認ダイアログのあいだは待って拒否文を出さない、と書いているときは、起動完了の通知と同じ時点で外部ドロップを配らない。ダイアログを閉じたあとに配り、待ちのあいだはキューを進めない
21. 同じ起動の二度渡しだけを1回にすると書いた重複排除は、処理し終えたあとの同じ入力まで捨てない
22. 2つ目のプロセスの引数は実行ファイルのパスを先頭に含む。落としたファイルの件数には、その先頭を数えない。ディレクトリは件数を数える前に除かない
23. キューを1件進める応答は、配りを受けたウィンドウが1回だけ送る。転送先は送らない
24. ダイアログが開いているあいだは拒む、と計画が書いたときは、ファイル操作の確認だけでなく、その時点で開いているダイアログを見る。詳細パネルの入力は、計画が除くと書いたときだけ除く
25. OS によって列挙子が無い Tauri のイベント（macOS だけの `RunEvent::Opened` など）は、その列挙子がある OS の `cfg` の中だけで参照する。その参照だけが呼ぶ関数は、他の OS で未使用警告になる。`cfg_attr` で `dead_code` を許し、`cargo clippy -- -D warnings` が Linux と Windows で通るようにする
26. 計画が失敗文を指定したときは、その文を返す処理が CLI の解析結果から `run_screen_cli` などの呼び出し元へ届くようにする。解析で `None` にして汎用の使い方の文だけにすると、計画どおりの文は出ない
27. 計画がツールの引数を触らないと書いたときは、別ツール用の引数整形（例: 読み取りの `window` を外す）をそのツールへ掛けない
28. 計画が同じ規則を MCP のツール説明とスキルの両方に書くと書いたときは、両方に置く。MCP だけに書いてスキルに無いと、MCP 利用時に規則が欠ける
29. Windows API を `windows-sys` で呼ぶときは、`Cargo.toml` に書いた版のクレートで、その関数があるモジュールと feature を見てから使う。別の版にあるモジュール名だけで feature を足さない。`#[cfg(windows)]` の中は macOS の Clippy ではコンパイルされない。unsafe な関数は unsafe ブロックで呼び、Windows の `cargo clippy -- -D warnings` が通る形にする

## 文書

どの文書を同じ変更に含めるかは [AGENTS.md](../../../AGENTS.md) の「変更したら文書も更新する」に従う。通常の不具合修正では [docs/PLANNING.md](../../../docs/PLANNING.md) は更新しない。利用者に見える変更をリリースへ入れるときは [CHANGELOG.md](../../../CHANGELOG.md) も更新する。計画が REVIEW.md の指摘を扱うときは、対応または見送りを同じ変更で REVIEW.md に書く。

既存の段落へ別機能の制約を足すときは、うしろの文の主語が新しい機能に掛からないよう、段落を分ける。

同じ段落の前の文が、今回の挙動と食い違うときは、うしろへ足すだけでは終えず、前の文も直す。

ツールの個数を書いた文は、表に行を足した同じ変更で、本文の数も数える。

計画が開いている画面ではファイルを書かない例外を名指ししているときは、スキルの「ファイルを書くとき」がその例外を読まないように、例外を同じ節へ書く。

計画が名指しした文書を足したあとは、同じ文書の古い表と手順が新しい形と食い違っていないかを見る。チュートリアルが名指しされているときは、スキルの個数と、アプリを起動しない書き方も揃える。

## テストと確認

1. 機能 ID がある変更は、自動テストか [docs/test-spec.md](../../../docs/test-spec.md) の手動テストケースの少なくとも一方に対応づける。テストを足した、消した、または対応する機能 ID が変わるときは、テスト仕様を同じ変更で更新する
2. 自動テストの対象は `src/model/` の純粋関数と、Rust 側のパス検査である。画面操作、Konva の描画、Tauri のダイアログは手で確かめる
3. 触った層に応じて検査する。フロントの型とテストは `npm run build`、`npm run lint`、`npm test`。Rust を変えたときは `cd src-tauri && cargo clippy -- -D warnings` と `cargo test --locked`
4. 画面の幅、余白、切れ、行の揃いを変えたときは、計画が指す境界をサンプルが含まないなら、その境界も見る。サンプルのラベルが札の文字より短いときは、より長い表示名とメンバー不明でも、札の幅と列の揃いを見る
5. 計画が手動テストで見る内容を列挙しているときは、その各項目を [docs/test-spec.md](../../../docs/test-spec.md) の手順か期待に残す。手動項目を1行にまとめるときは、計画の各条件が手順か期待に残っているかを項目ごとに照合する。近い語があるだけでは足したことにしない。計画の一つの段落に並んだ条件を写したあとも、条件ごとに照合し、代表の1条件だけが残っている状態で終えない。例として「文書順の配列」だけでは、選択の全部を含むことや、マイルストンを含めないことを書いたことにはならない。「一覧とチャートを操作できる」だけでは、本文の縦スクロール、詳細と差分列を同時に開いたときのチャート幅、差分テキストのフォーカス中のキー停止、隅の知らせが差分と重ならないことを書いたことにはならない。「外部反映を止める」だけでは、開いている入力へファイル側の値を書き込まないことを書いたことにはならない。計画が「見出しはファイル名」のような観測を直すと書いたときは、テスト仕様でその観測を手順や期待に使っている行も直す
6. 計画が名指ししたテストファイルには、その変更のケースを足す。意味規則は拒否する入力と通す入力の両方、差分の表示は追加・変化・変化なしをテストする。計画がカテゴリ、グループ、タスクの文書順と書いているときは、フィクスチャをカテゴリまたはグループが2段以上になる形にする。計画が絞り込み条件では落とさないと書いているときは、その条件で絞り込み結果から落ちるタスクを入力にし、絞り込み関数の戻りと並べて見る。関数が絞り込み引数を持たないことだけでは、そのケースを書いたことにしない
7. 計画が失敗条件を名指ししているときは、成功の置換だけでなく、その条件で失敗する入力のテストを同じ変更で足す
8. 計画が名指しした失敗の文言と、文書が変わらないこと、2件選択で `primarySelectedTaskId` が null になることは、引数に null を渡すだけのテストでは足りない。該当の純関数テストに具体の入力を書く
9. 計画が一つの文で並べたケースは、ケースごとにテストを置き、結果に計画の語とテスト名の対応を書く。対応が無い語がある状態で完了にしない。期待値が、計画が拒む別の計算でも同じになる入力では、そのケースを書いたことにしない。例は、グループのパーセントの平均とタスクの平均が同じになる件数、隠したタスクと見えているタスクで期間が同じ親バー、絞り込みで落ちたタスクが別グループにしか無いときのグループの値である
10. 計画が失敗文を指定したときは、その文を返す純粋関数のテストと、解析が成功して呼び出し元がその処理へ届く引数のテストを同じ変更で足す。片方だけでは足りない
11. 計画が書き出した実バイトを正解にし、部品ごとの要素と値、入力を一つだけ変えた差を列挙しているときは、各項目に実バイトを読むテストを置く。要素があることだけでは、値の一致も、変えていない側が同じであることも満たさない。色の十六進は色の関数のテストに書き、XML のテストは payload の戻りと比較する。手で組んだアンカーはライブラリの出力の代わりにしない。結果に計画の語とテスト名の対応を書き、対応が無い項目がある状態で完了にしない
12. 計画が、二つのグループ、空のフォルダ、失敗時に残す旨、今と同じエラー文のように、画面で区別できる条件を書いたときは、配列を分けたことやコマンドを呼んだことだけでは満たしたことにしない。見出し、拒否、知らせの文が戻り値か仕様の文に残っているかを照合し、その文のテストを置く
13. 同梱する JSON 作成スキルの名前を増減したときは、`JSON_SKILL_NAMES` の件数を期待値にしている Rust のテストと、テスト仕様と画面に書いてある個数を同じ変更で揃える。名前の一覧だけ増やして、件数の期待値を古い数のままにしない

## 完了条件

- 計画が指定した範囲が入っている
- 対応する文書が同じ変更に含まれている
- 触った層の検査が通っている
- 画面を変えたときは、操作を確認したか、確認できなかった箇所を結果に書いている
- 操作マニュアルの 7 図に写る見た目が変わる変更では、`docs/user-manual/images/` の PNG を撮影し直し、図を載せている getting-started または features の説明文も揃えている。撮影しなかったときは、図に写る見た目が変わらないことを結果に書く。撮影できなかったときは、理由を結果に書く
- レビューで計画と仕上がりがずれた箇所を直したときは、再発を防ぐ手順を該当する節へ同じ変更で必ず足す。足した節を結果に書く。足さない判断だけを書いて完了にしない
