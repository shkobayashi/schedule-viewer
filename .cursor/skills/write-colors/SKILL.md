# write-colors（schedule-viewer 用色の一覧）

設定から取り込む、タスク行の地の色の一覧 JSON を作る。この Skill フォルダだけコピーして使える。スケジュール JSON には色の値を書かない。タスクが持つのは `colorId` だけで、id をタスクへ書くのは `write-schedule` である。設定ファイルの `colors` に相対パスを足すのは `write-workspace` である。

## 参照

- 形式の正本: [colors.schema.json](colors.schema.json)
- 検証: `node scripts/validate-colors.mjs <path/to/colors.json>`

## 入力が揃っていること

次が決まっている（または既存 JSON にある）こと。足りないときは **JSON を書かず**、不足項目をユーザーに返す。

- 各項目の `name` と、LLM が id を選ぶための `description`（その id を選ぶ状態だけ）
- 各項目の `id`（利用者が値か付け方を指定したときだけ。無いときは JSON を書かず尋ねる）
- 既存 JSON を更新するときは、残す項目と追加・削除する項目

`id` を名前から推測して作らない。既にある `id` は変えない。色の十六進は、塗り直しを頼まれた項目以外は残す。

## 出力形

```json
{
  "schemaVersion": 1,
  "colors": [
    {
      "id": "focus",
      "name": "注力",
      "description": "今いちばん手を付ける作業。",
      "color": {
        "light": { "bg": "#FEF3C7" },
        "dark": { "bg": "#78350F" }
      }
    }
  ]
}
```

- `schemaVersion`: 常に `1`
- `colors` は 1 件以上 8 件まで
- 各項目は `id`、`name`、`description`、`color.light.bg`、`color.dark.bg`（`#RRGGBB`）
- `description` に色の名前や十六進は書かない

## 地の色が載る場所

地は左一覧とガントチャートの行だけに乗る。文字色やステータスのバーの色ではない。選択行とホバーの地はその上に重なる。Excel では常に `light.bg` を白いシートに塗る。

## 明るさを決める（JSON を書く前）

アプリの本文と補助の色は固定である。ライトの本文 `#1f2937`、補助 `#697586`。ダークの本文 `#e6e8ee`、補助 `#a8b0bf`。各 `#RRGGBB` の相対輝度 Y と、前景と背景のコントラスト比は WCAG 2.x と同じ式で求める（sRGB を線形化して 0.2126×R + 0.7152×G + 0.0722×B。比は (明るい Y + 0.05) / (暗い Y + 0.05)）。

**ライトの地**（薄い地）

- Y は 0.75 以上 0.92 以下
- 本文との比は 7:1 以上
- 補助との比は 3.2:1 以上（補助で 4.5:1 を求めると白に寄り、塗らない行と分かれない）

**ダークの地**（暗い地）

- Y は 0.045 以上 0.070 以下
- 本文との比は 7:1 以上
- 補助との比は 4.1:1 以上（これより暗いと、塗らない地 `#1c1f26` と分かれにくい）

ライトとダークは同じ色相の組にする。ライトは薄い地、ダークは暗い地。

**使わない値**

- `#ffffff`、`#000000`
- 選択の地 `#dce3fb` / `#343b52`
- 超過の薄い地 `#fde8e4` / `#3d2824`
- 未割当の薄い地 `#fff4d6` / `#3d3520`
- 進行中・完了・超過のバーと同じ濃さの藍紫・緑・朱

利用者が light と dark の十六進を両方指定したときは、黙って置き換えない。範囲外ならその旨を伝え、指定どおり書くか範囲内に直すかを尋ねる。色相だけ指定されたときは、その色相のまま上の範囲内の明るさにする。

## 意味から地色を選ぶ

表に無い意味は、いちばん近い行の色相を取り、明るさだけを上の範囲へ動かす。同じ一覧で同じ色相を二つ置かない。8 件を超えない。色相が隣り合って分かれないときは件数を増やさず尋ねる。

| 状態の意味（description に書く内容の例） | light.bg | dark.bg |
| --- | --- | --- |
| 今いちばん手を付ける | `#FEF3C7` | `#78350F` |
| 相手の確認を待っている | `#DBEAFE` | `#1E3A8A` |
| 遅れや手戻りが出ている | `#FEE2E2` | `#7F1D1D` |
| 順調に進んでいる | `#DCFCE7` | `#14532D` |
| 別のチームへ渡している | `#CCFBF1` | `#134E4A` |
| 判断が要る | `#EDE9FE` | `#4C1D95` |
| 期限が近い | `#FFEDD5` | `#7C2D12` |

「今いちばん手を付ける」と「期限が近い」を同じ一覧に置くときは、黄と橙のどちらに寄せるか尋ねる。二つの `description` が同じ作業に当てはまるときは、id を増やさず尋ねる。

## 手順

1. 利用者から項目の名前、選ぶ状態の説明、必要なら id を整理する
2. 意味に合う行から light と dark の組を選び、上の明るさの範囲に収める
3. 既存 JSON を更新するときは、残す項目の `id` と色を維持する
4. `schemaVersion: 1` を付け、`colors` を書く
5. このスキルフォルダで `node scripts/validate-colors.mjs <file>` を実行して検証する
6. エラーがあれば修正して再検証し、通ってからユーザーに渡す

## 画面にないものは入れない

扱い、枠の色、LLM 向けの指示、ステータス一覧、スケジュールのタスクなど、この JSON に無い項目は書かない。
