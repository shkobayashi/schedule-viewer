# 外部仕様

画面と機能の挙動を定める。正本はソースコードで、挙動を変えたらこの文書も直す。利用者向けの手順は [操作マニュアル](user-manual.md)、ファイルの形は [データ仕様](data-format.md) にある。

機能 ID は `FILE-01` の形である。テスト仕様は、この ID で自動テストと手動テストケースを対応づける。

## スコープ

アプリは、検証済みのスケジュール JSON を表示し、絞り込み、編集し、書き出す。次のことはしない。

- 稼働日を踏まえた期間の計算や、前後関係に合わせた日付の自動変更
- LLM への接続。スケジュール、メンバー、カレンダーの生成は、アプリの外のスキルが行う

## 用語

| 用語 | 意味 |
| --- | --- |
| カテゴリ | スケジュールの最上位のまとまり。識別子は `id` で、名前は表示である |
| グループ | カテゴリの中のまとまり。識別子は `id` で、名前は同じカテゴリの中で重複できない |
| タスク | 開始日と終了日を持つ作業。終了日はその日を含む |
| マイルストン | 名前、日付、確度を持つ時点。タスクではない |
| 対応マイルストン | タスクの `milestoneId` が指すマイルストン。タスクごとに0件か1件で、詳細パネルとタスク複製ダイアログの「対応マイルストン」で文字から選ぶ |
| 先行・後続 | タスクの `predecessors` が指す相手が先行、自分を指している相手が後続 |
| 前後ではない繋がり | ルートの `connections` に書く、2タスク間の関係。終わってから始まる前後とは別の線で描く |
| 破綻 | 後続の開始日が、先行の終了日より前であること。同じ日に始まる場合は破綻にしない |
| 期限超過 | 未着手と着手済みの扱いで、終了日が今日より前であること。一覧に無い `id` と管理外は超過にしない。終了日が今日なら超過にしない |
| ステータス | タスクの `status` が書く、ステータス一覧の項目の `id`。項目は表示名、色、扱い、説明を持つ |
| ステータスの扱い | 一覧の項目が持つ、未着手、着手済み、完了、管理外のいずれか一つ。イナズマ線の折れ位置と期限超過と「完了以外」に使う。同じ扱いの項目は複数あってよい |
| マイルストン超過 | 対応マイルストンがあり、終了日がその日付より後であること。当日は超過にしない |
| 割り当てなし | `assigneeId` が `null` であること。メモリ上は担当 id の空配列 |
| メンバー不明 | 並びの id のうち、使用中のカタログに無いものがあること。カタログ未選択も含む |
| カタログ | 設定に取り込んだメンバー JSON の1件 |
| 系統 | 選んだタスクから、先行をそれ以上さかのぼれないところまで、後続をそれ以上たどれないところまでつないだ範囲。起点を通らない枝は含めない。「繋がりも辿る」では、たどったタスクの繋がりの相手と、その相手からの前後も同じ規則で足す |
| 親バー | カテゴリ、グループ、または見出し行の期間を示す、タスクバーより低いバー |
| イナズマ線 | 今日の進み方を示す折れ線。遅れや先行を、行の端まで折って示す |
| 非稼働日 | カレンダーの規則、または未設定時の土日。表示だけに使い、日付の計算には使わない |
| 控え | 未保存の内容を、開いている JSON ファイルとは別にアプリデータへ残したもの |
| サンプルデータ | ファイルを開いていないときの起動用スケジュール |
| 見出し | 画面左上のタイトルと、その右に並ぶ状態の表示をまとめたもの |
| 追加項目 | 設定で選んでいる拡張項目の定義に載る項目。値は各タスクの `fieldValues` に、合成キー `プラグインID_項目ID` で書く。型は文章、数値、日付、候補の四つ |
| 色の一覧 | 設定で選ぶ、または設定ファイルの `colors` が指す JSON。項目は名前、ライトとダークの地、説明を持つ |
| 行の地 | 左一覧とチャートの同じ行の背景。使用中の色の一覧の `colorId` で塗る。タスクバーとマイルストンの色はステータス一覧のままである |

## 動作環境

Ubuntu 22.04 以降の安定版は deb で、入手先は [GitHub Releases](https://github.com/shkobayashi/schedule-viewer/releases) の Latest である。Windows の安定版は [Microsoft Store](https://apps.microsoft.com/detail/9PP41TRJ8ZT8) の MSIX で、更新は Windows が行う。ベータの Pre-release は実機確認用であり、Ubuntu の deb、Apple Silicon の dmg、Windows の自己署名 NSIS を載せる。自動更新の配信は、Pre-release の `updater-X` に載せる `latest.json` だけから行う。安定版の `latest.json` は `linux-x86_64` と `darwin-aarch64` を指す。ベータの Pre-release に載せる `latest.json` は、これに `windows-x86_64` を足す。配布物は、その `latest.json` が指す各版の Release から取る（Windows の安定版は Store である）。ベータの NSIS には公開用証明書（`.cer`）が同じ Release に付く。GitHub Releases 版のデスクトップは、設定で自動更新をオンにしているときだけ、起動復旧のあと、入っている版と同じメジャー用の `updater-X` Release が載せる `latest.json` を見て、より新しい安定版があれば、入れ直すかを聞く。確認先の URL はビルドに含まれる。この確認先を含む版を入れたあとから効く。ベータを手で入れたあとも、同じメジャーの `updater-X` を見る。入っている版より古い安定版へは進まない。次のメジャーへは自動では進まない。次の `beta.N` は自動では入らない。自動更新の版比較は semver である。接尾辞を外した安定版が出て、自動更新がオンなら、判定上はベータより新しい版として入れ直しが始まる。Ubuntu では deb の入れ直しで進む。macOS（GitHub Releases 版）では .app の入れ直しで進む。Windows の GitHub 版（入っている NSIS とベータ）は、安定版へは Microsoft Store から入れ直す。Ubuntu では deb の版比較は Debian の規則であり、ベータの deb が入っている状態では `dpkg` が安定版の deb をダウングレードとして拒否する。手で安定版へ移すときは、先にベータの deb を外す。GitHub Releases から入れた古い Windows 版で手動の更新確認をしたときは、安定版は Microsoft Store で入手・更新する旨を出す。安定版の Release ページには、ダウンロード手順のあとに、その版の [CHANGELOG](../CHANGELOG.md) の節が載る。Pre-release の本文は、動作確認用だと分かる短い文だけである。macOS の安定版（Apple Silicon）は [GitHub Releases](https://github.com/shkobayashi/schedule-viewer/releases) の Latest から `schedule-viewer_*_aarch64.dmg` で配る。Developer ID による署名と公証はしない。初回起動では Gatekeeper の警告が出ることがある。手順は安定版 Release 本文にある。Intel Mac は [開発ガイド](development.md#配布用ビルド) で手元ビルドする。

Tauri で作ったデスクトップアプリをデスクトップ版、`npm run dev` でブラウザに開いたものをブラウザ版と呼ぶ。違いは次のとおりである。

| 操作 | デスクトップ版 | ブラウザ版 |
| --- | --- | --- |
| 開く | OS のファイルダイアログ | ファイル選択 |
| 保存、別名保存、書き出し | OS の保存ダイアログ | ダウンロード |
| 外部の更新の監視 | 開いているファイルを約1.5秒ごとに見る | しない |
| 復旧用の控え | 未保存のときアプリデータに書く | しない |
| 前回開いたファイル | 開いていたウィンドウ一覧とパスを覚え、次回それぞれを開く | しない |
| 別ウィンドウ | 同じアプリでスケジュールを複数開ける。2つ目のアプリは起動しない | ウィンドウを増やさない |
| ウィンドウを閉じる | 未保存なら控えを書くか、サンプルなら確認する。終了は開いているウィンドウすべてに同じ確認を通す | ブラウザ標準の離脱確認 |
| メンバーとカレンダー | アプリデータ（デスクトップ版では変更を他のウィンドウへ知らせ、読み直す） | localStorage |
| 表示サイズ、配色、左一覧の幅 | localStorage（デスクトップ版では開いているウィンドウで同じ値） | localStorage |
| 行の密度、イナズマ線、一覧の列 | localStorage（デスクトップ版では開いているウィンドウで同じ値） | localStorage |
| 読み書きの上限 | スケジュールと書き出しは 10MB、メンバーとカレンダーは 2MB | 同じ上限 |

## 画面構成

```
+--------------------------------------------------------------------------------------------+
| ☰  タイトル [状態]  [名前|ノート] 検索  絞り込み        今日 日週月 全体  案内  ? |
| 系統  線を引く  追加  マイルストン追加  削除  取り消し  やり直し                      |
| [担当: 佐藤 ×] [期限超過 ×]  すべて解除   （条件があるときだけ）                          |
+--------------------------+-----------------------------------------------------------------+
| WBS / タスク             | 日付ヘッダー                                                    |
| マイルストン             | マイルストン帯                                                  |
| カテゴリ / グループ /    | 親バー、タスクバー、前後の線、イナズマ線                        |
| タスク                   |                                                                 |
+--------------------------+-----------------------------------------------------------------+
```

画面上部のツールバーは2段である。上段に ☰、見出し、検索、絞り込み、今日と日・週・月・全体と操作の案内とショートカット一覧の入口を並べ、下段に系統、線を引く、追加、マイルストン追加、削除、取り消し、やり直しを並べる。各ボタンのラベルは折り返さない。検索は1つの欄で、欄の左で「名前」か「ノート」を切り替える。絞り込みの担当者、ステータス、確度、期限、前後、マイルストンは「絞り込み」ボタンで開くパネルにまとまる。パネルは「絞り込み」ボタンの下に出し、欄の並びが窓の下にはみ出すときは、パネルを窓の中で止め、欄の並びだけを縦にスクロールする。タグ、マイルストン、追加項目の候補一覧は欄の下に重ね、パネルの高さは増やさない。ボタンには、効いている条件の数を出す。条件が1つでもあるとき、または系統が効いているときは、その下に外せる札を並べる。「すべて解除」は絞り込みだけを初期値に戻し、系統は外さない。線を引くモードのあいだだけ、チャートの上端に1行の帯を出す。入口や気づきにくい操作と色の意味は、上段の「案内」、☰ の「操作の案内」、コマンドパレットの「操作の案内」、macOS の表示メニューの「操作の案内」で開くダイアログにまとまる。起動時には出さない。キーの一覧は、? キー、F1、☰ の「ショートカット一覧」で開くダイアログにまとまる。⌘ または Ctrl と K で開くコマンドパレットから、同じ操作の多くを名前で探して実行できる。見出しのタイトル変更（鉛筆）の右に「階層編集」がある。枠と面を常に出すボタンである。「階層編集」の読み上げ名は「階層の名前、意味、指示」である。押すと各段の名前、意味、指示を直すダイアログが開く（EDIT-21）。追加項目の定義は設定の「拡張項目」から直す（SET-10）。

左の行と右のチャートは、縦に一緒にスクロールする。タスクを選ぶと、チャートの右に詳細パネルが出る。詳細パネルは一覧とチャートより一段手前に浮かせて見せる。左一覧とチャートの境界を横にドラッグすると、一覧の幅を変えられる。左の幅に収まらない名前は、マウスを乗せると全文が出る。名前をドラッグしても動かない。担当、追加列、「超過」は動かない。カテゴリ行とグループ行で、配下のタスクを同じ重さで平均した整数の進捗を、名前のうしろに `30%` のように出す。タスクが無い行には出さない。タスク行で項目があるときは、名前の直後に済んだ件数と全体の件数を `3/6` のように出す。行の下にチェックは積まない。追加列を出したときは、開始と終了を `09/19` のように月と日で、日数を `12日`、進捗を `30%`、ステータスは一覧の表示名で出す。件数は追加列には出さない。開始、終了、日数、進捗、ステータス、超過、担当は、行をまたいで同じ位置に揃う。超過が無い行もその幅を空ける。担当が列の幅を超えるときは省略し、マウスを乗せると全文が出る。スケジュール全体に、使用中のステータス一覧またはメンバー一覧に無い `id` があるときは、チャートの上端に短い帯を出す。文は、ステータスか担当か、その両方かだけである。絞り込みで行が隠れていても帯は出す。

☰ メニューの項目は「開く」、デスクトップ版では「最近開いたファイル」（履歴があるときは右に開くサブメニューに、スケジュールと設定ファイルを別グループで新しい順に最大 5 件ずつ並べ、区切りの下に「履歴を消す」。履歴が空のときは同じ位置に残し押せない）、「新しいウィンドウで開く」、「保存」「別名保存」「書き出し」、設定ファイルで開いていないウィンドウだけの「設定ファイルを新しいフォルダへ書き出す」、「JSON を表示」「差分を表示」「操作の案内」「ショートカット一覧」「更新を確認」「設定」である。「開く」「新しいウィンドウで開く」「保存」「別名保存」の右には、Mac では ⌘、それ以外では Ctrl のショートカットを出す。ファイル操作の途中は、開く、履歴からの開く、新しいウィンドウで開く、保存、別名保存、差分を表示を押せない。「履歴を消す」はファイルを開かないので、その途中でも押せる。未保存のときは、画面下の状態バーの「未保存」を押しても差分列を開き結果を出す。メニューは外側のクリックか Escape で閉じる。macOS のデスクトップ版では、画面上部のメニューバーにも同じファイル操作と、表示の切り替え、文字入力用の編集メニュー、ウィンドウメニュー（⌘W で閉じる、⌘M で最小化）を出す。編集の取り消しは、入力欄にフォーカスがあるときは文字入力の取り消し、それ以外はスケジュールの履歴を戻す。アプリメニューの終了は ⌘Q を割り当て、開いているウィンドウすべてに、ウィンドウを閉じる操作と同じ未保存確認を通る。

ダイアログが開いているあいだ、開く、新しいウィンドウで開く、保存、別名保存、タスク名の検索への移動、Enter で詳細パネルの名前欄へフォーカスを移す操作、Delete と Backspace での削除、線を引く、ノートを開く、タスクの追加、マイルストンの追加、タスクの複製、同じグループでの並べ替え、⌘/Ctrl+矢印でのスクロール、? と F1 によるショートカット一覧の開き、⌘/Ctrl+K によるコマンドパレットの開きは効かない。差分列はダイアログではないので、この停止には掛からない。コマンドパレットだけが開いているあいだは、同じ ⌘/Ctrl+K と Escape で閉じる。詳細パネルの入力欄にフォーカスがあるあいだも、外部ファイルの即時反映は止める。検索欄、入力欄、選択欄、ボタンにフォーカスがあるとき、開く、保存、別名保存、タスク名の検索への移動、⌘/Ctrl+矢印でのスクロール、⌘/Ctrl+K によるコマンドパレットの開きは効く。線を引く ⌘/Ctrl+L と、ノートを開く ⌘/Ctrl+N、タスクの追加（⌘/Ctrl+Enter と Insert）、マイルストンの追加（⌘/Ctrl+Shift+Enter）、タスクの複製（Alt+Shift+↓）、同じグループでの並べ替え（Alt+↑ と Alt+↓）は、検索欄、入力欄、選択欄では効かず、ボタンでは効く。ボタンにフォーカスがあっても、そのボタンのクリックにはしない。Enter と Delete と Backspace、修飾キーの無い矢印と L と N は、そのフォーカス先の操作のままにする。⌘/Ctrl+N は、開くときも、選択が無いなどで何もしないときも、ブラウザには渡さない。Shift 付きの N はアプリが取らない。タスクの追加とマイルストンの追加は、選択が無くても開く。複製と並べ替えは、選択が無いときは何もしない。ダイアログを開くキーは、押し続けでは開かない。右クリックメニューと ☰ と追加の種類のメニューが開いていれば閉じる。線を引くモードのあいだは、追加、マイルストンの追加、複製、並べ替えをしない。表示サイズの ⌘ または Ctrl と +、=、− は、ダイアログが開いていても、検索欄、入力欄、選択欄、ボタンにフォーカスがあっても効く。? と F1 は、検索欄、入力欄、選択欄では効かない。

画面下の状態バーに、ファイル名、保存の状態、メンバーカタログ、表示の粒度、件数を出す。件数は「全件数中、表示件数を表示」の順である。保存の状態は、未保存のとき「未保存」（押すと差分列を開く）、保存済みのとき「保存済み」またはファイル名に応じた表示である。未保存で開いているファイルとの差があるあいだは、チャート右に差分の取っ手を出す。一覧、チャート、詳細は操作できる。差分列のテキストにフォーカスがあるあいだは、ガント向けのキーは止まる。外部の反映のような一時的な知らせは、画面の隅に数秒だけ出る通知にする。差分列が開いている、または取っ手だけ出ているときは、知らせの右位置を列の幅だけ左へずらす。別のウィンドウで同じファイルが更新されたときの知らせも同じ隅に出し、押すとそのウィンドウを前面に出す。アプリが他のソフトの後ろにあるときは、同じ内容を OS の通知でも出す。メンバーとカレンダーの設定エラーは状態バーに注意の色で出し、押すと設定の該当欄が開く。見出しのタイトル欄には、スケジュールのタイトルだけを出す。

### FILE-01 開く

**操作** ☰ の「開く」。⌘/Ctrl+O でも同じ。

**挙動** 選んだ JSON を検証し、通れば画面のスケジュールを置き換える。見出しのタイトルは JSON の `title` になる。ファイル名は状態バーとウィンドウタイトルに出す。絞り込み、折りたたみ、系統、選択、取り消し履歴は初期状態に戻し、期間が幅に収まるよう Fit する。横位置と一覧の縦位置を先頭へ戻す。検証に失敗したファイルは開かず、それまでの保存先も変えない。エラーは日本語で、場所はカテゴリ、グループ、タスクの名前で示す。`schedule` が文字列で `categories` が無い JSON は FILE-10 の設定ファイルとして開き分ける。スケジュール JSON を直接開いたときは、隣の設定ファイルは読まない。

**制約** 未保存のときは、破棄して開くかキャンセルするかを先に選ぶ。ファイルの `note` が空白だけのときは読み込みエラーになる。画面でノートを空にして保存すると、その項目は消える。読み込み上限は 10MB。開けるのは schemaVersion 3、4、5、6、7、8 である。3 は、確度が無いタスクを確定として読む。4 は、カテゴリとグループに名前から決まる `id` を付ける。5 は、マイルストンが1件以上あるとき、名前「マイルストン」のグループを1つ足し、全部のマイルストンをそこへ入れる。マイルストンが0件なら、そのグループは空のままである。6 はマイルストン帯のグループ（`milestoneGroups` と `groupId`）である。7 はタスクの `tags` で、8 はタスクの `status` を一覧の項目の `id` で書く形である。7 以前の `status` の文字列は変えない。いずれも schemaVersion 8 にする。タグが無い 3〜6 は、タグなしとして読む。開いた直後の未保存の比較元は、その移行後の保存形式である。ディスク上の文字列とそのまま比べないので、開いただけでは未保存にならない。同じ 3、4、5、6 を開き直しても、付けた `id` は変わらない。保存すると schemaVersion 8 になる。schemaVersion 2 は開けない。ブラウザ版では「新しいウィンドウで開く」は出ない。

### FILE-10 設定ファイル

**操作** FILE-01 と同じ「開く」で、設定ファイル（`workspace.json` など）を選ぶ。デスクトップ版の FILE-09 から設定ファイルの履歴を選んでも同じ。

**挙動** 設定ファイルを検証し、相対パスで指したスケジュールを開く。メンバー、ステータス一覧、カレンダー、色の一覧のパスがあるときは、そのウィンドウだけで読み、表示に使う。アプリのメンバー、ステータス、カレンダーの選択は変えない。パスが無いメンバーは未選択、無いステータスは組み込みの三件、無いカレンダーは土日を塗る、無い色の一覧は行の地を塗らない。保存と別名保存はスケジュールファイルだけを書く。開いているあいだに自動で読み直すのはスケジュールだけである。設定ファイル、メンバー、ステータス一覧、カレンダー、色の一覧は起動時と、その設定ファイルを開き直したとき、および同じ設定ファイルを開いている別ウィンドウを前面にしたときに読み直す。覆いでメンバー JSON、ステータス一覧ファイル、色の一覧ファイルを保存したとき、編集用の拡張を作る、覆いで保存する、消すときも、同じ設定ファイルを開いているウィンドウへ読み直しを送る。すでに同じ設定ファイルで開いているウィンドウを前面にするとき、スケジュールのパスが変わっていなければ未保存のスケジュール本文は捨てない。

**制約** デスクトップ版だけ開ける。ブラウザ版では開けず、見出し「設定ファイルは開けません」で、デスクトップ版で開く旨と今の画面はそのままである旨を出す。読めない、検証に失敗、上限超過のときは、そのウィンドウに設定エラーを出す。色の一覧だけ読めないときは、状態バーに「色の一覧を読み込めませんでした。」を出し、設定は開かない。起動時に設定ファイルのパスがあるが読み込めないときは、中のスケジュールも開かず、サンプルのままにする。同じウィンドウでスケジュール JSON を直接開いたときは、設定ファイルの束縛を外し、アプリの設定に戻る。別名保存で別のスケジュールファイルを保存したときも、設定ファイルの束縛を外す。すでに同じ設定ファイルを開いているウィンドウを前面にしたとき、スケジュールのパスが変わっていなければ未保存のスケジュール本文は捨てず、設定ファイルとメンバーとステータス一覧とカレンダーと色の一覧だけ読み直す。パスが変わったときは、未保存の確認のあと新しいスケジュールを開く。確認をキャンセルしたときは画面も束縛も変えない。

### FILE-11 設定ファイルを新しいフォルダへ書き出す

**操作** 設定ファイルで開いていないウィンドウだけ、☰ と macOS のファイルメニューの「設定ファイルを新しいフォルダへ書き出す」。

**挙動** フォルダ選択のタイトルは「書き出し先のフォルダ」である。ファイルが 1 件も無いフォルダだけを選べる。`.DS_Store` だけ、または Windows の `Thumbs.db` と `desktop.ini` だけのフォルダは空として扱う。選んだ空のフォルダに、今の画面のスケジュール、選択中のメンバー、選択中のステータス一覧、選択中の色の一覧、取り込み済みのカレンダー、設定でチェックしている拡張項目をそれぞれ新しい JSON として書く。メンバー未選択、組み込みの三件のステータス、色未選択、カレンダー未設定はファイルを作らない。拡張項目は、チェックしているものだけを、選んだ順に `プラグインID.fields.json` として書く。1件も書けないときはファイルを作らない。`workspace.json` に、作ったファイルへの相対パスだけを書く。拡張項目は `fieldExtensions` に、書いたファイル名を選んだ順の配列で書く。今のウィンドウはユーザ設定モードのままにする。成功したときは、書き出したことと、このウィンドウがアプリの設定のままであること、書かなかったものがあればその旨を短い知らせで出す。拡張項目を1件も書かなかったときは「拡張項目は選んでいないため書いていません。」を出す。1件以上書いたときは、この文は出さない。

**制約** ファイルが 1 件でもあるフォルダは選べない。選んだときは何も書かず、「空のフォルダを選んでください。ファイルは書いていません。」を出す。親がシンボリックリンクのフォルダは選べない。失敗の見出しは「書き出しに失敗しました」である。一つでも書いたあとに失敗したときは、理由のあとに、それまでに書いたファイルがフォルダに残っていることと、このウィンドウがアプリの設定のままであることを出す。一ファイルも書いていないときは残した旨は出さない。アプリの設定は変えない。

### FILE-09 最近開いたファイル

**操作** デスクトップ版の ☰ の「開く」の下の「最近開いたファイル」から開くサブメニュー内の項目、macOS のファイルメニューの同じ位置のサブメニュー、⌘ または Ctrl+K のコマンドパレットの「最近開いたファイル …」、および「履歴を消す」。

**挙動** 開くことに成功したスケジュールの絶対パスを、新しい順に最大 5 件、設定ファイルの絶対パスを別配列に新しい順に最大 5 件、アプリデータの `recent-files.json` に覚える。設定ファイルを開いたときは設定ファイルの一覧だけに足し、中のスケジュールパスはスケジュールの一覧に足さない。どのウィンドウで開いても同じ一覧に足す。☰ と macOS のファイルメニューとコマンドパレットは、開くときに読み直す。履歴が空のとき、☰ と macOS のファイルメニューでは「最近開いたファイル」の行だけ残し、押せない。サブメニューは開かない。コマンドパレットには、履歴があるときだけ各ファイルと「履歴を消す」を出す。☰ と macOS のファイルメニューのサブメニューは、件がある側だけ「スケジュール」と「設定ファイル」の見出しを出し、両方あるときは見出しのあいだに区切りを入れる。見出しは押せない。項目の文言はファイル名である。同じ一覧の中で同じファイル名が 2 件以上あるときだけ、親フォルダ名を `ファイル名（親フォルダ）` の形で添える。コマンドパレットの項目は「最近開いたファイル スケジュール …」と「最近開いたファイル 設定ファイル …」の形である。☰ の項目にマウスを乗せたとき、絶対パスを出す。選んだ項目は、今のウィンドウで FILE-01 の「開く」と同じに開く。検証に通れば FILE-01 と同じ画面になる。「履歴を消す」は、覚えたパスをすべて消す。確認は出さない。開いているスケジュールは閉じない。

**制約** ブラウザ版では記録もメニューもコマンドパレットも出さない。パスが付いて画面に載せたときだけ足す。検証に失敗したとき、未保存の確認をキャンセルしたとき、サンプルのままのとき、保存、別名保存、起動時に前回のウィンドウを開き直すとき、既に開いているパスを前面にするだけのとき、MCP-01 の `replace_schedule` では足さない。同じファイルは 1 件にまとめ、ウィンドウ同士の突き合わせと同じパスキーで決める。もう一度開いたときは先頭へ移し、そのとき渡されたパス文字列を残す。一覧を出すときにファイルの有無は見ない。開けなかったときも項目は消さない。読めない、検証に失敗、ファイルが無いときは開かず、今の画面と保存先は残す。サンプルには戻さない。未保存のときは、破棄して開くかキャンセルするかを先に選ぶ。キャンセルしたときは開かず、順番も変えない。ファイル操作の途中と起動復旧が終わる前は、履歴からの開くを「開く」と同じく押せない。`recent-files.json` が壊れている、読めない、上限を超えているときは空として扱い、知らせない。次回起動のウィンドウ一覧（SYNC-03）、未保存の控え、絞り込みの記録は「履歴を消す」では消さない。パスはアプリデータに残るだけで、外へは送らない。

### FILE-08 ドロップで開く

**操作** デスクトップ版で、スケジュール JSON をウィンドウへ落とす。Finder などから、チャート上、左の一覧、マイルストン帯、アプリのウィンドウのどこへ落としてもよい。通過中のカーソルは OS と Tauri の受け付けのままである。

**挙動** 拡張子 `.json` のファイルがちょうど1件のときだけ、落としたウィンドウの「開く」と同じに開く。検証に通れば FILE-01 と同じ画面になる。ファイルダイアログは出さない。メンバー JSON とカレンダー JSON はスケジュールとして検証し、通らなければ開かない。設定へは取り込まない。

**制約** 未保存のときは、破棄して開くかキャンセルするかを先に選ぶ。フォルダ、`.json` 以外、2件以上を落としたときは開かず、「スケジュールの JSON を1つだけ落としてください。」と出す。ダイアログが開いている、開く・保存・別名保存の途中、起動復旧が終わる前、左一覧の並べ替えでしきい値を超えてドラッグ中は開かず、「画面の操作が途中なので、開けません。」と出す。忙しいときは、件数の文より先にこの文を出す。検証に失敗したときは、開くときと同じ読み込みエラーで、それまでの保存先は変えない。ネイティブのドロップがポインタを取るので、チャートの移動、期間の変更、並べ替えにはならない。ブラウザ版では JSON を開かず、ページがそのファイルへ移らないようにするだけである。

### WIN-01 新しいウィンドウで開く

**操作** デスクトップ版の ☰ の「新しいウィンドウで開く」。⌘/Ctrl+Shift+O でも同じ。コマンドパレットと macOS のファイルメニューからも選べる。

**挙動** 選んだ JSON を、今のウィンドウではなく新しいウィンドウで開く。今のウィンドウのスケジュールは残す。検証は今のウィンドウ側で行い、失敗したときは今のウィンドウにエラーを出し、ウィンドウは増やさない。通ったときだけ新しいウィンドウを作り、その内容を載せる。開き分けと移行は FILE-01 と同じである。`schedule` だけの設定ファイルは FILE-10 と同じに、相対パスのスケジュールと束縛を新しいウィンドウだけに読む。設定ファイルを開いたときは履歴に設定ファイルだけを足し、中のスケジュールパスは足さない。スケジュール JSON は schemaVersion 3〜8 を FILE-01 と同じく移行してから載せる。絞り込み、折りたたみ、系統、選択、取り消し履歴は新しいウィンドウだけ初期状態に戻し、期間が幅に収まるよう Fit する。同じパスは複数のウィンドウで開ける。

**制約** 未保存でも破棄の確認は出さない。ファイル操作の途中は押せない。⌘/Ctrl+Shift+O はデスクトップ版だけが取り、ブラウザ版はブラウザに渡す。ウィンドウの位置は覚えない。枚数の上限は置かない。開けるスケジュールの schemaVersion は FILE-01 と同じである。設定ファイルの読み込みに失敗したときは、新しいウィンドウに設定エラーを出し、スケジュールは載せない。

### FILE-02 保存

**操作** ☰ の「保存」。⌘/Ctrl+S でも同じ。

**挙動** 開いているパスがあれば、そのファイルへ今の内容を書く。無ければ別名保存と同じく保存先を選ぶ。成功すると未保存が外れ、控えは消える。

**制約** デスクトップ版は、開いているパスと保存先が一致するときだけ上書きする。書き込み上限は 10MB。ディスクの内容が開いたときと違えば SYNC-02 に進む。`levels` があり、入れ子の深さがその段数と一致しないときはファイルを書かず、「入れ子の数が階層の定義と違うので、保存できません。」と出す。文書は未保存のままである。保存に失敗したとき（階層の不一致、検証、書き込み、保存前の確認の失敗）は、見出し「保存できません」で本文に理由を出す。ブラウザ版は常にダウンロードで、パスは残らない。

### FILE-03 別名保存

**操作** ☰ の「別名保存」。⌘/Ctrl+Shift+S でも同じ。

**挙動** 保存先を選び、今の内容を書く。成功すると、そのパスが次の上書き先になる。

**制約** 拡張子は `.json`。ブラウザ版はダウンロードし、表示上のファイル名を外すので、状態バーは「サンプルデータ」に戻ることがある。見出しのタイトルは JSON の `title` のままである。中身の未保存は、ダウンロードした内容と一致すれば外れる。

### FILE-04 未保存の判定

**操作** 見出しの状態を見る。

**挙動** 保存形式にした画面の JSON と、最後に開いた・保存した・読み直した JSON が違えば「未保存」になる。インデントやキー順だけの違いは、同じ内容として扱う。MCP-01 の `replace_schedule` で前面ウィンドウの文書を置き換えたときも、画面で編集したときと同じ未保存の判定と控えになる。

**制約** 絞り込み、折りたたみ、ズーム、スクロール、系統、選択は未保存にしない。ダイアログで確定する前の入力と、見出しのタイトル入力の途中も、未保存の判定には含めない。

### FILE-05 閉じるとき

**操作** ウィンドウまたはタブを閉じる。

**挙動** デスクトップ版で、そのパスの最後のウィンドウが未保存なら、控えを書いてから閉じる。同じパスのウィンドウが残るときは、残ったうち前面の内容で控えを書き直す。保存済みで閉じても、開いていたパスは残る。サンプルのまま未保存なら、破棄して閉じるかキャンセルするかを選ぶ。破棄して閉じると控えも消える。パスが無いウィンドウを閉じても、他のウィンドウのパスは消さない。macOS の ⌘Q を含む終了は、開いているウィンドウすべてに、同じ確認を通してからアプリを終える。確認をキャンセルしたときは、どのウィンドウも閉じない。1枚だけ閉じるときは、そのウィンドウだけを見る。ブラウザ版は、未保存のときブラウザ標準の確認になる。

**制約** 次回に戻るのは、スケジュールの内容、開いていたファイル、そのファイルの絞り込みと折りたたみである。ズーム、スクロール、系統、選択は戻らない。同じパスを複数のウィンドウで開いているとき、控えを書くのはそのパスを開いているウィンドウのうち前面のものだけである。前面が保存済みなら、そのパスの控えは消す。ウィンドウを1枚閉じたとき、同じパスのウィンドウが残っていれば、残ったうち前面の内容で控えを書き直す。絞り込みの記録も、控えと同じ前面のウィンドウだけが書く。

**挙動** 今のスケジュールを、保存と同じ形式の JSON で見せる。ファイルには書かない。

**制約** 編集はできない。

### FILE-07 差分を表示

**操作** ☰ の「差分を表示」。未保存のときは状態バーの「未保存」。⌘ または Ctrl+Shift+D で全文をコピーする（列を開かない）。コマンドパレットの「差分をコピー」も同じ。

**挙動**

- 列: チャートの右に、スクロールできる一覧を出す。詳細パネルの右に置き、一覧、チャート、詳細は操作できる。☰ の「差分を表示」と状態バーの「未保存」は列を開き、差の一覧、「差はありません」、「比べるファイルがありません」のいずれかを出す。未保存で開いているファイルとの差があるあいだは、画面の編集が確定するたびに読み直す。開いたあとの自動更新は開いたまま、畳んだあとの自動更新は畳んだまま。中身だけ替える。差の一覧は列を畳み、右端の取っ手だけ出す。取っ手を押すと列を開く。開いたあとは「畳む」で取っ手に戻す。差が無いときとパスが無いときは、列も取っ手も出さない。空の結果を出しているあいだに差の一覧ができたときは、開いたまま一覧へ切り替え、「閉じる」は「畳む」になる。開いているファイルのパスが変わったときは、明示で出した空の結果を捨て、列をしまう。未保存で差があるときだけ、そのあと自動で一覧を読み直す。空の結果だけ「閉じる」で列をしまう。列の「コピー」で、閉じた行の本文も含めた全文を写す。ファイルには書かない。一覧にフォーカスがあるあいだは、ガント向けのキーは止まる。
- 一覧: 各変更は種類の札と名前の1行で並ぶ。行の高さは左のタスク行に揃える。場所は行に全文が入るときだけ名前のうしろに出す。行を押すか Enter で、その行を開き、見えている対象へ寄せる。繋がりの行は、見えている端のうち文書で前のタスクへ寄せる。両方見えなければ理由を出し、選択は変えない。見えているタスク、カテゴリ、グループの行は縦に動かさない。マイルストンは横だけ寄せ、ひし形の枠を太くして示す。マイルストングループと削除したマイルストンは、帯が見えていれば左の帯の行に薄い帯を付ける。削除のタスクは、画面に残っている親のグループ行へ寄せ、親の行にホバーと同じ薄い帯を付ける。↑↓ は行を移し、開いた行の本文だけを替える。チャートを動かすのは、行を押したときと Enter だけである。一覧にフォーカスがあるあいだは ↑↓ でタスク選択は動かない。開いた行の本文は選択して写せる。並びの行は寄せない。画面に無い、折りたたみや絞り込みで見えない、帯の線がオフのときは寄せず、行に理由を出す。寄せてもタスクの選択と詳細パネルは変えない。チャートか左の行でタスクを選び直すか、別の行を開くまで薄い帯は残る。title の行は左上のタイトルを示す。↑↓ で title の行を開いているあいだも同じ。
- 表示: 今の画面を保存と同じ形式にしたものと、開いているファイルを読んだ内容との差を、コピー用の全文と同じ文言で見せる。一覧の行の並びと、閉じた行に含まれる本文は、この全文と一致する。
- 失敗時: パスが無いとき（サンプル、ブラウザ版）は「比べるファイルがありません」と列に出す。差が無いときは、見出しのあとに「差はありません」と列に出す。読めない、10MB を超える、または検証に失敗したときは列に書かず、☰、「未保存」、コピーキーでは開くときと同じ読み込みエラーを出す。自動の読み直しで失敗したときはエラーダイアログを出さない。直前の差の本文があれば残す。
- 対応づけ: タスク、マイルストン、カテゴリ、グループは id で対応づける。`levels` と `outline` で保存する文書では、タスクと見出しも同じ id で対応づける。画面の `categories` が空でも、カテゴリの削除としては出さない。繋がりは両端のタスク id で対応づけ、`taskIds` の順だけが違うときは同じ組として扱う。追加は `追加 繋がり`、削除は `削除 繋がり`、言葉だけが違うときは `変更 繋がり` として前後を書く。タスクを消して組だけが残る削除は、タスク削除の差分とは別行にする。同じ id でカテゴリまたはグループの名前だけが違うときは、`変更 カテゴリ` または `変更 グループ` として `name` の前後を書く。`outline` の見出しの追加は `追加 見出し`、削除は `削除 見出し`、名前の変更は `変更 見出し` として前後を書く。`levels` の定義が違うときは、先頭行 `階層の定義` のあとに変わった段の項目を書く。同じ id のグループが別のカテゴリにあるときは、削除と追加にせず、`変更 グループ` の場所に移す前と移したあとの「カテゴリ名 / グループ名」を書く。名前も違うときは、場所のあとに `name` の前後を書く。親の id が同じタスクは、親の改名だけでは場所を出さない。場所の表示はカテゴリ名とグループ名のままである。同名でも id が違えば削除と追加である。別のグループへ移したタスクは、場所の変更として出す。
- 表示順: 変更と追加は画面の並び、削除はファイルの並びで書く。タスクの変わったフィールドだけを、場所、name、start、end、assigneeId、status、progress、confidence、predecessors、milestoneId、todos、tags、追加項目（使用中の定義の順。定義に無いキーはそのうしろへキーの文字順。ラベルは合成キー。値は JSON。無い側は「（なし）」）、note の順で書く。担当の `assigneeId` は一つの前後で書く。空は `null`、複数 id は入れた順に「, 」で並べ、順番だけが違うときも差にする。人の増減だけにはしない。追加と削除では、値がある追加項目のキーだけを同じ順で書く。タスクの変更、追加、削除では場所を必ず書く。`todos` は `[ ]` と `[x]` で済みを示し、無い側は「（なし）」と書く。日付の差は暦日で、`（+7日）` のように書く。先行は集合として比べ、増減だけを書く。追加は場所と全フィールドを書き、兄弟の並びは繰り返さない。削除はファイル側の名前、場所、全フィールドを書く。空のまま残っているグループとカテゴリは削除にしない。タスクを消して先行から外れたことは、残ったタスクの先行の変更として出す。カテゴリ、グループ、マイルストンの配列は、追加と削除を除いても残りの順が違うときだけ並びとして出す。タスクの並びは、同じ id の入れ替えでは左辺をファイルに残っているタスクの順、右辺を画面の順にする。末尾への追加だけなら並びは出さない。新しいタスクが末尾以外に入ったときは、右辺にそのタスクも含め、左辺はファイルに既にあるタスクの順にする。並べ替えと末尾への追加が同時のときは、右辺は末尾の追加を除いた画面の順にする。マイルストンの変わったフィールドだけを、name、date、confidence、groupId の順で書く。`groupId` はグループ名の前後で書く。date の差も暦日である。

**制約** 絞り込み、折りたたみ、ズーム、スクロール、系統、選択、確定前の入力は含めない。未保存の表示とは別で、画面と今のファイルが同じなら未保存でも差は空である。開く、保存、別名保存の途中はボタンもキーも止める。ブラウザ版では ⌘/Ctrl+Shift+D をブラウザに渡さない。読んだ内容はこの機能のためには保存しない。スキーマは変えない。

### SYNC-01 外部更新の反映

**操作** デスクトップ版でファイルを開いたままにする。保留中は「ファイルに更新あり — 確認する」を押す。

**挙動** 約1.5秒ごとにファイルの内容を見る。未保存でなく、ダイアログも開いておらず、詳細パネルにも入力の途中が無く、見出しのタイトル入力も開いておらず、階層の編集（EDIT-21）も開いておらず、拡張項目の編集（SET-10）も開いておらず、色の一覧の編集（SET-09）も開いておらず、メンバーの項目の編集（SET-02）も開いていなければ、検証に通った内容を画面へ即時反映し、約4秒「ファイルを反映しました」と出す。未保存、または編集中なら、「ファイルが更新されています」を出す。起点・画面・ファイルの分類（MCP-01 の `baseline_diffs` と同じ規則）で、衝突が無いときは「両方を画面へ反映」を選べる。繋がりについても同じ分類を使う。同じ組の言葉が画面とファイルで違う、片側だけの削除と言葉の変更が同時、画面でタスクを消してファイルでその端を含む組を足した、の三つは衝突である。衝突が無いときの合成では、画面とファイルの変化を起点へ載せ、片側だけ外した組は外し、両側が足した別の組は両方残す。`levels` と `outline` を使う文書では、分類と合成は `outline` の見出しとタスク、および `levels` の定義を見る。画面の `categories` が空でも、カテゴリの削除として扱わない。段の数や見出しの親子が画面とファイルで違うときは衝突とし、「両方を画面へ反映」は出さない。木の形が同じときだけ、非衝突のタスク変更と定義の変更を `levels` と `outline` のまま画面に置く。読み直すと「両方を画面へ反映」では、階層の編集ダイアログと「繋がりを足す」ダイアログ（EDIT-23）と追加項目の編集覆いと色の一覧の編集覆いとメンバーの項目の編集覆いは確定せず閉じ、下書きは文書へ書かない。確認では、変更の一覧を「画面」と「ファイル」の節に分け、それぞれに変わった項目を出す。各行を開いたときの項目の本文は、FILE-07 と同じ規則である。`outline` のタスクの `todos` と `tags`、見出し、`levels` の定義も含む。追加と削除は閉じたままにし、同じ変更は件数と見出しだけを閉じたままにする。一覧だけがスクロールし、ボタンは外に残る。衝突があるときは、一覧は衝突の見出しだけをスクロールする。衝突の見出しの下に、画面とファイルで違う追加項目だけを、FILE-07 と同じ定義の順で出す。同じキーで画面とファイルの型が違うとき（数値と文字列など）は衝突とし、自動では決めない。衝突が無いときの最初のフォーカスは「両方を画面へ反映」、衝突があるときと合成が検証に通らないときは「読み直す」である。Enter では反映も読み直しもしない。Space とクリックはそのままである。反映すると起点から非衝突の結果だけを画面の未保存に置き、ファイルには書かない。消えた行の選択は外し、残っている行の選択と系統は残す。開いている編集ダイアログは閉じる。約4秒「両方の変更を画面へ反映しました」と出る。取り消しで反映の直前の文書に戻ったときだけ、保留の帯を戻す。やり直しで反映の直後の文書に進んだときだけ、帯を消す。反映のあとに別の編集だけを取り消したときは帯は出ない。保存や読み直しで起点が変わったあとの取り消しでは帯は戻らない。分類が「同じ」だけのときは、見えている内容は変わらない。読み直すと未保存が消え、取り消しは空になる。衝突があるとき、または合成が検証に通らないときは、画面では一つにまとめない。衝突が無いのに反映できないときは、件数の文ではなく理由を1行出す。「依頼文をコピー」で、チャットへ MCP または read-screen スキルを使って `baseline_diffs` を読ませる文を渡せる。チャットが MCP-01 の `replace_schedule` でまとめを画面へ置いたときは、確認を閉じ、起点と違えば未保存にする。状態バーの「ファイルに更新あり — 確認する」は出さない。取り消しで反映の直前に戻ったときだけ、帯を戻す。いつも「読み直す」と「画面の編集を残す」も選べる。読み直すと画面の編集は捨て、控えも消える。残すと状態バーに「ファイルに更新あり — 確認する」が出て、画面の内容はそのまま残る。開いたダイアログのあいだにファイルがもう一度変わったときは、一覧を差し替え、「ファイルがもう一度更新されました」と出す。検証に失敗した内容は反映せず、同じ内容のエラーを繰り返さない。

**制約** ブラウザ版では動かない。読み取りに5回連続で失敗すると、SYNC-03 の、ファイルが無いときのファイルダイアログを出す。1回だけの失敗では出さない。読み取り失敗の汎用メッセージは出さない。成功すると回数は戻り、同じ欠落では一度だけ出す。自分の保存は外部更新とみなさない。同じパスを別のウィンドウで開いているとき、片方が保存すると、もう一方は外部更新として扱う。保存した側は、自分の保存を外部更新にしない。

### WIN-02 他ウィンドウのファイル更新の知らせ

**操作** デスクトップ版で、同じファイルを複数のウィンドウで開く。片方で SYNC-01 の反映または確認が終わる。

**挙動** 結果を他のウィンドウへ知らせる。知らせを受けたウィンドウの隅に、ファイル名と「反映した」か「確認待ち」を出す。押すと、更新が起きたウィンドウを前面に出す。「反映した」は数秒で消す。「確認待ち」は、そのウィンドウが確認を終えるまで残る。確認が終わると「確認待ち」は消え、読み直したときは「反映した」に替わる。未保存のウィンドウは、知らせだけでは書き換えない。アプリのどのウィンドウも前面に無いときだけ、同じ内容を OS の通知で1回出す。通知のクリックを受け取れる環境では、押すとそのウィンドウを前面にする。

**制約** ブラウザ版では動かない。通知が出せない環境でも、アプリ内の知らせは動く。

### WIN-04 アイコンとショートカットで開く

**操作** デスクトップ版で、スケジュール JSON を Dock、Finder のアプリケーション、デスクトップのエイリアス、実行ファイル、デスクトップのショートカット、タスクバーにピンしたアイコン、Ubuntu のランチャ、`.desktop` へ落とす。アプリが動いていないときは起動も含む。JSON のダブルクリックでは開かない。

**挙動** 拡張子 `.json` のファイルがちょうど1件のときだけ開く。検証は FILE-01 と同じである。アプリが動いていないときは、起動と SYNC-03 の復元が終わってから開く。復旧の確認ダイアログが開いているあいだは待ち、閉じたあとに開く。この待ちでは忙しい旨は出さない。パスの無いウィンドウが1枚だけなら、そのウィンドウで FILE-01 と同じに開く。未保存なら破棄の確認を出す。それ以外は新しいウィンドウで開く。今開いているウィンドウの未保存確認は出さない。すでに動いているときは2つ目のプロセスを作らず、既存のアプリを前面に出す。同じパスを開いているウィンドウがあれば、前面順の新しい方を前面にする。中身は読み直さず、未保存も残す。同じパスが無ければ新しいウィンドウで開く。検証に失敗したときはウィンドウを増やさず、前面のウィンドウにエラーを出す。前面のウィンドウが受け付けない状態なら開かず、忙しい旨を出す。パスが渡らないときは前面に出るだけで、ファイルは開かず、エラーは出さない。`--mcp` と `--screen` だけの起動ではファイルを開かない。同じ起動で引数と macOS の `Opened` が同じパスを二度渡しても、開く処理は1回である。

**制約** ブラウザ版では動かない。フォルダ、`.json` 以外、2件以上は FILE-08 と同じ文で拒む。忙しい条件も FILE-08 と同じである。macOS と Linux のインストーラは、拡張子 `json` を閲覧用に宣言するが、既定の開き先には選ばれない。Windows は関連付けを登録しない。実行ファイルとショートカットは、関連付けが無くても引数でパスを受け取る。

### SYNC-02 保存時の外部更新の確認

**操作** 外部で変わったファイルに対して「保存」を押す。

**挙動** 「上書き保存」「別名保存」「取り消し」を選ぶ。上書きはそのパスへ書く。別名保存は別のパスを選ぶ。取り消しは何も書かない。

### SYNC-03 前回のファイル

**操作** デスクトップ版でファイルを開き、保存して、または未保存のまま閉じて、次に起動する。

**挙動** 開いていたウィンドウを `open-windows.json` に順に書く。各要素はウィンドウのラベル、スケジュールのパス、設定ファイルで開いたときはそのパス（任意）、またはパスの無いサンプルである。前面にあったウィンドウのラベルも書く。設定ファイルのパスがあるウィンドウは、次回起動時にその設定ファイルからスケジュール、メンバー、ステータス一覧、カレンダー、拡張項目（ピン留めと編集用）を読む。未保存の控えはパスごとに1ファイル。`schedule-recovery/` に、パスのハッシュを名前にした JSON を置く。中身は `path`、`baselineJson`、`documentJson` である。絞り込みはパスごとに1ファイル。`schedule-filters/` に、控えと同じハッシュを名前にした JSON を置く。中身は `version`、`path`、絞り込みの各値、検索欄の対象、帯の線をオフにしたマイルストングループの id、折りたたんだカテゴリ id の配列、折りたたんだグループ id の配列である。初期値のときは絞り込みのファイルを置かない。サンプルは控えも絞り込みも作らない。次回起動時、記録にあるウィンドウをそれぞれ作る。同じパスが複数あるときは1つにし、閉じる時点で前面だったウィンドウの未保存だけを残す。文書を画面へ載せたあと、そのパスの絞り込みと折りたたみを戻す。☰ の「開く」と「新しいウィンドウで開く」で選んだファイルでは戻さない。`open-windows.json` が無く、古い `last-schedule.json` がある初回起動は、その1枚として開く。古い控えがあれば、そのパスの控えへ移し、移し終えたら古い2ファイルは消す。

各ウィンドウについて、ファイルがあり、未保存が無いか、ディスクが控えの基準と一致すれば、そのファイルを開く。未保存があれば、その内容を未保存のまま戻す。警告は出さない。ディスクが未保存の内容と違えば、「ファイルを開く」か「未保存の編集を戻す」かを選ぶ。開くならそのパスの最新内容を保存済みとして読み、控えは消す。戻すなら画面は控えのままで、ディスクの内容はあとから読み直せる。

前回のファイルが無く、未保存も無いときは、見つからないことを知らせてサンプルにする。ファイルダイアログは出さない。前回のファイルが無く、未保存があるときは、未保存を画面に戻し、ファイルが無いことを知らせる。「未保存の編集を戻す」はその内容を残す。「ファイルを開く」は、下のファイルダイアログである。この起動でファイルが無いと知らせたあとは、そのファイルが再び読めるまで、監視のファイルダイアログは出さない。

ファイルが無いときの「ファイルを開く」は、起動時の警告と、作業中にファイルが消えたときで同じである。覚えたパスは直接開かず、OS のファイルダイアログを出す。初期フォルダは、保存先の親フォルダが残っていればそこ、無ければホームである。消えたファイルは初期選択にしない。キャンセルすると、画面に出している内容と見出しのパスを残す。未保存なら、破棄して開くかの確認を先に出す。選んだあとは、通常の開くと同じ検証に進む。作業中は、1回読めないだけでは出さず、5回連続で読めなくなってから出す。

**制約** 次回に起動するウィンドウは、記録のラベルと一致する。記録に `main` が無いときは、設定で自動に作られる空の `main` は起動直後に閉じ、記録のウィンドウだけが残る。次回に戻るのは、スケジュールの内容、開いていたファイル、そのファイルの絞り込みと折りたたみである。ズーム、スクロール、系統、選択は戻らない。サンプルではパスも控えも絞り込みの記録も作らない。保存、破棄して別ファイルを開く、外部の内容を読み直したときは控えを消す。絞り込みの記録は残す。「画面の編集を残す」では控えを消さない。ブラウザ版ではパスも控えも絞り込みの記録も残さない。絞り込みのファイルが壊れている、上限を超えている、または `path` が一致しないときは無視し、初期値にする。知らせは出さない。上書き保存は、ファイルが無いパスへは書けない。別名保存は書ける。控えが壊れている、またはファイルはあるが検証できないときは、その旨を出してサンプルのままにする。記録は残し、「控えを破棄」で控えを消せる。破棄するまで起動のたびに知らせる。開いているウィンドウがサンプルだけになったとき、次回はサンプルから始まる。前回のファイルを開き終わるまでは、画面のスケジュールを変更できない。取り消しとやり直しも受け付けない。開き終わったあとは変更できる。開き終わるまでにファイルが変わっていれば、開いたあと SYNC-01 と同じように読み直す。開いているあいだの編集や、外からの書き換えは止めない。2つ目のアプリを起動したときは、既存のアプリを前面に出し、新しいプロセスは起動しない。

### VIEW-01 階層

**操作** 画面を見る。

**挙動** 行はカテゴリ、グループ、タスクの3段で、JSON の配列順に並ぶ。`levels` と `outline` があるときは、定義の段数どおりの見出し行とタスク行になる。左一覧では、カテゴリ、グループ、階層の見出し、タスクの名前は、同じ列から始まる。深さは、幅の決まった細い縦線（最大4本）で示す。線は、いま一覧に出ている行の並びから決める。縦線は行の境でつながり、枝の最後の行では中央で止まる。折りたたみ、絞り込み、系統で行が消えた枝には線を出さない。並べ替えの半透明の塊も、塊の先頭を深さ0として同じ規則で線を描く。絞り込みも系統も無いときは、タスク0件のグループと、配下のタスクがすべて0件のカテゴリも行に出す。絞り込み中と系統の表示中は、条件に合うタスクが無い行は出さない。データとしては残る。左一覧の行の地は、一番上の見出し（定義の無いカテゴリと同じ）だけ別色である。タスクのすぐ上の見出しはグループ行と同じ地色である。あいだの見出しは地を塗らず太字である。1段だけのときは見出し行が無く、塗る行も無い。

**制約** タスクの並びと別グループへの移動は EDIT-15、グループの並びと別カテゴリへの移動は EDIT-17、カテゴリの並びは EDIT-16 で変えられる。

### VIEW-02 タスクバー

**操作** タイムラインのタスク行を見る。

**挙動** バーは開始日から終了日の終わりまでを塗る。終了日はその日を含む。地と枠の色は、タスクのステータスの項目の色（ライトとダークで別）である。既定の三件は、未着手が灰、進行中が薄青、完了が緑である。一覧に無い `id` は中立の灰である。進捗率が 1 以上のときは、バーの左から進捗率の幅を、枠と同じ色で濃く塗る。ステータスによらない。選択中は枠を太くする。バーが十分に長いときは、バーの中に名前と進捗率を出す。短いときや月表示では、バーの右に名前と担当を出す。

**制約** 進捗が 0 のときは帯を出さない。幅は1日より短くならない。バー内の文字は、地の色に合わせて白か暗色にする。進捗率は、バーが十分に長いときのバー内の文字にも、1 以上のときだけ出す。

### VIEW-03 親バー

**操作** カテゴリ行とグループ行を見る。

**挙動** 見えている子のうち、最も早い開始日から最も遅い終了日までのバーを、タスクバーより細い帯で出す。両端に下向きの小さな角を付ける。子が途切れている期間は点線、つながっている期間は塗りで示す。折りたたんでも親バーは残る。縦スクロールで残している行の親バーも横スクロールに追従し、ドラッグできないままである。タスクが無いグループとカテゴリには親バーを出さない。`levels` と `outline` の見出し行も、見えている子があるときは同じ親バーである。HTML と SVG の書き出しの親バーも、見えている子の期間の同じ形である。左の行では、配下のタスクを1件ずつ同じ重さで平均した整数の進捗を、名前のうしろに出す。`status` が `done` のタスクは 100 として平均する。扱いが完了の他の項目は、進捗欄の数字のままである。タスクに保存してある進捗は書き換えない。0% も出す。タスクが無い行には出さない。絞り込み、折りたたみ、系統で行に出ていないタスクも含める。グループのパーセントを平均してカテゴリにはしない。絞り込みで子が一部だけ見えているとき、見えているタスクだけを足した数字と合わないことがある。追加列の進捗には出さない。

**制約** 親バーはドラッグできない。親バーに進捗の長さや色は出さない。

### VIEW-04 マイルストン帯

**操作** 日付ヘッダーの下を見る。ひし形、またはその右の名前を主ボタンで単クリックすると、そのマイルストンだけ点線のオンオフを切り替える。左のマイルストングループ名の行を主ボタンで単クリックすると、そのグループの点線だけをまとめて切り替える。

**挙動** `milestoneGroups` の配列順に、グループごとに帯を積む。各グループの中では、マイルストンをひし形と名前で置く。確定のひし形は塗りつぶす。未確定のひし形は、中を空け、輪郭だけ同系色で残す。同じグループでひし形が重なるときだけ段を増やす。名前の長さでは段を増やさない。名前は同じ段の次のひし形の手前まで出す。手前までの幅が全角24文字分より狭ければ、そこで「…」にする。次のひし形が無く、名前が全角24文字分より長いときも「…」にする。カーソルを乗せているあいだは、切り詰めた名前の位置に全文を重ねる。全文がチャートの右端を越えるときは左へ寄せ、チャートの幅で折り返す。ウィンドウの高さに収まらないときは、入る行まで出して末尾を「…」にする。段の高さは変えない。右端までスクロールしたときに、出している文字が途中で切れないよう、帯に出ている名前と右端の年月ラベルが収まるまで期間の右を延ばす。段は横スクロールでは変わらない。日・週・月の切り替えで1日の幅が変わると、重なりが変わり、段も変わる。マイルストンが無ければ帯の高さは 0 である。空のグループは線を出さない。

点線は、最初はどのマイルストンもオフである。オンにしたマイルストンだけ、ひし形の中心から帯の下端まで、およびチャート本体の上端から下端まで、同じ日付の位置に縦の点線を出す。同じ日で複数オンにしても、縦線は同じ位置に重なる。下線は、縦線と同じ点線を一本、ひし形の左端から、帯に出している名前の右端まで引く。名前が「…」のときは、その「…」の右端までである。ホバーで出している全文には下線を引かない。名前が無いときは、ひし形の幅だけである。段の高さは増やさない。今日の位置の縦線とイナズマ線の意味は変えない。

左のグループ名の単クリックでは、そのグループのマイルストンだけを見る。全部オフなら、そのグループを全部オンにする。一つでもオンなら、そのグループを全部オフにする。ひし形の単クリックで一部だけ変えたあとも同じである。他のグループのオンオフは変えない。

**制約** 左には、見えているグループごとに、そのグループ名と段の高さに合わせた行を出す。点線のオンオフは画面だけに持ち、スケジュール JSON には書かない。起動し直すとオフである。帯に出ていないマイルストンからは点線を出さない。ダブルクリックの編集と、日付の横ドラッグではオンオフを変えない。オンのまま日付を動かしたとき、点線は動いたあとの日付についてくる。左のグループ名の単クリックでは帯の表示は変えない。右クリックは FILTER-11 の帯の線のままである。帯を隠して左の名前が出ていないグループでは、グループ名の単クリックはできない。

**制約** 進捗率では判定しない。

### VIEW-07 イナズマ線

**操作** チャート上の本日の線を見る。

**挙動** 基準はパソコンの今日の日付で、日付が変わると更新する。行の中央で折れる。折れ位置は、項目の扱いと開始日・終了日・今日から決める。進捗率は見ない。終了日が今日の行は、開始日から終了日まで（終了日当日を含む）の期間に入れ、終了日よりあとの列へは折れない。色は橙色で、太さ 1.5px、不透明度 0.55 である。設定で非表示にできる。HTML と SVG の書き出しも同じ太さと不透明度を使い、非表示のときは線を出さない。

期間は次の三つである。今日が開始日より前、開始日から終了日まで（終了日当日を含む）、終了日が今日より前。

| 扱い | 今日が開始日より前 | 開始日から終了日まで（終了日当日を含む） | 終了日が今日より前 |
| --- | --- | --- | --- |
| 未着手 | 今日 | 開始日 | 終了日 |
| 着手済み | 開始日 | 今日 | 終了日 |
| 完了 | 終了日 | 終了日 | 今日 |
| 管理外 | 今日 | 今日 | 今日 |

期限超過の赤は、未着手と着手済みで、終了日が今日より前のときだけ付ける（VIEW-05）。完了と管理外は、終了日が過去でも赤くしない。

**制約** 一覧に無い `id` は、どの期間でも今日に置く。管理外と同じである。終了日が過去でも赤くしない。

### VIEW-08 前後の線

**操作** 先行と後続が両方見えているタスクを見る。

**挙動** 先行から後続へ矢印を引く。間隔があるときは先行の右端から右へ出て縦に折れ、後続の左端へ入る。終了と開始が近く、右へ出る余地が矢印の頭より狭いときは、先行バーの外側を回ってから、後続の左端の手前で右を向いて入る。頭は後続バーの外に残る。後続の開始が先行の終了より前なら赤く太くする。同じ日に始まる線は赤くしない。フィルタや折りたたみでどちらかが見えなければ線は出さない。線を引くモードの追随する線は、確定した矢印ではない。バーの移動または端のドラッグのあいだは、そのタスクが端になる線だけ、離したときに入る日付で色を追従させ、線はそのバーの見た目の位置に付いてくる。他のタスクの線の色と位置は変えない。絞り込みで見えている行は、離して確定するまで変えない。

**制約** 「前後: 破綻のみ」のときは、破綻している線だけを描く。追随する線は破綻の赤にしない。

### VIEW-15 前後ではない繋がりの線

**操作** [examples/connections/schedule.json](../examples/connections/schedule.json) を開く。塗った行の上を通る円弧は、デスクトップ版で [examples/connections/workspace.json](../examples/connections/workspace.json) を開く。両方のタスク行が見えている状態でチャートを見る。

**挙動** 終わってから始まる線（VIEW-08）とは別の色と太さで、2つのタスクバーの上端の中央を、上へふくらむ緩い円弧で結ぶ。矢印は付けない。円弧とその上の短い言葉は、完了バーの緑とは別の色相（空の青）である。円弧の下には、チャートの地色と同じ細い縁を敷き、棒の端に接しても線が棒の続きに見えないようにする。円弧の上に、その2つのあいだの関係を示す短い言葉を出す。言葉の既定位置は、円弧のてっぺんの少し上である。棒の中の名前、棒の右の担当、すでに置いた別の繋がりの言葉と重なるときだけ、上、左、右の順で近くの位置を見る。4か所とも重なるときは、既定の位置のまま出す。上へずらすとチャート本体の上端より上に出る候補は使わない。棒の名前と担当は動かさない。2つの行のあいだに別の棒があるとき、円弧はその棒の上を通る。ふくらみは、そのズームの1週間分の横幅を超えない。折りたたみや絞り込みでどちらかの行が見えなければ出さない。日が前後と合わなくても描く。赤くしない。「前後: 破綻のみ」でも消さない。バーをドラッグしているあいだは、端だけそのバーの見た目に付く。色は変えない。円弧の左クリックでは選択も詳細も開かない。ポインタを円弧の上に乗せると、線を少し強調する。付け外しと言葉の編集は EDIT-23 である。

**制約** Excel、HTML、SVG の書き出しには出さない。タスクを消すと、そのタスクを含む繋がりだけ JSON から外れる。残ったタスク同士を自動ではつなぎ直さない。

### VIEW-09 非稼働日

**挙動** 非稼働日を薄い灰色で塗る。カレンダー未設定なら土日、設定済みなら [データ仕様](data-format.md#稼働日カレンダー-jsonschemaversion-1) の判定に従う。HTML と SVG の書き出しも同じである。

**制約** 月表示では日ごとに塗らない。バーの移動と期間は暦日のままである。

### VIEW-10 担当の表示

**操作** タスク行の右側を見る。

**挙動** 左の一覧では、解決できたメンバーは表示名を「、」でつないだ1つの文字列で出す。同じ表示名が複数のメンバーにあるときだけ、その位置に ID を添える。並びの id がすべてカタログに無いときだけ、従来どおり紫の「メンバー不明」札にする。解決できた人が1人でもいるときは、不明 id も同じ文字列に含め、札は付けない。一人だけのときは従来どおり、名前が付いた担当は薄い文字のままで、札は付けない。割り当てなしは担当欄に「未割当」と出し、琥珀色の札にする。文字色と地色は配色の未割当用の色を使う。角丸、余白、太字はメンバー不明の札と同じである。担当列は見えている文字列の先頭8文字まで表示し、超えた分は隠す。マウスを乗せると全文が出る。札の余白を含め、「未割当」は担当列の幅で切れない。選択中の行と、カーソルを乗せた行でも、札の地色は残す。行左端の細い琥珀色の線は残す。チャートのバーでは担当はバーの右の文字で示し、切らず、マウスを乗せても全文は出さない。割り当てなしの破線や上端の色は出さない。期限超過のタスク名は赤のままである。担当欄の「未割当」は赤にしない。HTML と SVG の書き出しも、画面と同じ文字列と札にする。ライトとダークで同じである。

**制約** 使用中カタログが無いとき、ID がある担当はすべてメンバー不明になる。

**操作** タスク行の左のノートアイコンを見る。

**挙動** ノートがあるタスクと無いタスクで色を分ける。押すとノートの全文をダイアログで開く。行の選択は変わらない。空のときは「ノートはありません」と出す。

**制約** ノート本文は行に常時出さない。

### VIEW-12 確度

**操作** タスクのバーと、左のタスク行と、マイルストンのひし形を見る。

**挙動** 確定のバーはベタ塗りである。未確定のバーは、同じステータス色の地に斜線を重ねる。斜線は、ライトでは地より濃く、ダークでは地より明るく、地の色が残る間隔である。左の一覧では「未確定」は出さない。マイルストンの「超過」があるときは一覧に「超過」を出す。確定のマイルストンはひし形を塗りつぶす。未確定のマイルストンは、中を空け、輪郭だけ同系色で残す。HTML と SVG の書き出しも、マイルストンのひし形は画面と同じである。タスクバーの斜線は今までどおりである。

**制約** 枠の線種、上端の色、進捗の濃い帯、期限超過の赤は変えない。進捗の濃い帯は斜線の上にベタで描く。親バーと前後の線は、タスクの確度では変えない。マイルストンのひし形は、そのマイルストン自身の確度で変える。確度は着手や進捗とは独立である。

### VIEW-13 一覧に無いステータスと担当と追加項目

**操作** チャートの上端の帯と、設定の「表示」で出した左一覧のステータス列を見る。

**挙動** 文書のすべてのタスクを見て、使用中のステータス一覧に無い `status`、担当の id の並びに使用中のメンバー一覧に無い id がある（`assigneeId` が一人の文字列でも複数 id の配列でも、並びの各 id を見る）、使用中の色の一覧に無い `colorId` がある、または使用中の拡張項目の定義に無い `fieldValues` のキーがあるとき、チャート領域の上端に帯を出す。ある種類だけを順に書き、「一覧に無いステータス」「一覧に無い担当」「一覧に無い色」「一覧に無い追加項目」を「と」でつなぎ、末尾に「があります。」を付ける。色の一覧のパスが無いときは、`colorId` があっても色の不一致は帯に出さない。`id` も件数も書かない。定義に無いキーの値は書き換えない。列を出すよう促す文も、列が隠れているという文も書かない。帯の地と文字は、一覧に無いステータスの札と同じ配色である。帯は秒数で消さず、不一致が無くなるまで残す。線を引くモードの帯より上に置く。右下の一時的な知らせとは別である。スケジュールの値は書き換えない。帯が出ているあいだ、左一覧の上端は帯の高さだけ空き、タスク行とバー、左の見出しと日付見出しの下端が揃う。帯が消えると空きも消える。

左一覧のステータス列は、開始や進捗と同じく設定で出したり隠したりできる。初期は隠す。一覧にある `id` は表示名を出す。無い `id` は、メンバー不明と同じ配色の札で `id` だけを出す。角はメンバー不明のカプセルより小さくする。表示名と `id` が列の幅を超えるときは省略し、マウスを乗せると全文が出る。カテゴリ行、グループ行、マイルストンの行には出さない。列に出るのは、絞り込みなどで行に出ているタスクだけである。割り当てなしは知らせの対象にしない。

**制約** バーの色でずれを表さない。不一致があるあいだ、ステータス列を自動では出さない。絞り込みを変えずに、隠れている行を一覧に出さない。確度と、マイルストンの参照切れは対象にしない。色の一覧が無いときは、色の不一致も帯に出さない。

### VIEW-14 色の一覧で行の地

**操作** 設定の「色」で一覧 JSON を取り込み、選ぶ。設定ファイルで `colors` のパスを読んだウィンドウでも、左のタスク行とチャートの行の地を見る。ライトとダークを切り替える。HTML、SVG、Excel に書き出す。

**挙動** ユーザ設定では、選んだ色の一覧 JSON をアプリデータから読む。設定ファイルでは、`colors` が指す一覧 JSON を、そのウィンドウだけで読む。読めた一覧に `colorId` があるタスクは、左一覧の行の地と、チャートの同じ行の地を、ライトでは `color.light.bg`、ダークでは `color.dark.bg` で塗る。チャートでは格子と非稼働日の灰色より手前に塗り、選択とホバーの地はその上に残す。`colorId` が無いタスク、見出し、マイルストンの行、一覧に無い `colorId` のタスクは、今の行の地のままである。タスクバーとマイルストンの色は、ステータス一覧の色のままである。HTML と SVG のタスク行の地は、書き出した時点のライトまたはダークに合わせ、画面と同じ色に揃える。Excel のタスク行の地は、画面の配色にかかわらず `color.light.bg` に揃える。Excel では左の列と稼働日の日付セルを塗り、非稼働日は灰色のままである。

**制約** 組み込みの色の一覧は置かない。未選択のとき、設定ファイルに `colors` が無いとき、読み込みに失敗したときは行の地を塗らない。使用中の一覧があるウィンドウでは、詳細・一括・複製に「色」を出す。一覧が無いウィンドウでは出さない。色の一覧は 1 件以上 8 件までである。読み込みに失敗したときは状態バーに「色の一覧を読み込めませんでした。」を出し、設定は開かない。塗らない。タスクの `colorId` は残す。

### NAV-01 スクロール

**操作** チャートをドラッグする。チャート本体か左の一覧の上で、ホイールまたは Shift+ホイールを回す。タッチパッドの二本指で縦横に滑らせる。⌘ または Ctrl を押しながら矢印キーを押す。

**挙動** 修飾キーを押さないドラッグは、縦横にスクロールする。チャート本体と左の一覧の上では、ホイールの縦の量で上下に、横の量で左右に動く。斜めに滑らせたときは、縦と横が一緒に動く。大きい方の軸だけを残す処理は入れない。チャート本体と左の一覧の上で Shift+ホイールを回すときは、縦の量を左右に使う。ブラウザが Shift で軸を入れ替え、横の量だけを載せるときは、その横の量を一度だけ使う。縦の量と横の量が同じときも一度だけ使う。縦の量があり、横の量と違うときは、縦の量だけを左右に使う。左の一覧の上で Ctrl または ⌘ とホイールを回すと、チャートの左端の日付を保って NAV-02 と同じ倍率になる。Ctrl または ⌘ を押したホイールとピンチは、横の量では拡大せず、スクロールもしない。日付ヘッダーとマイルストン帯の上では、ホイールの縦の量と横の量の両方で左右に動く。両方あるときは足す。Shift で軸が入れ替わっているときは、一度だけ足す。Shift で軸が入れ替わっていないときは、縦の量と横の量が違っても足す。上下には動かない。⌘ または Ctrl と矢印では、上で縦に戻り、下で縦に進む。左で日付を過去へ、右で未来へ動かす。縦は左の一覧とチャートが一緒に動く。上下は 1 行分、左右はその行と同じ画面上の距離だけ動く。キーを押しているあいだは連続して動く。端では止まる。右クリックメニューが開いていれば閉じる。日付ヘッダーとマイルストン帯は、その上に固定されたままである。縦にスクロールしたとき、展開していて配下がまだ下に残っているカテゴリ行とグループ行は、その下に最大2行残る。残すのはカテゴリ1行とグループ1行で、表示サイズで行の高さが変わっても同じである。`levels` と `outline` の見出し行では、見ている枝の展開した祖先を、浅い方から段の数だけ残す。見出しは最大4行である。左の名前とチャートの行は一緒に残し、残した見出しにも、見えている子があるときは親バーを出す。見た目は通常のカテゴリ行・グループ行・見出し行のままで、固定用の装飾は足さない。同じ行は二重に出さない。一覧が画面に収まるときは残さない。固定段はタスクに重ならない。折りたたんだカテゴリ、グループ、見出しは残さない。その行自身は通常どおり上へ流れる。絞り込みと系統で省いた行は対象にしない。次の見出しが上端へ来るときは入れ替わる。前後の線、イナズマ線、残していない行のバーは固定段の下で切れ、固定段の上には描かない。固定段の上の操作はそのカテゴリ行、グループ行、見出し行に当たる。折りたたみ、右クリックの「名前を変更」、切れた名前の全文は、固定中の行にマウスを乗せても出る。カテゴリ行の並べ替えは、固定中の行の握りからも始められる。グループ行の並べ替えも、固定中の行の握りから始められる。追加や複製でタスクを見える位置へ寄せるときは、固定段の下にタスクが出る位置までスクロールする。デスクトップ版とブラウザ版で同じである。

**制約** タスクバーの上では、修飾キーの無いドラッグは移動か期間変更になる。空いた所、スペースキーを押したドラッグ、中ボタンのドラッグはスクロールのままである。スペースキー単体は、フォーカスが `body` かチャート本体にあるときだけスクロール用に取り、ボタンにフォーカスがあるときはボタンの既定の動作に渡す。移動と期間変更は 8px を超えてから始まり、離す前の Escape で取り消せる。Escape ではドラッグを止めて形を戻し、離したときの確定や取り消し履歴には積まない。3px 未満の動きはスクロールとみなさない。修飾キーの無い ↑↓ はタスクの選択を移し、Alt+←→ は開始日と終了日を、Shift+Alt+←→ は終了日だけを 1 日ずらす。検索欄、入力欄、選択欄、ボタン、ダイアログではこれらの矢印はその欄の操作のままである。それ以外の修飾キーの無い矢印キーではチャートを動かさない。Shift または Alt を一緒に押しているときは、矢印では動かさない。検索欄、選択欄、ボタンにフォーカスがあっても、⌘ または Ctrl と矢印はチャートを動かす。ダイアログが開いているあいだは動かない。Mac では Ctrl+矢印が OS に取られて届かないことがある。届いた ⌘ または Ctrl は同じ動きにする。スケジュールのデータ、取り消し履歴、選択、絞り込みは変わらない。⌘ または Ctrl と矢印は、ドラッグやホイールの代わりにはならない。線を引くモードのあいだは、タスクバーの移動、期間変更、マイルストンの日付変更はしない。空き、親バー、背景を 3px 以上ドラッグすると、線を引いていないときの空白ドラッグと同じスクロールになる。タスクバーでは 8px 以上ドラッグしたときも同じスクロールになる。8px 未満で同じバーの上で離したときだけ、今どおりそのタスクを後続にする。8px 未満で空きや別のバーで離したときは、線もスクロールも起きない。スクロールになったドラッグは、離した場所がタスクバーでも線を足さない。スペースキーを押したドラッグと中ボタンのドラッグも、モード中はスクロールする。スペースキーを押したまま 3px 未満で同じバーの上で離したときは、今どおりそのタスクを後続にする。中ボタンでは線を足さない。3px 未満の動きはスクロールとみなさない。ホイールの縦と横、Shift+ホイール、⌘ または Ctrl と矢印は、モード中もスクロールする。スクロールしてもモードは残り、追随する線も動く。ドラッグがスクロールになっているあいだは、カーソルを閉じた手にする。スクロールのドラッグ中にポインタがチャートの外へ出ても、追随する線の終点は消えない。ドラッグ中の Escape は線を引くモードを終え、閉じた手も消す。動いたビューは戻さない。ダブルクリックの 2 回目では線を足さない。OS やタッチパッドが横スクロールのイベントを出さない機種では、アプリ側では横に動かせない。そのときは、チャートの空白をドラッグするか、Shift を押しながらホイールを回す。

### NAV-02 ズームと日・週・月の切り替え

**操作** チャート本体か左の一覧の上で、Ctrl または ⌘ を押しながらホイールを回す。ツールバーの「日」「週」「月」を押す。「今日」を押す。

**挙動** ホイールは、マウスポインタの位置を基準に、1日あたりの幅を約1.15倍ずつ変える。左の一覧の上では、チャートの左端の日付を保つ。「日」は 40px、「週」は 22px、「月」は 8px に幅を決め、チャートの中央を基準に変える。幅に応じて見出しの表示単位は、40px 以上なら日表示、10px 以上 40px 未満なら週表示、それ未満なら月表示になる。月表示では、見えている左端の日が属する月をチャート左端に固定し、各月の1日の位置にも同じ形式の月ラベルを出す。上下で字が重なるので、横に重なる月ラベルだけを出さない。左端の固定ラベルと、すでに出すと決めた手前の月ラベルの右に、表示サイズに合わせた 4px の隙間を空けて収まる月だけ文字を出す。収まらない月は文字を出さず、月の区切り線は残す。文字は途中で切らない。日表示と週表示の見出しは今までどおりである。「今日」は、縦位置と選択は変えず、横スクロールだけを今日の日付が見える位置へ寄せる。今日が期間の外なら、端で止める。

**制約** 幅は 3px 以上 90px 以下。既定は 22px で週表示になる。このズームは、設定の表示サイズとは別である。

### NAV-03 Fit

**操作** 「全体」を押す。

**挙動** 表示中の全期間がチャート幅に入るよう1日あたりの幅を決め、横位置を先頭に戻す。ファイルを開いた直後の Fit は FILE-01 と同じで、これに加えて一覧の縦位置も先頭へ戻す。

**制約** 幅の上下限は NAV-02 と同じである。下限に当たると、全期間が入り切らないことがある。

### NAV-07 コマンドパレット

**操作** ⌘ または Ctrl と K を押す。欄に文字を入れて候補を絞り、↑↓ で選び、Enter で実行する。

**挙動** 開く、保存、別名保存、検索へ移る、タイトルを変更、差分を表示、差分をコピー、JSON を表示、書き出し、設定、更新を確認、操作の案内、ショートカット一覧、今日、日・週・月・全体、取り消し、やり直し、表示サイズの拡大と縮小、選択中タスクの編集、削除、線を引く、ノート、系統、タスクを追加、マイルストンを追加、タスクを複製を候補に出す。デスクトップ版で履歴があるときは、「開く」の次に FILE-09 の各ファイル（「最近開いたファイル」にメニューと同じ文言を続ける）と「履歴を消す」を出す。デスクトップ版だけ「更新を確認」を出す。並べ替えは出さない。ファイル操作の途中や、選択が無い操作は、候補を残したまま押せない。「履歴を消す」はファイルを開かないので、その途中でも押せる。同じ ⌘/Ctrl+K と Escape で閉じる。

**制約** ほかのダイアログが開いているあいだは開かない。検索欄や入力欄にフォーカスがあっても開ける。コマンドパレットの中では、キー操作はパレットが受け取り、ほかのショートカットは効かない。

### NAV-08 操作の案内

**操作** 上段の「案内」、☰ の「操作の案内」、コマンドパレットの「操作の案内」、macOS の表示メニューの「操作の案内」を押す。ダイアログ内の「ショートカット一覧」で、案内を閉じてショートカット一覧を開く。Escape または「閉じる」で閉じる。

**挙動** 見出し「スケジュールの作り方」「画面」「タグ」「気づきにくい操作」「色と線」に分け、入口と気づきにくい操作とタグの使い方と色の意味を短い文で示す。内容は [操作マニュアル](user-manual.md) の全文ではなく、案内用に要約した文である。起動時には出さない。見たかどうかの記録は持たない。

**制約** ? キーと F1 はショートカット一覧のままである。ブラウザ版では、外部ファイルの反映と自動更新に関する文を出さない。デスクトップ版では出す。案内とショートカット一覧は重ねない。

### NAV-04 折りたたみ

**操作** カテゴリまたはグループの左の三角を押す。

**挙動** 配下の行を隠す。もう一度押すと戻す。畳んでもその行と親バーは残る。追加したタスクのカテゴリとグループは、追加時に展開する。

**制約** 折りたたみは取り消し履歴に入らない。☰ の「開く」と「新しいウィンドウで開く」ではすべて展開に戻る。次回起動で前回のファイルを開き直したときは、絞り込みの記録と一緒に戻る。

### NAV-05 切れた名前

**操作** 左の名前が幅に収まらないとき、その名前にマウスを乗せる。

**挙動** 全文が出る。名前をドラッグしても、名前は動かない。データは変わらない。

**制約** 収まっている名前には全文を出さない。担当、追加列、「超過」は動かない。

### NAV-06 左一覧の幅

**操作** 左の一覧とチャートの境界を横にドラッグする。境界をダブルクリックするか、境界にフォーカスして左右キーを押しても変えられる。⌘ または Ctrl を押した左右キーでは変えない。

**挙動** 一覧の幅が変わり、チャートは残った幅に合わせて縮む。幅は表示倍率に比例し、表示倍率 1 のときの既定は 260px である。離した幅は localStorage に残り、次の起動でも使う。ダブルクリックは既定に戻し、保存した幅を消す。左右キーは、見えている幅を基準に、基準幅を 8 ずつ動かす。⌘ または Ctrl が付いているときは幅を変えず、NAV-01 のとおり横にスクロールする。そこに Shift または Alt も一緒のときは、幅もスクロールも変えない。ドラッグも左右キーも、表示幅が変わらないときは覚えている幅を変えない。ウィンドウを狭めてチャートが 200px を下回りそうなときは、その場の表示だけ縮め、覚えている幅は残す。広げ直すと、その幅に戻る。

**制約** 利用者が指定する基準幅は 140 未満にしない。チャート側は 200px 未満にしない。スケジュールのデータと取り消し履歴は変わらない。切れた名前の全文は、名前にマウスを乗せたときに出る。書き出しのラベル幅は、画面の一覧幅とは別に、名前が収まる長さで決める。

### FILTER-01 タスク名

**操作** 検索欄の対象を「名前」にし、文字を入れる。⌘/Ctrl+F で検索欄へ移し、入っている文字を選択する。対象が「名前」のときだけ、⌘/Ctrl+F は名前の欄へ移る。

**挙動** 名前にその文字を含むタスクだけを残す。前後の空白は除いて比べる。

**制約** 大文字小文字は区別する。絞り込みを変えると選択は外れる。

### FILTER-02 ノート

**操作** 検索欄の対象を「ノート」にし、文字を入れる。

**挙動** ノートにその文字を含むタスクだけを残す。ノートが無いタスク、空白だけのノートは残さない。タスク名の検索と併用したときは、両方を満たすタスクだけが残る。

**制約** 絞り込みを変えると選択は外れる。

### FILTER-03 担当者

**操作** 「絞り込み」パネルの「担当者」で「すべて」「割り当てなし」、またはメンバーを選ぶ。

**挙動** 「割り当てなし」は、担当が空のタスクと、並びの id がすべてカタログに無いタスクだけを残す。解決できたメンバーが1人でもいるタスクは残さない。特定のメンバーは、その id が並びに含まれるタスクを残し、メンバー不明だけのタスクは出さない。カタログが変わり、選んでいた ID が消えると「すべて」に戻る。

**制約** 絞り込みを変えると選択は外れる。

### FILTER-04 ステータス

**操作** 「絞り込み」パネルの「ステータス」で「すべて」「完了以外」と、使用中のステータス一覧の項目（一覧の並び順）を選ぶ。

**挙動** 「完了以外」は、扱いが完了の項目を除いて残す。管理外と一覧に無い `id` のタスクは残る。項目を選ぶと、その `id` のタスクだけを残す。以前に保存した `not-started`、`in-progress`、`done`、`not-done` の値は、そのまま読む。使用中の一覧に無い `id` で絞っていたときは、一覧を読み終えたあとで「すべて」に戻す。

**制約** タスクが持つ `id` が一覧に無いときも、「すべて」と「完了以外」では出る。一覧に無い `id` の選択肢は、そのタスクを詳細パネルで開いている間だけ、その `id` のまま出す。

**制約** 絞り込みを変えると選択は外れる。

### FILTER-05 期限

**操作** 「絞り込み」パネルの「期限」で「すべて」か「期限超過」を選ぶ。

**挙動** 「期限超過」は VIEW-05 のタスクだけを残す。

**制約** 絞り込みを変えると選択は外れる。

### FILTER-06 前後

**操作** 「絞り込み」パネルの「前後」で「すべて」か「破綻のみ」を選ぶ。

**挙動** 「前後: 破綻のみ」は、破綻している線の両端のタスクだけを残す。線の見た目は VIEW-08 に従う。

**制約** 絞り込みを変えると選択は外れる。

### FILTER-07 マイルストン

**操作** 「絞り込み」パネルの「マイルストン」欄に文字を入れて候補を絞り、一覧から「すべて」「なし」、またはマイルストンを選ぶ。閉じた欄は「すべて」「なし」、または「名前（日付）」を出す。検索語が空のときだけ、先頭に「すべて」と「なし」が出る。そのあとのマイルストンは配列の順で、帯の線がオフのグループも含める。候補は名前か日付の一部で絞り、比べる前に前後の空白を除く。大文字小文字は区別する。一度に50件まで出す。多いときは「さらに絞り込んでください」が一覧の外に出る。一覧をスクロールしなくても見える。一致が無いときは「一致するマイルストンがありません」を一覧の外に出す。候補が無いときは空の一覧は出さない。文字を入れただけでは絞り込みは変わらない。行を選んだときだけ条件が変わり、一覧は閉じる。パネルは開いたままである。今の条件と同じ行を選び直したときは、絞り込みも選択も変えない。一覧が開いた直後の強調は、今の条件の行である。見えないときは一覧の表示矩形ではみ出した分だけスクロールする。長い名前は候補のボタンだけ折り返す。焦点があるあいだ、閉じた表示は全文選択である。Escape で一覧を閉じたあとも、次の文字は閉じた表示を置き換えて検索を始める。一覧が開いているときの Escape は一覧だけを閉じ、もう一度の Escape でパネルを閉じる。変換中の Enter と矢印は、一覧が扱わない。

**挙動** 「なし」は対応マイルストンが無いタスクだけを残す。特定のマイルストンは、それを指すタスクだけを残す。選んでいたマイルストンが消えると「すべて」に戻る。

**制約** 絞り込みの値が変わったときは選択が外れる。同じ値を選び直したときは選ばない。

### FILTER-11 マイルストン帯の線

**操作** 「絞り込み」パネルの「帯の線」で、マイルストングループごとに表示のオンオフを切り替える。左のマイルストングループ名の行を右クリックしても切り替えられる。

**挙動** オフにしたグループの線は、帯と書き出しの両方から消える。書き出しの期間の端にも、そのグループの日付は使わない。タスク一覧の絞り込み（FILTER-07）と、タスク行の超過は変えない。初期は全部オンである。消えたグループの選択は捨て、新しいグループはオンである。「すべて解除」では、帯の線も全部オンに戻す。系統は外さない。左のマイルストングループ名の行を主ボタンで単クリックしても、帯の線は変えない。

**制約** 取り消し履歴には入らない。1つでもオフがあれば、絞り込みの条件数に数える。

### FILTER-08 系統

**操作** タスクを選んで「系統」を押す。もう一度押すと解除する。右のプルダウンで「繋がりも辿る」を選べる。右クリックメニューの「系統を表示」は、そのタスクを起点にする。すでにそのタスクが起点なら「系統を解除」になる。

**挙動** 起点から先行と後続をたどれるところまでたどり、そのタスクだけを残す。起点を通らない枝は含めない。主ボタンは前後だけを辿る。「繋がりも辿る」では、たどったタスクの繋がりの相手を足し、その相手からも同じ前後の辿りを届くところまで繰り返す。繋がりも辿っているあいだは、主ボタンを押すと系統を全部外す。前後だけに戻すには、外したあとでもう一度主ボタンを押す。右クリックの「系統を表示」は前後だけである。別のタスクへ起点を移すとき、繋がりも辿る状態は持ち越さない。ボタンには起点の名前を出す。効いているときは、絞り込みの札に「系統: 名前」を出す。繋がりも辿っているときは「系統: 名前（繋がりも）」である。札を押すと解除する。別のタスクが起点のときに「系統を表示」を選ぶと、起点をそのタスクへ切り替える。起点が同じで前後だけの系統が付いているときに「繋がりも辿る」を選ぶと、起点は動かさず繋がりも辿る方へ切り替える。ツールバーの「系統」は、起点があるあいだは解除だけをする。タスクを追加したとき、または起点のタスクを削除したときは解除する。

**制約** タスクを1件だけ選んでいるときだけ「繋がりも辿る」のプルダウンを押せる。タスクを選んでいないときは主ボタンも押せない。絞り込みを変えても系統自体は外れないが、選択は外れる。系統は取り消し履歴に入らない。

### FILTER-09 組み合わせと空のグループの省略

**操作** 複数の絞り込みと折りたたみ、系統を同時に使う。

**挙動** タスクはすべての条件を満たすものだけが残る。絞り込みも系統も無いとき以外は、残ったタスクが無いグループとカテゴリは行から省く。折りたたみは、残った行をさらに隠す。前後の線は、両端が行として見えているときだけ描く。

**制約** 省いたグループとカテゴリはデータに残り、追加ダイアログでは選べる。絞り込みも系統も無いときは、空のグループとカテゴリも行に出す。

### FILTER-10 確度

**操作** 「絞り込み」パネルの「確度」で「すべて」「未確定」「確定」を選ぶ。

**挙動** 「未確定」は `tentative` だけを残す。「確定」は `committed` だけを残す。

**制約** 絞り込みを変えると選択は外れる。ステータスや進捗では判定しない。

### FILTER-12 タグ

**操作** 「絞り込み」パネルの「タグ」欄に文字を入れ、出た候補をチェックでオンオフする。入力が空のときも、ファイルにあるタグをすべて候補に出す。候補をオンにしても一覧は閉じない。この欄から新しいタグは作らない。ファイルにタグが無いときは入力欄を出さず「タグはありません」と出す。タグを一つ以上選んでいるときは、見出し「タグ」の横に「選択を外す」を出す。押すと、選んでいるタグだけを空にする。

**挙動** 一つもオンにしていないときは、タグでは絞らない。タグの付いていないタスクも残る。一つ以上オンのときは、そのどれかを持つタスクだけが残る。タグどうしだけが OR である。ほかの絞り込み条件は、今までどおり全部満たすタスクだけが残る。候補の並びは、文書を前から見てタグが初めて出た順である。札も同じ順である。候補の絞り込みは、タスク名の検索と同じく、前後の空白を除き、大文字と小文字を区別して名前にその文字を含むタグだけを出す。一致が無いときは「該当するタグはありません」と出す。候補は欄の下に重ねて出す。絞り込みパネルの高さはタグの件数で変えない。候補が多いときスクロールするのは、その候補一覧だけである。パネルを閉じたあとも、選んだタグは絞り込みの札に出す。タグごとに札を一枚出す。札を押すと、そのタグだけ外れる。パネルの中には、選んだタグの札を出さない。絞り込みボタンに出す数は、タグを一つ以上選んでいるとき 1 と数える。札の枚数では数えない。ファイルから消えたタグは、選択から外す。ほかに選んだタグがあれば、その選択は維持する。選んだタグが残らなければ、タグでは絞らない。タスクを追加したとき、選んでいるタグがそのタスクに一つも無いなら、タグの選択は全部外す。複製はタグを写す。元のタスクが条件に合うなら、複製も残り、選択は残る。

**制約** 絞り込みを変えると選択は外れる。タグの絞り込みは取り消し履歴に入らない。ファイルを開くとタグの選択は無くなる。取り消しでは戻らない。「すべて解除」は、選んだタグもほかの絞り込みも外す。系統は残す。「選択を外す」は、タグの選択だけを空にする。担当者、ステータス、確度、期限、前後、マイルストン、帯の線、タスク名とノートの検索、系統は残す。欄の検索文字とパネルは残す。取り消し履歴には入らない。ファイルにタグが無いときと、タグを一つも選んでいないときは出さない。

### FILTER-13 追加項目

**操作** 使用中の拡張項目の定義があるときだけ、「絞り込み」パネルの担当者から帯の線までの欄の下に「追加項目」を出す。「項目名で検索」欄に文字を入れ、出た候補を選ぶと、その項目の条件行が出る。候補の絞り込みは、タスク名の検索と同じく、前後の空白を除き、大文字と小文字を区別して名前にその文字を含む項目だけを出す。入力が空のときは定義の順にすべての候補を出す。すでに条件行を出している項目は候補に出さない。一致が無いときは「該当する項目はありません」と出す。候補は欄の下に重ねて出す。絞り込みパネルの高さは定義の件数で変えない。候補が多いときスクロールするのは、その候補一覧だけである。条件行では、文章は「含む」、数値は「以上」「以下」、日付は「から」「まで」、候補は「一致」のプルダウンで選ぶ。各行に「値が無い」を置き、「指定しない」「残す」「除く」から選ぶ。初期は「指定しない」である。行の「外す」または見出し横の「選択を外す」で、その項目の条件行を消す。「選択を外す」は追加項目の条件行だけを消し、担当者やタグなどほかの絞り込みは残す。行が1件以上あるときだけ「選択を外す」を出す。パネルを閉じて開き直したとき、開いている条件行は効いている項目だけである。候補から足したあと、値の条件が空で「値が無い」が「指定しない」の行は、絞り込みに使わない。「項目名で検索」を空にしただけでは行は残る。値の条件を空に戻したあとも、パネルを開いているあいだは行は残る。

**挙動** 値の条件が空で「値が無い」が「指定しない」の行は、絞り込みに使わない。文章は前後の空白を除いた文字を含むタスクだけを残す。大文字と小文字は区別する。数値は下限と上限を含む範囲である。片方だけでも効く。パーセント表示の項目も、保存されている数値のまま比べる。日付は開始と終了を含む期間である。片方だけでも効く。開始が終了より後のときは、合うタスクは無い。候補は選んだ文言と一致するタスクだけを残す。「値が無い」は、そのキーが `fieldValues` に無いタスクである。値の条件があり「指定しない」または「除く」のときは、合うタスクだけが残る。値の条件があり「残す」のときは、合うタスクと値が無いタスクが残る。値の条件が無く「残す」のときは、値が無いタスクだけが残る。値の条件が無く「除く」のときは、値があるタスクだけが残る。ほかの絞り込みとは、すべて満たすタスクだけが残る。効いている項目ごとに札を1枚出す。絞り込みボタンの数は、効いている項目を1件ずつ数える。札を押すと、その項目だけ初期に戻す。「すべて解除」は追加項目の条件も外し、系統は残す。タスクを足したとき、そのタスクが隠れる追加項目の条件だけを外す。定義から消えたキーは、絞り込みの記録を戻すときに外す。ファイルに定義が無いときは条件を出さず、記録に残っていても絞らない。

**制約** 絞り込みを変えると選択は外れる。追加項目の絞り込みは取り消し履歴に入らない。左一覧の列にはしない。

### EDIT-01 選択

**操作** タスクバーまたは左のタスク行の握り以外をクリックする。背景を左クリックすると解除する。Shift+クリックは、直前に選んだタスクからクリックしたタスクまで、見えているタスクを選択に含める。選択が無いときは、その1件を選ぶ。⌘（Mac）または Ctrl（Windows と Linux）+クリックは、その1件を選択へ入れたり外したりする。Mac の Ctrl+クリックは右クリックのままである。↑↓ は、見えている隣の1件へ選択を移す。Shift+↑↓ は、その方向へ選択を伸ばす。タスク行の握り以外、またはバーを右クリックすると、そのタスクを選択する。右クリックしたタスクがすでに選択に入っていれば、選択は維持する。入っていなければ、その1件だけを選ぶ。

**挙動** 1件だけ選んでいるときは、選択したバーに期間変更のハンドルを出す。詳細パネルは EDIT-04 の1件用を開く。2件以上選んでいるときは、選択したバーすべてに枠を出し、期間変更のハンドルは出さない。詳細パネルは EDIT-04 の一括用を開く。どちらでも「削除」が押せるようになる。追加に成功すると、そのタスクを1件だけ選び、固定段の下に出る位置までスクロールする。↑↓ で選択を移すとき、行が縦に画面外なら入るところまでだけスクロールする。見えている行を選んでも縦位置は変えない。バーが横の表示範囲にすでにかかっているときは、横スクロールは変えない。かかっていないときだけ、開始日の少し手前が見える位置へ寄せる。カーソルを乗せたタスク行は、一覧とチャートで薄い帯を出す。2件以上選んだときは、線を引くモードは終わる。

**制約** 並べ替えの握りはドラッグ専用である。クリック、右クリック、3px 以内で離した操作では選択を変えず、詳細パネルやメニューを開かない。並べ替えになったドラッグでも選択を変えない。絞り込みの変更、削除、別ファイルを開くと選択は外れる。スクロールと判定したドラッグでは選択を変えない。バー端の期間ドラッグの当たりでは選択しない。

### EDIT-02 移動

**操作** タスクバーの本体を横にドラッグし、離す。⌘ または Ctrl を押したドラッグでも同じ。

**挙動** 開始日と終了日を、ドラッグした日数だけ動かす。縦には動かない。他のバーと日付の位置は動かない。ドラッグを始めたときから離すまで、開始日と終了日を両方、`4/3` のように月と日だけで出す。年と曜日は出さない。数字は、離したときに入る日に合わせる。文字の大きさは、チャートのズームではなく画面の表示倍率に従う。文字は不透明な地の上に書き、チャートの背景が文字に透けないようにする。地は、動かしている棒、もう一方の日付の地、見えている他の棒には重ねない。空いているときは各端の上に置き、重なるときや画面の端では、棒の外側へずらして画面内に収める。離すと日付は消える。離したときに1回だけ確定し、取り消しの1ステップになる。

**制約** バーの端のドラッグと、空いた所のドラッグでは日付は出さない。期間の長さは変わらない。確度は変わらない。左の名前、マイルストンのひし形、親バーには出さない。開始日や終了日が非稼働日でも印は出さない。バーの長さは暦日のままである。ドラッグを始めたときに、動かすバーが2件以上の選択に入っていれば、選択中のタスクすべてを同じ日数だけ動かす。入っていなければ、その1本だけを動かす。Alt+←→ も、2件以上選んでいれば選択中のすべてを同じ日数だけ動かす。1件のときはその1件だけである。

### EDIT-03 期間変更

**操作** バーの左端または右端を横にドラッグし、離す。選択前でも端をドラッグできる。端とその周りの当たりは、期間を変えるドラッグだけを受ける。

**挙動** 左端は開始日、右端は終了日を変える。ドラッグ中は、開始日と終了日の両方を EDIT-02 と同じ置き方で出す。1日より短くならない位置で止まった日付を出す。離したときに1回だけ確定する。離しても選択は変わらない。Escape の取り消しは EDIT-02 と同じである。

**制約** 期間は1日未満にできない。終了日は開始日より前にできない。確度は変わらない。バー本体の移動と、空いた所のドラッグでは日付を出さない。端の当たりのクリック、ダブルクリック、右クリックでは、選択も詳細パネルもメニューを変えない。バーの移動とパンも始まらない。当たりはバーの外へ 12px、バーの中へは最大 16px で、上下はバーの高さである。バーが長いときは中央に 8px のクリックできる幅を残す。それより短いバーは端の当たりが重なる。2件以上選んでいるバーでは、端の当たりは期間変更ではなく本体の移動として扱う。ハンドルは出さない。

### EDIT-04 詳細パネル

**操作** タスクを選ぶ。バーの本体をダブルクリックする。選択中に Enter を押すか、右クリックメニューの「編集」でも、詳細パネルの名前欄にフォーカスを移す。端の当たりのダブルクリックでは移さない。

**挙動** 右に幅 320px（表示倍率に比例）のパネルが出る。背面は暗くせず、チャートと一覧は操作できる。名前とノート、タグ、期間、担当・ステータス・進捗・確度、マイルストンと前後関係、繋がりの言葉の変更と外すを編集できる。使用中の色の一覧があるウィンドウでは、1件用の詳細パネルに、ステータスの直後に「色」を出す。先頭は「なし」、そのあと一覧の名前を配列の順で出す。一覧にある色は、名前の左に、今の画面と同じライトまたはダークの地色を小さな角丸の四角で示す。「なし」と一覧に無い `colorId` には四角を出さない。一覧に無い `colorId` は id を選択肢に残す。選んだときに `colorId` を書き、取り消しは1ステップである。「なし」はキーを書かない。ほかの項目を確定しても、色を変えていなければ `colorId` は残る。担当は、入れた順の一覧で示す。詳細・一括・複製の担当欄が参照するメンバー一覧は、左一覧と同じである。設定ファイルで開いているときはそのファイルのメンバーである。メンバーをプルダウンで選ぶと末尾に足し、すでに入っている人は候補に出さない。各行を前後に動かし、外すことができる。最後の1人を外すと未割当になる。一覧に無い id はその行に「メンバー不明」と id を出し、外しても候補には戻さない。確定のたびにスケジュールへ書き、取り消しは各操作1ステップである。名前・ノート・期間などのほかの項目も、確定するとスケジュールに反映し、取り消しの1ステップになる。同じ内容は積まない。タグは付いているものを札で外し、入力して Enter で足す。ファイルに既にあるタグのうち、このタスクに無いものは候補に出す。タグの付け外しはそれぞれ取り消しの1ステップになる。

追加項目の定義があるファイルでは、マイルストンと前後関係の節のあとに「追加項目」を出す。定義の順で、文章・数値・日付・候補の欄を出す。数値の欄は文章の欄と同じ幅である。パーセント表示の印がある項目は、その入力の横に `%` を出す。候補はプルダウンで、先頭は「値なし」である。必須で値が空のときだけ、ラベルのうしろに「空欄」を出す。値がある必須項目と、任意の空欄には出さない。確定したキーだけが変わり、取り消しは1ステップである。定義の無いファイルではこの節は出さない。

日付のカレンダーは、欄の下に空きが足りないときは上に開き、画面の中に収める。開始日、終了日、一括パネルと追加項目の日付欄も同じである。

「対応マイルストン」は文字で候補を絞る入力欄である。閉じているときは未設定と一覧に無い ID は「なし」、設定済みは「名前（日付）」である。一覧に無い ID は候補を選ぶまで変えない。フォーカスで一覧を開き、欄の文字を全選択する。文字を変えると絞る。比べる前に前後の空白を除く。空のときは先頭に「なし」、そのあとマイルストンを配列の順で出す。文字があるときは名前か日付にその文字を含むものだけを同じ順で出す。「なし」は出さない。帯の線がオフのグループも含める。候補の表示は「名前（日付）」である。マイルストンは一度に50件まで出す。「なし」は数えない。超えるときは「さらに絞り込んでください」と出す。一致が無いときは「一致するマイルストンがありません」と出す。候補をクリックするか、上下で移して Enter で選ぶと反映する。「なし」は未設定である。選ばずにフォーカスを外すと表示と対応は戻る。Escape は一覧だけ閉じる。変換中の Enter では選ばない。一致が無い Enter では変えない。入力ではマイルストンを足さない。

**制約** タスク名は必須。日付は実在する日で、終了日は開始日以降。項目が無いときは進捗率を 0 以上 100 以下の整数で手で直せる。項目があるときは EDIT-22 に従い、進捗率を手で直せない。循環する前後関係や、存在しない先行は保存せず、理由を出す。パネルの入力欄にフォーカスがあるあいだは、外部ファイルの即時反映を止める。同じタグを足そうとしたときは文書を変えず、理由を出す。

2件以上選んでいるときは、同じ位置に一括用のパネルを出す。見出しは件数である。期間、担当者、ステータス、確度、対応マイルストン、先行と後続の追加、タグの付与だけを書ける。使用中の色の一覧があるウィンドウでは、ステータスの直後に「色」を出す。「変更しない」と「なし」は別の値である。一覧にある色は、名前の左に、今の画面と同じライトまたはダークの地色を小さな角丸の四角で示す。「変更しない」「なし」と一覧に無い id には四角を出さない。「なし」はキーを書かない。全員が同じ色のときだけその値を出し、1件でも違うときは「変更しない」と「複数の値」である。名前、ノート、進捗率は出さない。担当者は1件用と同じ並びの部品で、全員が同じ並びのときだけその並びを出し、1人でも順番や人が違うときは「複数の値」と出す。足す、外す、順を変えたときだけ下書きに入れる。「変更しない」に戻すと下書きから外れ、各作業の今の並びは残る。空の並びの下書きは未割当を書く値であり、「変更しない」とは別である。適用すると、選んだ作業すべての担当がその並びで置き換わる。元の人は残さない。全員が同じ値のほかの項目だけその値を出し、違う項目は空欄か「変更しない」である。値が揃っていない項目の下に「複数の値」と出す。対応マイルストンが揃っていないときは、閉じた表示は空欄で、「なし」とは出さない。「変更しない」と担当の「割り当てなし」は別の値である。欄を変えてもその場では反映せず、「件数に適用」で下書きのある項目だけを選択中のすべてに一度に書く。日付と対応マイルストンは、共通の値と同じに戻した欄は下書きから外す。「入力をクリア」では破棄の知らせは出さない。選択が0件または1件になり、下書きがあったときだけ「入力は破棄しました」をチャート側の `aria-live` に出す。1件に戻ったときは詳細パネルの見出しへ、0件のときはチャートへフォーカスを移す。取り消しは1ステップである。1件でも保存できないときは、どれも変えない。開始と終了は、入れた側だけを書く。下書きの終了が開始より前のときは、先頭のタスク名を含む理由を出す。先行と後続は足すだけである。タグも足すだけである。足す相手が全員に既にあり、ほかに書く項目が無いときは失敗し、文書は変えず、タグは「選択中のタスクには、すでにこのタグがあります。」、先行と後続は「選択中のタスクには、すでにこの前後関係があります。」と出す。下書きがあるあいだは、フォーカスが外れても外部ファイルの即時反映を止める。Enter、バー本体のダブルクリック、右クリックの「編集」、コマンドパレットの「選択中のタスクを編集」は、2件以上選んでいるときは何もしない。Shift+Alt+←→ は1件のときだけである。

### EDIT-05 前後関係

**操作** 詳細パネルの先行と後続でタスクを足す、または外す。

**挙動** 先行に足したタスクの ID は、自分の `predecessors` に入る。後続に足すと、相手の `predecessors` に自分の ID が入る。候補は名前で絞れ、自分自身は出さない。先行にいるタスクは後続の候補から外し、後続にいるタスクは先行の候補から外す。選択済みは、カテゴリとグループを1行、タスク名を次の行に出す。長い階層はカテゴリとグループの行だけを省略する。ホバーでは「カテゴリ / グループ / タスク名」の全文が出る。見つからない ID は `ID` と ID の1行で、ホバーも同じ文字列である。

**制約** 候補は一度に50件までである。それを超えると「さらに絞り込んでください」と出す。

### EDIT-06 ノート

**操作** ノートアイコン、右クリックメニューの「ノート」、または選択中のタスクで ⌘/Ctrl+N からノートダイアログを開く。詳細パネルのノート欄からも保存する。

**挙動** 書いた内容をタスクの `note` にする。空白だけを保存するとプロパティを消す。確定すると取り消しの1ステップになる。⌘/Ctrl+N では、選択中のタスクのダイアログが開く。タイトルはタスク名で、ノート欄にフォーカスする。ノートが無い、または空白だけなら「ノートはありません」と出す。選択は変えない。右クリックメニューが開いていれば閉じる。キーのリピートでは開かない。

**制約** 空のノートは JSON に書かない。タスクが選択されていないときは開かない。マイルストンにはノートが無く、このキーの対象ではない。ダイアログが開いているあいだと、線を引くモードのあいだは開かない。検索欄、入力欄、選択欄では効かない。ボタンにフォーカスがあっても効く。N だけ、Shift や Alt が一緒のときは開かない。Shift 付きはアプリが取らない。ブラウザ版では、開くときも、選択が無いなどで何もしないときも、⌘/Ctrl+N はブラウザに渡さない。スキーマは変えない。

### EDIT-07 マイルストン

**操作** 「マイルストン追加」、または ⌘ または Ctrl と Shift と Enter で、名前、日付、確度を指定して足す。`milestoneGroups` が2件以上あるときは、同じダイアログでグループも選ぶ。日付ヘッダー、マイルストン帯の空き、チャート本体の空きを右クリックし、「マイルストンを追加」を選んでも、同じダイアログが開く。マイルストンが 0 件で帯が無いときでも、ツールバーと、日付ヘッダーとチャート本体の空きから足せる。ひし形、またはその右の名前を主ボタンで単クリックすると、VIEW-04 の点線を切り替える。同じ場所を横にドラッグする。同じ場所のダブルクリック、または右クリックメニューの「編集」で名前、日付、確度を編集する。`milestoneGroups` が2件以上あるときは、編集でもグループを選ぶ。右クリックメニューの「削除」で確認して消す。

**挙動**

- 追加: 名前の初期値は空、確度の初期値は未確定である。ツールバーと ⌘ または Ctrl と Shift と Enter から開いたときの日付の初期値は画面の今日である。ダイアログを開いたとき、名前の欄にフォーカスする。名前の欄で、修飾キーの無い Enter を押すと保存する。変換中の Enter では保存しない。Ctrl、⌘、Alt、Shift が付いた Enter でも保存しない。日付、確度、グループの選択では Enter では保存しない。日付のカレンダーは、欄の下に空きが足りないときは上に開き、画面の中に収める。日付ヘッダー、マイルストン帯の空き、チャート本体の空きから開いたときは、ポインタの横位置が含まれる暦日である。その日の左端から、次の日の左端の手前までがその日である。月表示でヘッダーが月のラベルでも、日で決める。配列の末尾に1件足す。`milestoneGroups` が2件以上あるときは、ダイアログでグループを選ぶ。候補は `milestoneGroups` の順で、表示はグループ名である。帯の線がオフのグループと、中身が空のグループも含める。帯の空きを右クリックして開いたときの初期値は、ポインタの縦位置が含まれるグループである。どのグループの帯にも入らない位置なら、先頭である。ツールバー、日付ヘッダー、チャート本体の空きから開いたときの初期値は、先頭である。`milestoneGroups` が1件のときは選択を出さず、先頭に入れる。グループが無いときは、名前「マイルストン」のグループを1つ作って入れる。同じ名前と日付でも足せる。保存する名前は前後の空白を除いたものである。ID は、そのスケジュールのカテゴリ、グループ、タスク、マイルストン、マイルストングループの ID のどれとも重ならない UUID である。帯の線がオフのグループを選んで足しても、帯の線は変えない。オンに戻すのは編集で別のグループへ移したときだけである。追加しても絞り込み、折りたたみ、ズーム、スクロール、系統、選択は変えない。足した日付が今の範囲の外なら、保存後の期間は、全タスクと全マイルストンから今までどおり決まる。
- 表示順: 日付順には並べ替えない。
- ドラッグ: 日付を日単位で変え、離したときに確定する。確度もグループも変えない。点線のオンオフも変えない。オンなら、動いたあとの日付についてくる。
- 編集: 名前、日付、確度を変える。ダブルクリックで開いても、点線のオンオフは変えない。日付のカレンダーは追加と同じである。`milestoneGroups` が2件以上あるときは、グループも選ぶ。候補は `milestoneGroups` の順で、表示はグループ名である。帯の線がオフのグループと、中身が空のグループも含める。初期値は、開いたマイルストンのグループである。`milestoneGroups` が1件のときは選択を出さず、`groupId` は変えない。保存すると `groupId` を選んだグループにする。`id` と、マイルストン配列上の位置と、タスクの対応（`milestoneId`）は変えない。日付が空なら保存しない。名前が空白だけなら、元の名前を残す。名前、日付、確度、グループを一度に変えても、取り消しは1ステップである。段の位置は、移した先のグループの中で、日付と id から今までどおり決まる。元のグループのマイルストンが0件になると、その帯の行は消える。グループ自体は残る。移した先が空だったときは、そのグループの帯が出る。移した先の帯の線がオフのときは、そのグループだけオンに戻す。他のオフはそのままである。これは表示状態なので、取り消しでは戻らない。オンに戻したあとに取り消すと、マイルストンは元のグループへ戻り、移した先の線はオンのまま残る。絞り込み、選択、折りたたみ、系統、ズーム、スクロールは変えない。マイルストンの日付が同じなら、タスクの日付と超過の判定も変わらない。グループの付け替えの入口は編集だけである。
- 削除: マイルストンを配列から外し、その ID を指すタスクの `milestoneId` をすべて外す。タスクの日付、先行、ステータス、進捗、ノートは変えない。空のグループとカテゴリは残す。見えていないタスクも含め、その ID を指すタスクが1件でもあれば、確認に「このマイルストンを指しているタスクの対応は外れます。タスクの日付は変えません。」を出す。無ければその文は出さない。絞り込んでいたマイルストンを消したときだけ、マイルストンの絞り込みを「すべて」に戻す。「なし」と「すべて」と別のマイルストンはそのままである。選択と系統と折りたたみは変えない。
- 履歴: 追加と削除は、それぞれ取り消しの1ステップである。絞り込みを「すべて」に戻すことは履歴に入らない。取り消しても絞り込みは「すべて」のままである。

**制約** 名前が空白だけなら「名前を入力してください」、日付が空または実在しない日なら「日付を入力してください」と出し、追加しない。ダイアログは開いたままにする。キャンセルと Escape では足さない。ツールバーの「追加」と「削除」、Delete、Backspace はタスクのままである。確認をキャンセルすると消さない。当たりは、ひし形の円と、名前の文字の矩形と、そのあいだの隙間である。名前の幅は段の割り当てに使う幅と同じで、右端より右は当たらない。上下は円の直径と文字の高さのうち広い方で、段の上下の空きと段の高さ全体には広げない。名前が空のときは円だけである。左のグループ名の行は当たらない。線を引くモードでは、名前の上でも編集もドラッグもメニューも出さない。ホイールの横スクロールは変えない。

### EDIT-08 追加

**操作** 「追加」を押すか、⌘ または Ctrl と Enter、または Insert で、カテゴリ、グループ、タスク名、開始日、終了日を指定する。

**挙動** 選んだグループの末尾にタスクを足す。ダイアログを開いたとき、タスク名の欄にフォーカスする。タスク名の欄で、修飾キーの無い Enter を押すと、「追加」と同じ確定をする。変換中の Enter では確定しない。Ctrl、⌘、Alt、Shift が付いた Enter でも確定しない。日付欄、カテゴリ、グループでは Enter では確定しない。日付のカレンダーは、欄の下に空きが足りないときは上に開き、画面の中に収める。選択中のタスクがあれば、そのカテゴリ、グループ、日付を初期値にする。無ければ先頭のカテゴリとグループ、今日の日付を使う。新しいタスクは割り当てなし、未着手、進捗 0、未確定、前後関係なし、対応マイルストン未設定で、ID は、カテゴリ、グループ、タスク、マイルストンの ID と重ならない新しい UUID である。追加後はその行が見えるよう展開し、系統を解除し、そのタスクを選択する。

絞り込みは、新しいタスクを隠してしまうものだけを外す。

- 担当者: 特定のメンバーなら「すべて」に戻す。「割り当てなし」はそのまま残す
- ステータス: 選んでいる項目が新しいタスクのステータスと違えば「すべて」に戻す。「完了以外」は、新しいタスクの項目の扱いが完了のときだけ「すべて」に戻す
- 確度: 「確定」なら「すべて」に戻す。「未確定」と「すべて」はそのまま残す
- 期限: 「期限超過」で、新しいタスクが期限超過でなければ「すべて」に戻す
- 前後: 「前後: 破綻のみ」は外す
- マイルストン: 特定のマイルストンなら「すべて」に戻す。「なし」はそのまま残す
- タグ: 選んでいるタグを一つも持たないなら、タグの選択は全部外す
- タスク名の検索: 新しい名前に含まれない文字なら消す
- ノートの検索: 文字が入っていれば消す

**制約** 終了日が開始日より前なら追加しない。期間は1日未満にできない。空のグループとカテゴリも追加先として選べる。2件以上選んでいるときの初期値は、1件も選んでいないときと同じである。

### EDIT-09 削除

**操作** タスクを選んで「削除」を押すか、Delete または Backspace を押し、確認する。右クリックメニューの「削除」でも同じ確認を開く。

**挙動** 選んでいるタスクを消す。2件以上選んでいるときは、確認に件数を出す。他のタスクの先行からはその ID を外し、前後のタスク同士はつながない。消したタスクを含む繋がりも JSON から外し、残ったタスク同士はつなぎ直さない。系統の起点を消したときは系統を解除する。空になったグループとカテゴリはデータに残す。線の上で Delete または Backspace を押したときは、タスクは消さず、EDIT-12 のとおりその線だけを外す。複数の削除も取り消しの1ステップである。

**制約** タスクを1件も選んでいないと「削除」は押せない。確認をキャンセルすると消さない。検索欄、入力欄、選択欄、ボタンにフォーカスがあるときは、Delete と Backspace では消さない。ツールバーの「削除」は、線の上でもタスクを消す。

### EDIT-10 取り消し・やり直し

**操作** ⌘/Ctrl+Z で取り消す。⌘/Ctrl+Shift+Z、または Ctrl+Y でやり直す。

**挙動** カテゴリ、グループ、タスク、マイルストン、スケジュールのタイトルの確定した変更を1操作1ステップで戻す。対象はバーの移動、期間変更、マイルストンの移動、詳細パネルでの項目の確定、一括パネルでの適用、ノートの保存、確度の切り替え、カテゴリとグループの改名、EDIT-20 のタイトルの確定、EDIT-21 の階層の確定、カテゴリとグループの追加と削除、タスクの複製、タスクの削除、タスクの並べ替えと別グループへの移動、グループの並べ替えと別カテゴリへの移動、カテゴリの並べ替え、チャート上で線を足すこと、線を1本外すこと、繋がりを足すこと、繋がりの言葉を変えること、繋がりを1組外すこと、SYNC-01 の「両方を画面へ反映」、MCP-01 の `replace_schedule` による前面ウィンドウの置き換えである。置き換えは変わったタスクの数では分けない。最大100件まで覚える。ファイルを開くと履歴は空になる。`replace_schedule` では履歴を空にしない。

**制約** 絞り込み、折りたたみ、ズーム、スクロール、系統、選択は履歴に入らない。ダイアログ、検索欄、入力欄にフォーカスがあるときは、取り消し・やり直しのキーはスケジュールに効かない。拡張項目の編集覆い（SET-10）と、ステータス項目の編集覆い（SET-08）と、色の一覧の編集覆い（SET-09）を開いているあいだは、スケジュールの取り消しとやり直しは動かない。追加項目の覆いとステータス項目の覆いと色の一覧の覆いでは、⌘/Ctrl+Z で取り消し、⌘/Ctrl+Shift+Z または Ctrl+Y でやり直しができ、対象はその覆いの下書きだけである。文字欄に焦点があるときも、ブラウザの取り消しではなくこの履歴を使う。macOS の編集メニューの取り消しとやり直しも同じ履歴を使う。削除の確認が出ているあいだは、取り消しもやり直しも動かない。同じ内容の変更はステップに積まない。

### EDIT-11 右クリックメニュー

**操作** タスクのバー、または左のタスク行を右クリックする。マイルストンはひし形、またはその右の名前を右クリックする。左のマイルストングループ名の行、カテゴリ行、グループ行、`levels` と `outline` があるときの見出し行も右クリックする。日付ヘッダー、マイルストン帯の空き、チャート本体の空きも右クリックする。

**挙動** メニューは、ポインタの下にあるものの操作だけを出す。重なったときは上から先に当たる 1 つだけである。左のマイルストングループ名の行では「非表示」と、帯に出ている別のグループ行があるときだけ「この行だけ表示」を出す。どちらも FILTER-11 の帯の線のオンオフと同じである。右クリックしてもタスクの選択は変えない。タスクでは「編集」、「複製」、確度、ノート、系統、削除のあいだに区切りを入れる。「編集」の右に Enter、「複製」の右に Alt+Shift+↓、「ノート」の右に ⌘N または Ctrl+N、「削除」の右に Delete を出す。削除の文字は危険色である。各項目の左に小さなアイコンを置く。マイルストン、カテゴリ、グループでも、削除の前に区切りを入れ、削除の文字は同じ危険色である。確度の切り替えは日付を動かさず、取り消しの1ステップである。右クリックしたタスクを選択する。2件以上選んでいるときは「削除」だけを出す。マイルストンでは「編集」、今の確度と逆の「確定にする」または「未確定にする」、「削除」を出す。確度の切り替えは日付を動かさず、取り消しの1ステップである。右クリックしても選択しない。左のカテゴリ行では「名前を変更」、「下にカテゴリを追加」、「グループを追加」を出し、消せるときだけ「削除」を足す。左のグループ行では「名前を変更」、「下にグループを追加」を出し、消せるときだけ「削除」を足す。`levels` と `outline` があり、定義と入れ子の数が揃っているときは、見出し行でもカテゴリ行と同じ並びで、各段の定義名を使った「名前を変更」、「下に（その段の名前）を追加」、タスクの一つ上の段以外では「（次の段の名前）を追加」を出し、消せるときだけ「削除」を足す。名前の変更と追加は EDIT-13 または EDIT-18 のダイアログを開く。削除は EDIT-19 の確認を開く。見えている線の上では「線を外す」または円弧の上では「繋がりを外す」だけを出す。日付ヘッダー、マイルストン帯の空き、チャート本体の空きでは「マイルストンを追加」だけを出す。選ぶと EDIT-07 の追加ダイアログが開く。右クリックでは選択を外さない。チャートの空きの左クリックで選択を外すのは今どおりである。メニューはクリック位置に出し、画面の端では内側へずらす。項目を選ぶ、外側をクリックする、Escape、スクロール（⌘/Ctrl+矢印を含む）、表示サイズの変更（SET-01）、またはダイアログが開くと閉じる。選択中バーの端の当たりではメニューを出さない。バー本体では同じメニューが出る。タスクの削除は確認を開く。カテゴリとグループの削除も確認を開く。線を外すは確認しない。系統は FILTER-08 のとおりである。線を外すは EDIT-12 のとおりである。

**制約** ダイアログを開いているあいだは背面を操作できないので出ない。線を引くモードのあいだは、タスク、ひし形と名前、左のマイルストングループ名の行、カテゴリ行、グループ行のメニューと、「マイルストンを追加」は出さない。線の「線を外す」は出す。タスクバーとハンドルは線より先、マイルストンの当たりは帯の空きより先、線はチャートの空きより先に当たる。親バーはクリックを受けないので、チャート本体の空きと同じ項目になる。左の「マイルストン」、左の見出し、ツールバー、見出し、ヒントには出さない。表示期間の外は押せない。マイルストンの名前の上は追加にしない。

### EDIT-12 チャート上の前後の線

**操作** タスクを選んで「線を引く」を押す。⌘/Ctrl+L でも同じ。別のタスクバーをクリックすると、起点からそのタスクへ線を足す。起点をもう一度クリックする、Esc、「線を引く」、または ⌘/Ctrl+L で、結ばずに終わる。線にカーソルを合わせて Delete または Backspace を押すか、線を右クリックして「線を外す」を選ぶと、その 1 本を外す。

**挙動**

- モード: 選んでいないときはモードに入らない。入るとボタンに起点の名前が出て、画面上部は「次にクリックしたタスクを後続にします。Esc で中止」になる。起点は入ったときのタスクのままである。モードを終えると追随する線は消える。線を引くモードの帯も、左一覧の上端に同じ高さの空きで揃える。一覧に無いステータスと担当の帯と同時に出るときは、両方の高さを空きに含める。失敗の文で帯が伸びたときも同じ。
- 追随: 起点の右端からカーソルへ、確定した矢印と同じ折れ線が通常の色で追随する。タスクバーの上ではそのバーの左端まで伸び、左の一覧の上ではチャートの左端で終わる。カーソルが乗ったタスクバーは、選択の枠とは別の輪郭になる。起点、親バー、ひし形は強調しない。
- 追加: 別のタスクバーをクリックすると、後続の `predecessors` に起点が入り、モードは残る。
- 失敗時: すでに結ばれている組と循環する組は保存せず、詳細パネルと同じ理由をモードのヒントの下に出す。モードは残る。
- 削除: 線を外すときは確認せず、その先行だけを外す。タスクは残り、前後のタスク同士はつながらない。重なった線は、カーソルに一番近い 1 本だけを太くして外す。
- 履歴: 線を足すのも外すのも、取り消しの 1 ステップである。

**制約** 見えていないタスクへは、チャート上ではスクロールしてからクリックする。画面の外を指して結ぶ操作はない。詳細パネルの先行と後続は今どおり使える。モード中、タスクバーの移動、期間変更、マイルストンの日付変更はしない。空き、親バー、背景を 3px 以上ドラッグすると、線を引いていないときの空白ドラッグと同じスクロールになる。タスクバーでは 8px 以上ドラッグしたときも同じスクロールになる。8px 未満で同じバーの上で離したときだけ、別のタスクバーをクリックしたときと同じで線を足す。8px 未満で空きや別のバーで離したときは、線もスクロールも起きない。スクロールになったドラッグは、離した場所がタスクバーでも線を足さない。スペースキーを押したドラッグと中ボタンのドラッグも、モード中はスクロールする。スペースキーを押したまま 3px 未満で同じバーの上で離したときは、今どおりそのタスクを後続にする。中ボタンでは線を足さない。3px 未満の動きはスクロールとみなさない。ホイールの縦と横、Shift+ホイール、⌘ または Ctrl と矢印ではスクロールでき、追随する線も動く。スクロールしてもモードは残る。ドラッグがスクロールになっているあいだは、カーソルを閉じた手にする。スクロールのドラッグ中にポインタがチャートの外へ出ても、追随する線の終点は消えない。ドラッグ中の Escape はモードを終え、閉じた手も消す。動いたビューは戻さない。ダブルクリックの 2 回目では線を足さない。親バー、ひし形と名前、背景のクリックではモードは終わらない。ダブルクリックと Enter では詳細パネルの名前欄にフォーカスを移さない。タスクと、ひし形と名前の右クリックメニューは出さない。左の切れた名前の全文と一覧の幅は今どおりである。絞り込み、起点の削除、別ファイルを開くなどで選択が外れるとモードも終わる。⌘/Ctrl+L は、ダイアログ、検索欄、入力欄、選択欄では効かない。ボタンにフォーカスがあっても効く。修飾キーの無い L では始まらない。線の上の Delete と Backspace は、検索欄、入力欄、選択欄、ボタンにフォーカスがあるときは線を外さない。バーや、ひし形と名前の上では、今どおりタスクの削除確認である。両端が見えていない線は描けないので、この操作では外せない。ツールバーの「削除」はタスクを消す。線の端をドラッグして付け替えない。スキーマは変えない。

### EDIT-13 カテゴリとグループの名前

**操作** 左のカテゴリ行またはグループ行をダブルクリックする。`levels` と `outline` があるときは見出し行も同様である。右クリックの「名前を変更」でも同じ。

**挙動** 名前だけのダイアログが開く。保存する名前は前後の空白を除いたものである。空白だけなら、元の名前を残して閉じる。カテゴリ名が他のカテゴリと重なるとき、または同じカテゴリの中でグループ名が重なるときは、保存せず、重複であることを示す。見出し行では、同じ親の下で兄弟の名前が重なるときも保存しない。保存すると `id` は変わらず、名前だけが変わる。取り消しは 1 ステップである。折りたたみは `id` を鍵にするので、改名しても開閉は残る。絞り込み、ズーム、スクロール、系統、選択は変えない。

**制約** チャート上の親バーからは開かない。線を引くモードのあいだは開かない。

### EDIT-14 複製

**操作** タスクのバー、または左のタスク行を右クリックし、「複製」を選ぶ。または、タスクを選んで Alt と Shift と ↓ を押す。

**挙動** 「タスクを複製」ダイアログが開く。項目は詳細パネルと同じで、初期値は元タスクのタスク名、ノート、開始日、終了日、担当者、確度、対応マイルストンである。使用中の色の一覧があるウィンドウでは、ステータスの直後に「色」を出し、初期値は元タスクの色で、無ければ「なし」である。一覧にある色は、名前の左に、今の画面と同じライトまたはダークの地色を小さな角丸の四角で示す。「なし」と一覧に無い id には四角を出さない。「追加」まで文書は変えない。追加したタスクの色は、ダイアログで選んだ値である。「なし」ならキーは無い。担当者は詳細パネルと同じ並びの部品で、開いたとき元タスクの入れた順が入る。足す、外す、順を変える操作も同じである。「追加」するまで元タスクの担当は変わらない。タグは元タスクから写す。ダイアログには出さない。ステータスは一覧の初期値（未着手）、進捗率は 0、先行と後続の初期値は空である。追加前に、ステータス、進捗率、先行、後続は変えられる。先行と後続の候補には元タスクを含める。「対応マイルストン」は詳細パネルと同じ入力欄である。選んだ値は「追加」まで文書に反映しない。ダイアログで変えた項目は、「追加」するまでスケジュールに反映しない。タスク名にフォーカスし、全文を選択する。同じ名前のままでも足せる。「追加」で、元タスクと同じグループの直後に新しいタスクを足す。ID は、カテゴリ、グループ、タスク、マイルストン、マイルストングループの ID と重ならない UUID である。元タスクを先行にしている他のタスクへ、新しい ID は入れない。ダイアログで先行または後続を足したときだけ、相手の先行に新しい ID が入る。追加後はそのグループとカテゴリを展開し、新しいタスクを選択して固定段の下に出る位置へ寄せ、系統を解除する。絞り込みは、新しいタスクを隠すものだけを外す。担当、ステータス、確度、期限、前後、マイルストン、タスク名の検索、ノートの検索を、足したタスクの値で判定する。取り消しは 1 ステップで、挿入と、ダイアログで足した後続をまとめて戻す。

**制約** 名前が空白だけ、日付が空または実在しない日、終了日が開始日より前、進捗率が 0 以上 100 以下の整数でない、循環する前後関係、存在しない先行なら足さず、理由を出してダイアログを開いたままにする。空白だけのノートは付けない。キャンセルと Escape では足さない。カテゴリとグループは選べず、別のグループへは動かない。ツールバーには出さない。複製ダイアログでは Enter では確定しない。対応マイルストンの欄で一致が無い Enter でも確定しない。線を引くモードのあいだは、タスクのメニューが出ないので複製もできない。1件だけ選んでいるときだけ開ける。スキーマは変えない。

### EDIT-15 タスクの並べ替え

**操作** 左のタスク行の左端の握りをドラッグし、離す。または、タスクを選んで Alt と ↑ または Alt と ↓ を押す。

**挙動** 同じグループの `tasks` 配列の順を変える。キーは 1 回で 1 つ動かし、押し続けでは動かない。別のグループへ離したときは、そのグループへ移す。別のカテゴリでも同じである。あとから足したタスクを、既存のタスクのあいだに置ける。ドラッグ中は文書を変えず、左の一覧とチャートの行だけを仮の順で描く。挿入位置に線を出す。並べ替えが始まると、半透明のタスク行がポインタの縦位置に付いて動く。左の一覧では、仮の位置のその行は空けておく。離したときに1回だけ確定し、順または場所が変わったときだけ取り消しの1ステップになる。同じ位置へ戻したドロップは積まない。タスクの `id`、日付、確度、先行、担当は変えない。元のグループが空になっても残す。左の一覧は自動ではスクロールしない。

**制約** 複数タスクを一度に動かさない。カテゴリ行、親バー、折りたたんだカテゴリやグループの中へは入れない。並べ替えは左端の握りだけで始まる。キーボードの並べ替えは、端では文書も履歴も変えない。絞り込み、系統、折りたたみで兄弟の行が揃わないときと、起動復旧の前は動かない。握りを 3px を超えて動かすと、方向にかかわらず並べ替えが始まる。3px 以内で離してもタスクを選ばず、詳細パネルを開かない。握りを右クリックしても選択を変えず、メニューを出さない。握り以外をドラッグしても並べ替えは始まらない。名前が幅に収まらないときは NAV-05 のとおり全文が出て、名前は動かない。並べ替えになったドラッグでは選択を変えない。ノートボタンと、握り以外の右クリックメニューは今どおりである。チャート上のドラッグは NAV-01 と EDIT-02、EDIT-03 のままである。受けない位置で離したときは元の位置に戻す。絞り込みか系統で、移動元か移動先の兄弟が1件でも隠れているあいだは始めない。SYNC-03 で前回のファイルを開き終わるまでは始めない。スキーマは変えない。

### EDIT-16 カテゴリの並べ替え

**操作** 左のカテゴリ行の左端の握りをドラッグし、離す。

**挙動** `categories` 配列の順を変える。グループとタスクは、そのカテゴリの中に残る。折りたたんだカテゴリも、その行の握りをドラッグして順を変えられる。開閉は残る。ドラッグ中は文書を変えず、左の一覧とチャートの行だけを仮の順で描く。挿入位置に線を出す。並べ替えが始まると、半透明のカテゴリ行と、いま見えている配下のグループ行とタスク行が、上から順に積まれた塊でポインタの縦位置に付いて動く。折りたたんで出ていない配下は塊に入れない。左の一覧では、仮の位置の塊に入った行は空けておく。離したときに1回だけ確定し、順が変わったときだけ取り消しの1ステップになる。同じ位置へ戻したドロップは積まない。カテゴリ、グループ、タスクの `id` と中身は変えない。左の一覧は自動ではスクロールしない。

**制約** 複数カテゴリを一度に動かさない。グループの並びは変えない。タスクを別のグループや別のカテゴリへは動かさない。グループ行、タスク行、親バーは、この操作では掴めない。並べ替えは左端の握りだけで始まる。握りを 3px を超えて動かすと、方向にかかわらず並べ替えが始まる。握り以外をドラッグしても並べ替えは始まらない。名前が幅に収まらないときは NAV-05 のとおり全文が出て、名前は動かない。ダブルクリックの名前変更、右クリックの「名前を変更」、三角の折りたたみは今どおりである。チャート上のドラッグは NAV-01 のままである。カテゴリ全体の縦範囲の外、または固定されている見出しの上で離したときは元の位置に戻す。固定されているカテゴリ行の握りからも始められる。絞り込みか系統でカテゴリが1件でも行に出ていないあいだは並べ替えを始めない。SYNC-03 で前回のファイルを開き終わるまでは並べ替えも始めない。スキーマは変えない。

### EDIT-17 グループの並べ替え

**操作** 左のグループ行の左端の握りをドラッグし、離す。

**挙動** 同じカテゴリの `groups` 配列の順を変える。別のカテゴリのグループの境界へ離したときは、そのカテゴリへ移す。タスクは、そのグループの中に残る。折りたたんだグループも、その行の握りをドラッグして順を変えられる。開閉は残る。ドラッグ中は文書を変えず、左の一覧とチャートの行だけを仮の順で描く。挿入位置に線を出す。並べ替えが始まると、半透明のグループ行と、いま見えている配下のタスク行が、上から順に積まれた塊でポインタの縦位置に付いて動く。折りたたんで出ていない配下は塊に入れない。左の一覧では、仮の位置の塊に入った行は空けておく。離したときに1回だけ確定し、順または場所が変わったときだけ取り消しの1ステップになる。同じ位置へ戻したドロップは積まない。カテゴリ、グループ、タスクの `id` と中身は変えない。左の一覧は自動ではスクロールしない。

**制約** 複数グループを一度に動かさない。カテゴリの並びは変えない。カテゴリを別のカテゴリの中へは入れない。カテゴリ行、タスク行、親バーは、この操作では掴めない。並べ替えは左端の握りだけで始まる。握りを 3px を超えて動かすと、方向にかかわらず並べ替えが始まる。握り以外をドラッグしても並べ替えは始まらない。名前が幅に収まらないときは NAV-05 のとおり全文が出て、名前は動かない。ダブルクリックの名前変更、右クリックの「名前を変更」、三角の折りたたみは今どおりである。チャート上のドラッグは NAV-01 のままである。受けない位置で離したときは元の位置に戻す。移した先に同じグループ名があるときは確定しない。移すと元のカテゴリのグループが0件になる位置は受けない。折りたたんだカテゴリの中へは入れない。絞り込みか系統で、移動元か移動先の兄弟グループが1件でも隠れているあいだは始めない。親のカテゴリを折りたたんでいるあいだは、グループ行が無いので始めない。SYNC-03 で前回のファイルを開き終わるまでは並べ替えも始めない。スキーマは変えない。

### EDIT-18 カテゴリとグループの追加

**操作** 左のカテゴリ行またはグループ行を右クリックし、「下にカテゴリを追加」、「グループを追加」、または「下にグループを追加」を選ぶ。`levels` と `outline` があり、定義と入れ子の数が揃っているときは、見出し行でも EDIT-11 のとおり同じ段または次の段を選ぶ。ツールバーの「追加」の右のプルダウンでは、タスクの次に、定義が無い3段のときも、定義があり見出しがあるときも「見出しを追加」を選べる。

**挙動** 見出し行の右クリックの追加は、名前だけのダイアログが開く。プルダウンの「見出しを追加」では、見出しの段が1つだけのときも名前だけを聞く。見出しの段が2つ以上のときは、段（タスクの段を除く見出しの定義名。定義が無い3段では「カテゴリ」と「グループ」）、最上段以外では追加先（一つ上の段の枝。定義が無い3段ではカテゴリ。同じ段で名前が重なる枝だけ、根から「 / 」でつないだ経路を出す）、名前を選ぶダイアログが開く。段を変えたあとも名前は残り、追加先はその段の文書順の最後の枝に戻る。保存すると、カテゴリの追加は右クリックしたカテゴリの直後に足す。中にはタスク0件のグループを1つ作り、名前は「グループ」にする。カテゴリ行からのグループ追加はそのカテゴリの末尾、グループ行からはその直後に入れる。プルダウンの「見出しを追加」で段がカテゴリのときは一覧の末尾にカテゴリを足し、中へ空の「グループ」を1つ作る。段がグループのときは選んだカテゴリの末尾にグループを足す。定義があるときの見出しの追加は、右クリックでは選んだ段の直後または子の末尾に枝を足す。プルダウンでは最上段は一覧の末尾、それ以外は選んだ追加先の子の末尾に足す。いずれも下の段は定義名の見出しをタスクの一つ上まで自動でつなぐ。タスクは足さない。タスクの一つ上の枝は子を空にできる。定義が無い3段では JSON に `levels` と `outline` は付けない。追加先が無いときは「追加先を選んでください」と出し、文書は変えない。`id` はカテゴリ、グループ、タスク、マイルストンと重ならない UUID である。取り消しは1回である。絞り込み、系統、選択は変えない。

**制約** 主ボタンの「追加」はタスクのままである。見出しの段の名前をプルダウンに並べない。1段だけの定義と、定義と入れ子がずれているあいだは、プルダウンに見出しの追加を出さない。ダブルクリックは名前の変更のままである。空白だけの名前と、重複する名前は追加しない。ダイアログは開いたまま理由を出す。線を引くモードのあいだは開かない。スキーマは変えない。

**制約** Delete キーとツールバーの「削除」は、選んだタスクのままである。カテゴリとグループは選択されないので、キーでは消さない。線を引くモードのあいだはメニューを出さない。スキーマは変えない。

### EDIT-20 スケジュールのタイトル

**操作** 見出しの右の「タイトルを変更」（鉛筆）を押す。Enter と Space でも編集を始める。⌘/Ctrl+K のコマンドパレットの「タイトルを変更」でも、パレットを閉じたあと同じ入力を開く。見出しの文字をクリック、ドラッグ、ダブルクリックでは編集を始めない。

**挙動** 見出しの位置で1行入力になり、全文が選択される。Enter、入力の外のクリック、Tab、Shift+Tab で確定する。Escape では確定せず、編集を始める前のタイトルに戻す。変換中の Enter と Escape は、変換の操作だけに使い、編集は閉じない。確定時は前後の空白だけを除き、途中の空白は残す。空白だけなら元のタイトルのまま閉じ、履歴にも未保存にもしない。読み上げで「タイトルは変更していません」と一度だけ伝える。除いた結果が今のタイトルと同じときは、閉じるだけで履歴にも読み上げも出さない。文字が変わった確定は取り消しの1ステップである。入力にフォーカスがあるあいだの取り消しとやり直しは、入力中の文字に効き、スケジュールの履歴には効かない。開く、保存、別名保存、書き出し、差分を表示、差分をコピー、JSON を表示の前に、開いている入力を確定する。コマンドパレットを開くときも、フォーカスが外れて確定する。確定した変更だけを `title: 旧 → 新` として差分に出す。FILE-07 で title の行を開いているあいだ、下線は休止中の見出しの文字に付ける。鉛筆と編集中の入力には付けない。入力にフォーカスがあるあいだは、詳細パネルと同じく外部ファイルの即時反映を止める。開いている入力へ、ファイル側のタイトルは書き込まない。

**制約** 変えるのは JSON の `title` だけである。ファイル名、ウィンドウタイトル、状態バーのファイル名、開いているパスは変えない。ファイル名を変えてもタイトルは追従しない。別名保存の提案名と書き出しのファイル名は、今どおりタイトルから作る。☰ とメニューバーには入口を足さない。専用のグローバルショートカットは付けない。ファイル操作の途中は、鉛筆も「タイトルを変更」も押せない。省略されているときだけ、見出しの文字にマウスを乗せると全文が出る（NAV-05 と同じ）。

### EDIT-21 階層の名前と意味

**操作** 見出しの鉛筆の右の「階層編集」を押す。

**挙動** 「階層」ダイアログが開く。幅はおおむね 880px である。段の一覧は枠のある面の中だけをスクロールする。一覧の上に、意味と指示の書き方を1回だけ出す。一段は、左から番号、名前・意味・指示の欄、操作を並べ、枠と角のある行にする。番号と欄の左端は、全段で揃える。各段に名前、意味、指示を書く。意味は必須、指示は空でよい。最下段の操作列には「タスク」と出し、上下と削除は出さない。見出しの段には「上へ」「下へ」「削除」がある。段が2つ以上のときだけ、見出しの段にこれらを出す。1段だけのときは出さない。最上段の「上へ」と、タスクの一つ上の段の「下へ」は押せない。「上へ」「下へ」は、ダイアログを閉じるまで文書には書かず、段の定義の順だけを入れ替える。チャートの入れ子は、閉じたあとも変えない。段は5つまで足せる。「段を追加」は、タスクの一つ上に空の段を入れる。フッター左に「段を追加」、右に「閉じる」がある。名前と意味がすべて1文字以上のときだけ「閉じる」が押せる。閉じると下書きを画面の文書へ入れ、取り消しは1回である。名前か意味が空のときは「閉じる」は押せず、Escape では下書きを捨てて文書は変えない。定義が無いファイルを開いたときの初期値は、名前が「カテゴリ」「グループ」「タスク」、意味が「上のまとまり」「その中のまとまり」「日付を持つ一つの作業」である。下書きがこのままなら `levels` は書かず `categories` の形も残す。名前か意味だけを変えて段数が同じときは行は動かない。`levels` が無かった3段のファイルは、同じ `id` と順の `outline` に移し `levels` を書く。すでに `outline` のファイルは `levels` の名前、意味、指示だけを書き換える。段数を変えて閉じたときは `levels` だけ新しい段数にし、空の見出しは足さない。入れ子の深さが新しい段数と一致しないときは、一覧とフッターのあいだに「入れ子の数が違うので、この段数はまだ保存できません。」と出す（`role="alert"`）。チャート上の帯は従来どおり「階層の定義と入れ子の数が違います。」である。このダイアログで揃っていたファイルの段数を変えた直後だけ、見出しの追加とタスクの移動を止めない。深さが揃っていないときは、下の段を定義名で自動ではつなぎません。

**制約** 検索、日・週・月、案内には入口を置かない。ファイル操作の途中と起動復旧の前は押せない。押せないときの文字色は二次色で、不透明度では薄くしない。入口は常に枠と面がある。ダイアログにファイル保存は置かない。変換中の Enter と欄の Enter では閉じない。閉じたあとのフォーカスは「階層編集」に戻す。開いた直後のフォーカスは最上段の名前欄である。ダイアログを開いているあいだは、EDIT-20 のタイトル入力と同様に外部ファイルの即時反映を止める。開いたまま親が描き直しても、下書きは文書の定義へ戻さない。

### EDIT-22 タスクの項目と進捗の連動

**操作** 詳細パネルで「TODOを追加」を押し、文を入力して確定する。チェックを付け外しする。文を直す。削除する。最後の1件を削除する。

**挙動** 項目は詳細パネルだけで編集する。ノート欄には入れない。複製、追加、一括パネルには載せない。項目が無いときは進捗率をスライダーと数値で手で直せる。1件以上あるときは、進捗率は件数の結果だけを読み取り表示し、その直後に `3/6` のように済んだ件数と全体の件数を出す。各項目の重さは同じである。済んだ件数を全体で割った整数が進捗率である。割り切れないときは切り捨てる。全部済んだときだけ 100 になる。チェックの付け外し、文の確定、削除はそれぞれ取り消しの1ステップである。読み込みと保存のたびに、文書の `progress` が件数と違っていても件数の方で上書きする。最後の1件を消したときは `todos` を外し、その直前の進捗率を残す。0 には戻さない。そのあと進捗率を手で直せる。左のタスク行では、項目があるときだけ名前の直後に `3/6` を出す。HTML、SVG、書き出しのチャートには項目を出さない。バーの濃い部分は、件数から決めた進捗の幅のままである。

**制約** TODO の文は1行で、前後の空白だけは除く。空白だけ、改行を含む文は保存しない。進捗率からステータスや色は変えない。絞り込みの対象にしない。マイルストンには付けない。Excel のチェックボックスにはしない。

### EDIT-23 前後ではない繋がり

**操作** 1件選んでいるとき、詳細パネルの「繋がり」の「足す」でダイアログを開き、相手のタスクと言葉を書いて確定する。言葉を直す。外す。円弧の上を右クリックして「繋がりを外す」。円弧の上で Delete または Backspace を押す（タスクやマイルストンの上でなければ）。詳細とチャートから外す。複製ダイアログと一括パネルからは足さない。

**挙動** 詳細パネルでは、マイルストンと前後関係のあとに「繋がり」を出す。既にある組は、相手のタスク名、言葉の欄、外すボタンで並ぶ。「足す」で「繋がりを足す」ダイアログが開く。開いているタスクの名前を出し、相手は名前の一部で探す。候補には場所と名前を出す。言葉の欄は、相手を選ぶ前から出す。確定するまで文書は変えない。相手が未選択なら「相手のタスクを選んでください。」、言葉が空または空白だけなら理由を出し、ダイアログは開いたままにする。確定のとき、選んだ相手が文書に無ければ足さず「相手のタスクが見つかりません。」と出し、相手の選択は外してダイアログは開いたままにする。同じ2タスクの組、自分自身、は足さず、理由を出す。確定できたときは取り消しの1ステップで足し、ダイアログを閉じる。キャンセルと、候補一覧が閉じているときの Escape では足さない。候補一覧が開いている Escape は一覧だけ閉じる。検索欄の Enter は候補を選ぶだけで、確定にはしない。検索欄の上下矢印は、変換中は候補の強調を動かさない。言葉の欄の Enter は、変換中でなければ確定する。詳細の言葉欄で空または空白だけを確定しようとしたときは理由を出し、欄は保存済みの言葉に戻す。前後の空白だけを足して保存済みと同じ言葉になるときも、欄は保存済みの言葉に戻す。言葉の変更と1組を外すは、それぞれ取り消しの1ステップである。同じ2タスクの組は1つだけである。保存すると、開いているタスクを `taskIds` の先、相手を後に書く。並びは方向ではない。開いているタスクが変わったとき、および2件以上の選択に変わったときは、確定せずダイアログを閉じる。チャートでは、前後の線と同じ当たりのしきい値で円弧を当てる。前後の線と円弧が両方近いときは、近い方だけを1本取る。右クリックの「繋がりを外す」は確認しない。ツールバーの「削除」はタスクを消す。

**制約** 言葉は前後の空白を除く。空と空白だけでは保存せず、理由を出す。自分自身とは組めない。繋がり専用の絞り込みは付けない。「前後: 破綻のみ」ではこの円弧を消さない。タスクを消すと、そのタスクを含む組だけ JSON から外れる。残ったタスク同士はつなぎ直さない。

### SET-01 表示サイズ

**操作** 設定の「表示」で「自動」「50%」「75%」「100%」「125%」「150%」「200%」を選ぶ。⌘ または Ctrl と + または = で一段大きくする。⌘ または Ctrl と − で一段小さくする。テンキーの + と − も同じである。Shift を押して文字が + になる押し方も拡大である。

**挙動** 文字、行、ボタンの大きさを変える。初回起動の既定は 100% である。保存値が無いときも 100% として読む。「自動」は、幅 1100px、高さ 780px を基準に、それより大きいウィンドウで最大 200% まで広げる。基準以下では 100% のままである。行の密度は「標準」と「詰める」から選び、チャートの行の高さだけを変える。イナズマ線の表示のオンオフと、左一覧の追加列も同じ「表示」に置く。追加列は、開始、終了、日数、進捗、ステータスである。選んだ値（`auto` を含む）は localStorage に残り、次の起動でも使う。ショートカットは一段ずつ変え、押し続けは keydown の繰り返しで、端では止まる。固定の段は隣へ進む。200% で拡大しても 200%、50% で縮小しても 50% のままである。自動のときは、その場の倍率を小数第2位で段と比べ、自動をやめて固定の段にする。一致する段は、その段にいるものとして隣へ進む。拡大は今の倍率より大きい段のうちいちばん小さい段で、無ければ 200% を保存して自動をやめる。縮小は今の倍率より小さい段のうちいちばん大きい段で、無ければ 50% にする。端で段が変わらないときは保存値も変えない。設定の「表示」が開いていれば、選択は新しい段を示す。検索欄、入力欄、選択欄、ボタン、開いているダイアログの中でも変わる。このキーでは、ブラウザのページズームとデスクトップ版の WebView のズームは起こさない。右クリックメニューは閉じる。線を引くモードは終わらない。追加列は、開始と終了を `09/19` のように月と日で、日数を `12日`、進捗を `30%`、ステータスは一覧の表示名で出す。開始、終了、日数、進捗、ステータス、超過、担当は、行をまたいで同じ位置に揃う。超過が無い行もその幅を空ける。担当が列の幅を超えるときは省略し、マウスを乗せると全文が出る。初期はどれも出さない。保存値に `status` のキーが無いときは、ステータス列はオフとして読む。ダイアログの幅と文字も表示サイズに追従する。

**制約** チャートのズーム（NAV-02）とは別である。固定値は 50% 未満、200% 超にはできない。修飾キーの無い +、=、−、Alt が付いた組み合わせ、Shift で `_` になる押し方、⌘0 や Ctrl+0 では変えない。スケジュール、取り消し、選択、絞り込み、折りたたみ、1日あたりの幅、左一覧の基準幅は変わらない。デスクトップ版では、同じオリジンの localStorage を他のウィンドウが読み直す。

### SET-08 ステータス

**操作** 設定の「ステータス」で、「取り込み…」でステータス一覧 JSON を足す。一覧のラジオボタンで使う一覧を選ぶ。「選択を解除」で未選択に戻す。各一覧の「外す」で消す。「項目を編集…」で設定を閉じ、主画面の覆いを開く。覆いのあいだは、絞り込み、追加、スケジュールの保存など、覆いの下の操作はできない。

**挙動** ステータス一覧 JSON（[データ仕様](data-format.md#ステータス一覧-jsonschemaversion-2)）を検証して保存する。schemaVersion 1 は読み込み時に 2 へ移す。ID はファイル名から作り、同じ ID が既にあるときは上書きを確認する。選んだ一覧の項目が、バーの色、詳細パネルと一括パネルと複製ダイアログの選択肢、絞り込みの選択肢、Excel の「ステータス」列の名前になる。未選択のときは、未着手・進行中・完了の三件を使う。初回は、この三件を `standard` として一度だけ入れて選ぶ。外したあとは、自動では戻さない。複製と追加のステータスの初期値は、一覧にある `not-started`、無ければ扱いが完了でない最初の項目、それも無ければ最初の項目である。

**制約** スケジュール JSON には一覧を書かない。タスクが持つのは `id` だけである。1件の上限は 2MB。デスクトップ版では、取り込みや選択の変更を他のウィンドウへ知らせ、受けた側はアプリデータを読み直す。FILE-10 で設定ファイルを開いたウィンドウでは、取り込み、一覧の選択、外しは出さない。`statuses` のファイルを読めているときだけ「項目を編集…」を出す。パスが無いときは組み込みの三件を使う。読み込みに失敗したときは設定にその旨を出し、バーの色と選択肢は組み込みの三件に戻す。アプリデータで選んでいる一覧には戻さない。

**項目の編集** 主画面の覆いで直す。見出しの右に「閉じる」がある。説明の次の行に、このウィンドウのチャートがどの一覧を使っているかを出す。項目の一覧だけがスクロールし、「項目を足す」「保存」「編集を戻す」「JSON を書き出す」は足元に固定する。

ユーザ設定モードでは、「編集する一覧」で取り込み済みを選ぶ。横に「新しい一覧」「コピーして作る」「外す」がある。「新しい一覧」は組み込みの未着手・進行中・完了から、アプリデータの取り込み済みに一覧を足す。作っただけでは使用中にしない。「コピーして作る」は、選んでいる一覧の画面（下書きを含む）を写して同じ手順で足す。一覧を選んでいないときは押せない。どちらも一覧 ID は空いている `custom`、`custom-2` のように決める。作ったあとはその一覧を覆いで開く。「外す」は、選んでいる一覧を設定の「外す」と同じ手順でアプリデータから消す。一覧を選んでいないときは押せない。確認のあと進めたとき、覆いは閉じない。残っている一覧があれば、その並びの先頭を覆いで開く。無ければ一覧の選択は無い。使用中の一覧を外したときは未選択に戻り、チャートは組み込みの三件になる。下書きがあるときの確認では、下書きを保存しないことを伝える。チャートで使っている一覧のときは、外すと組み込みの三件に戻ることを伝える。ファイルへ出すのは足元の「JSON を書き出す」だけである。設定の「取り込み…」は今どおりファイルから足す。

設定ファイルモードでは、一覧の切り替えと新規・コピーは出さない。設定ファイルの `statuses` のファイルだけを直す。「保存」は、このウィンドウが開いている設定ファイルに書かれた `statuses` の実パスだけを上書きし、このウィンドウのチャートを読み直す。アプリデータの使用中は変えない。同じファイルの編集は、デスクトップ版では同時に一つのウィンドウだけである。

項目ごとに表示名、扱い、ライトとダークの地と枠の色を直し、行を選んで右の説明と指示を書き、「上へ」「下へ」で並びを変え、「削除」で外せる。説明はその `id` を選ぶ状態だけを書く。指示は空でもよく、選んだあとに LLM が守ることだけを書く。各行には、その項目の説明を1行だけ出す。右には、選んでいる項目の表示名と、説明と指示を書く欄を出す。行のどこを押してもその行を選ぶ。扱い、色、表示名、`id`、上へ、下へ、削除を押したときは、その操作を行い、焦点はそのコントロールに残る。余白と行の説明と扱いの一文を押したときは、選んだあと右の説明欄へ焦点を移す。選んでいる行は左にアクセントの帯を出す。扱いは未着手、着手済み、完了、管理外のいずれか一つで、行の中で選び、選んでいる扱いの説明を扱いの直下に2行で出す。説明は全角32字相当の幅で折り返し、常に2行分の高さを取る。幅を変えても行数と色・操作の位置は変わらない。極端に狭いときだけ末尾を省略する。覆いを開いてから閉じるまで、⌘/Ctrl+Z で取り消し、⌘/Ctrl+Shift+Z または Ctrl+Y でやり直しができる。対象はこの覆いの下書きだけである。スケジュールの取り消しは動かない。文字欄に焦点があるときも、ブラウザの取り消しではなくこの履歴を使う。macOS の編集メニューの取り消しとやり直しも同じ履歴を使う。下書きを捨てるなどの確認が出ているあいだは、取り消しもやり直しも動かない。指示は空でも保存できる。別の扱いにポインタを乗せる、またはキーボードの焦点を移したあいだは、値は変えず説明だけ差し替える。「項目を足す」で足した項目は、`id` も決められる（`status-N` が入る）。説明は空で、焦点は説明欄へ移る。足す項目の既定の扱いは着手済みである。保存した項目の `id` は変えられない。「保存」は、開いている一覧またはファイルの本文だけを上書きする。ユーザ設定モードで使用中の一覧を保存したときだけ、このウィンドウと同じ一覧を使うほかのウィンドウのチャートが変わる。使用中の切り替えは設定のままである。「編集を戻す」は保存前の状態に戻す。「JSON を書き出す」は、編集中の内容を一覧 JSON として書き出す（デスクトップ版は保存ダイアログ、ブラウザ版はダウンロード）。書き出しだけでは使用中は変えない。狭い幅では右の欄を一覧の上に重ね、一覧だけがスクロールする。

下書きがあるときに覆いを閉じる、別の一覧を選ぶ、「新しい一覧」の前には、下書きを捨てるかを聞く。「コピーして作る」で下書きがあるときは、元の一覧には保存しないことを確認する。確認の Escape は確認だけをやめ、覆いは閉じない。スケジュールの未保存は確認に出さない。デスクトップ版のユーザ設定モードでは、同じ一覧 ID の編集は同時に一つのウィンドウだけである。別のウィンドウが編集中のときは、そのウィンドウを前面にし、このウィンドウでは一覧を選ばない。設定ファイルモードでは、同じ `statuses` ファイルの編集も同様である。編集中にその一覧を設定で外したときは、下書きを捨てて覆いを閉じ、短い知らせを出す。設定でその一覧を取り込み上書きしたときは、保存済みの項目と違う内容だけ下書きを捨てて読み直し、覆いは開いたままにする。ほかのウィンドウがメンバーなど別の設定を変えても、開いている一覧の本文が同じなら下書きは残す。

**項目の編集の制約** 項目は最後の1件を外せない。表示名と説明が空白だけのとき、`id` が空か重複するときは、保存と書き出しができず、理由を出す。項目を外したり `id` を変えたりしても、タスクの `status` は書き換えない。その `id` のタスクは、一覧に無い `id` として扱う（VIEW-02）。

### SET-09 色

**操作** 設定の「色」で、「取り込み…」で色の一覧 JSON を足す。一覧のラジオボタンで使う一覧を選ぶ。「選択を解除」で未選択に戻す。各一覧の「外す」で消す。「項目を編集…」で設定を閉じ、主画面の覆いを開く。覆いのあいだは、覆いの下の操作はできない。

**挙動** 色の一覧 JSON（[データ仕様](data-format.md#色の一覧-jsonschemaversion-1)）を検証して保存する。選んだ一覧の項目が、左一覧とチャートの行の地、詳細パネルと一括パネルと複製ダイアログの「色」になる。未選択のときは行の地を塗らず、「色」も出さない。組み込みの一覧は置かない。

**制約** スケジュール JSON には一覧を書かない。タスクが持つのは `colorId` だけである。1件の上限は 2MB。項目は 8 件まで。項目に扱いや枠の色、LLM 向けの指示は無い。項目は名前、ライトとダークの地、説明だけである。デスクトップ版では、取り込みや選択の変更を他のウィンドウへ知らせ、受けた側はアプリデータを読み直す。FILE-10 で設定ファイルを開いたウィンドウでは、取り込み、一覧の選択、外しは出さない。`colors` のファイルを読めているときだけ「項目を編集…」を出す。パスが無いときは「色の一覧を作る」で、設定ファイルと同じフォルダに JSON を書き、`colors` の相対パスを足す。読み込みに失敗したときは設定にその旨を出し、作成も編集も出さない。覆いのあいだは背面のワークスペースは操作できない。覆いを開いているあいだは、スケジュール JSON の外部ファイルの即時反映を止める。SYNC-01 で読み直す、または「両方を画面へ反映」する前には、確定せず閉じる。外部ファイルの読み直しで覆いを閉じたときは、設定は開かない。

**項目の編集** 主画面の覆いで直す。見出しは「色の一覧の項目を編集」。ステータス項目の編集（SET-08）と同じ流れで、一覧の選択、新しい一覧、コピー、外し、項目の追加と並べ替えと削除、保存、編集を戻す、JSON の書き出し、下書きの取り消しを持つ。扱いと指示は無い。地の色は「ライト 地」と「ダーク 地」である。説明はその `id` を選ぶ状態だけを書く。色の値は説明に書かない。8 件のとき「項目を足す」は押せない。最後の 1 件は消せない。保存した項目の `id` は変えない。足した直後で、まだ保存していない項目の `id` だけは変えられる。使用中の一覧を外したときは、行を塗らなくなることを確認する。設定ファイルモードでは、そのファイルだけを上書きする。同じファイルの編集は同時に一つのウィンドウだけである。項目を消しても、タスクの `colorId` は書き換えない。設定ファイルを読み直しても、色の項目が保存済みと同じなら下書きを残す。違うときだけ読み直す。

ユーザ設定モードでは、「編集する一覧」で取り込み済みを選ぶ。横に「新しい一覧」「コピーして作る」「外す」がある。「新しい一覧」は、項目が 1 件の下書き（名前「新しい色」、説明「この色にする」、ライトの地 `#E2E6ED`、ダークの地 `#454b5c`）をアプリデータの取り込み済みに足す。組み込みの三件やステータス一覧からは写さない。作っただけでは使用中にしない。「コピーして作る」は、選んでいる一覧の画面（下書きを含む）を写して同じ手順で足す。一覧を選んでいないときは押せない。どちらも一覧 ID は空いている `custom`、`custom-2` のように決める。作ったあとはその一覧を覆いで開く。「外す」は、選んでいる一覧を設定の「外す」と同じ手順でアプリデータから消す。一覧を選んでいないときは押せない。確認のあと進めたとき、覆いは閉じない。残っている一覧があれば、その並びの先頭を覆いで開く。無ければ一覧の選択は無い。使用中の一覧を外したときは未選択に戻り、行の地は塗らなくなる。下書きがあるときの確認では、下書きを保存しないことを伝える。チャートで使っている一覧のときは、外すと行を塗らなくなることを伝える。ファイルへ出すのは足元の「JSON を書き出す」だけである。設定の「取り込み…」は今どおりファイルから足す。

設定ファイルモードでは、一覧の切り替えと新規・コピーは出さない。設定ファイルの `colors` のファイルだけを直す。「保存」は、このウィンドウが開いている設定ファイルに書かれた `colors` の実パスだけを上書きし、このウィンドウのチャートを読み直す。アプリデータの使用中は変えない。

**項目の編集の制約** 表示名と説明が空白だけのとき、`id` が空か重複するときは、保存と書き出しができず、理由を出す。

### SET-10 拡張項目

**操作** 設定の「拡張項目」で、「取り込み…」で定義を足す。取り込み済みの一覧でチェックボックスを使い、複数選ぶ。各定義の「外す」で消す。「項目を編集…」で主画面の覆いを開き、定義を直す。

**挙動** 拡張項目 JSON を検証して保存する。プラグイン ID は JSON の `id` である。同じプラグイン ID が既にあるときは上書きを確認する。選んだ順に合成キー `プラグインID_項目ID` を画面へ載せる。各拡張の中はファイルの項目の順である。すでに選んでいる拡張どうしで合成キーが重なるものは、同時に選べない。理由を設定に出す。詳細パネル、絞り込み、帯では、選んでいる拡張の項目だけを定義として使う。定義に無いキーは文字列と値をそのまま見せ、編集できない。絞り込みの候補にも出さない。

覆いはステータス項目の編集（SET-08）と同じ作りである。見出しの右に「閉じる」が一つある。利用者が覆いを閉じたときは、設定の「拡張項目」を開き直す。外部ファイルの読み直しで覆いを閉じたときは、設定は開かない。ユーザ設定では、「編集する拡張」をラジオで選び、右に「新しい拡張」「コピーして作る」「外す」がある。ラジオの表示は、保存済みの拡張の名前のうしろにプラグイン ID を括弧で添える。編集中の下書きには追従しない。編集枠の上端に「拡張の名前」と「プラグイン ID」があり、項目一覧だけがスクロールする。プラグイン ID と項目 ID を変えると、スケジュール上の既存の値は未登録の追加項目として残る旨を、その近くに出す。「項目を足す」「保存」「編集を戻す」「JSON を書き出す」は枠の足元に固定する。「新しい拡張」は空いている `custom`、`custom-2` をプラグイン ID にし、項目が1件の下書きを足す。アプリデータへ書いた直後にラジオへ出て選ばれ、別の拡張を選んだあともそのラジオから戻れる。作っただけでは使用中にしない。作成に失敗したときは理由を出す。「コピーして作る」は、選んでいる拡張の画面を写して同じ手順で足す。足したあとは同じくラジオへ出て選ばれる。選んでいないときは押せない。「外す」は設定の「外す」と同じで、覆いは閉じない。下書きがあるときに「新しい拡張」「コピーして作る」、別の拡張を選ぶ、覆いを閉じる前には、下書きを捨てるかを聞く。捨てたあとは、選んだ操作を続ける。プラグイン ID は保存後も変えられる。取り込み済みと重なる ID には保存できない。ユーザ設定で ID を変えたときは、新しい ID のファイルを書いてから古いファイルを消し、使用中だった拡張は新しい ID のまま使用中にする。この覆いで足した項目の ID だけその場で変えられ、保存した項目 ID は変えない。「新しい拡張」で足した最初の1件は、覆いで最初に保存するまで ID を変えられる。プラグイン ID と項目 ID に `_` と前後の空白は使えない。拡張の画面の名前は直せる。項目が0件の拡張は保存できない。

「保存」は、その拡張 JSON の本文だけを上書きする。開いているスケジュールの `fieldValues` は書き換えない。項目を外したキーは未登録の追加項目になる。型や候補が合わなくなった値は、スケジュールの上書き保存と別名保存を止める。値そのものは消さない。詳細では、その欄を空に戻せる。拡張の読み込みが終わるまで、絞り込みの記録から追加項目の条件は削らない。デスクトップ版のユーザ設定と設定ファイルの編集用では、同じ拡張ファイルの編集は同時に一つのウィンドウだけである。別のウィンドウが編集中のときは、そのウィンドウを前面にし、このウィンドウでは覆いを開かない。「編集を戻す」は保存前に戻す。「JSON を書き出す」は下書きを拡張 JSON として出す。保存した拡張が、すでに選んでいる別の拡張と合成キーが重なるときは、保存せず理由を出す。覆いを開いてから閉じるまで、⌘/Ctrl+Z で取り消し、⌘/Ctrl+Shift+Z または Ctrl+Y でやり直しができる。対象はこの覆いの下書きだけである。スケジュールの取り消しは動かない。新しく作るタスクの初期値は、選んでいる拡張のデフォルトだけを入れる。既にあるタスクと複製には入れない。

設定ファイルで開いたウィンドウでは、取り込み、選択、外す、新しい拡張、コピーは出さない。`fieldExtensions` に書いた拡張はピン留めのプラグインとして読み取り専用で示し、覆いでは直さない。ステータス（SET-08）は、設定ファイルの `statuses` が指す一覧が一つなので、読めているときは今どおりそのファイルだけを覆いで直す。編集用の拡張は、設定ファイルの `editableFieldExtension` が指すファイルが一つだけである。無いときは「編集用の拡張を作る」で、フォルダに拡張 JSON を新しく書き、その相対パスを設定ファイルに足す。あるときは「項目を編集…」で覆いを開き、ユーザ設定の覆いと同様に項目を自由に直せる。「保存」はそのパスだけを上書きする。プラグイン ID を変えてもパスは変わらない。ピン留めと同じプラグイン ID には保存できない。「消す」は確認のあと、設定ファイルから `editableFieldExtension` を外し、そのファイルを消す。ピン留めの配列は触らない。アプリデータには書かない。編集用のファイルを読めないときは「編集用の参照を外す」で、設定ファイルから `editableFieldExtension` だけを外せる。

**制約** スケジュール JSON に `fields` は書かない。1件の上限は 2MB。読み込みに失敗すると見出しにエラーを出す。デスクトップ版では、取り込みや選択の変更を他のウィンドウへ知らせる。FILE-10 で設定ファイルを開いたウィンドウでは、取り込み、選択、外すは出さず、`fieldExtensions` に書いたピン留めの拡張を読み取り専用で示す。`editableFieldExtension` と `fieldExtensions` に同じ相対パスは書けない。設定ファイルに同じプラグイン ID の拡張を二つ書くことはできない。覆いのあいだは背面のワークスペースは操作できない。覆いを開いているあいだは、外部ファイルの即時反映を止める。読み直しの前には、確定せず閉じる。必須で値が空のタスクがあるときは、上書き保存と別名保存を拒否する。開くときの検証は通す。

### SET-02 メンバー

**操作** 設定の「メンバー」で、「取り込み…」でカタログを足す。一覧のラジオボタンで使うカタログを選ぶ。「選択を解除」で未選択に戻す。各カタログの「外す」で消す。「項目を編集…」で設定を閉じ、主画面の覆いを開く。覆いのあいだは、絞り込み、追加、スケジュールの保存など、覆いの下の操作はできない。

**挙動** メンバー JSON を検証してカタログとして保存する。カタログの ID はファイル名から作り、同じ ID のカタログが既にあるときは上書きを確認する。選んだカタログの人が、詳細パネルと一括パネルと複製ダイアログの担当候補、左一覧の表示名、絞り込みの担当者欄になる。使用中のカタログ名は、設定と見出しに出る。「外す」はそのカタログを消し、使用中だったなら未選択に戻す。初回はサンプルのメンバーを一度だけ入れる。削除したあとは、自動では戻さない。

**制約** スケジュール JSON にはメンバーを書かない。1件の上限は 2MB。読み込みに失敗すると見出しに「メンバー設定エラー」を出す。ブラウザの保存領域に書けないときは、その旨を設定画面に出す。デスクトップ版では、取り込みや選択の変更を他のウィンドウへ知らせ、受けた側はアプリデータを読み直す。FILE-10 で設定ファイルを開いたウィンドウでは、取り込み、カタログの選択、外すは出さない。`members` のファイルを読めているときだけ「項目を編集…」を出す。パスが無い、読み込みに失敗したときは編集も出さない。覆いのあいだは背面のワークスペースは操作できない。覆いを開いているあいだは、スケジュール JSON の外部ファイルの即時反映を止める。SYNC-01 で読み直す、または「両方を画面へ反映」する前には、確定せず閉じる。外部ファイルの読み直しで覆いを閉じたときは、設定は開かない。

**項目の編集** 主画面の覆いで直す。見出しは「メンバーの項目を編集」。ステータス項目の編集（SET-08）と同じ流れで、カタログの選択、新しいカタログ、コピー、外し、人の追加と並べ替えと削除、保存、編集を戻す、JSON の書き出し、下書きの取り消しを持つ。人ごとに `id`、表示名、任意の説明だけである。説明はその `id` を選ぶ担当だけを書く。表示名は、この選び方には使わない。指示欄は無い。

ユーザ設定モードでは、「編集するカタログ」で取り込み済みを選ぶ。横に「新しいカタログ」「コピーして作る」「外す」がある。「新しいカタログ」は、人が0人の下書きをアプリデータの取り込み済みに足す。作っただけでは使用中にしない。「コピーして作る」は、選んでいるカタログの画面（下書きを含む）を写して同じ手順で足す。カタログを選んでいないときは押せない。どちらもカタログ ID は空いている `custom`、`custom-2` のように決める。作ったあとはそのカタログを覆いで開く。「外す」は、選んでいるカタログを設定の「外す」と同じ手順でアプリデータから消す。カタログを選んでいないときは押せない。確認のあと進めたとき、覆いは閉じない。残っているカタログがあれば、その並びの先頭を覆いで開く。無ければカタログの選択は無い。使用中のカタログを外したときは未選択に戻る。下書きがあるときの確認では、下書きを保存しないことを伝える。チャートで使っているカタログのときは、外すと担当の解決が無くなることを伝える。ファイルへ出すのは足元の「JSON を書き出す」だけである。設定の「取り込み…」は今どおりファイルから足す。

設定ファイルモードでは、カタログの切り替えと新規・コピーは出さない。設定ファイルの `members` のファイルだけを直す。「保存」は、このウィンドウが開いている設定ファイルに書かれた `members` の実パスだけを上書きし、このウィンドウの担当表示を読み直す。同じ設定ファイルを開いている他のウィンドウへも読み直しを送る。アプリデータの使用中カタログは変えない。

人ごとに `id` と表示名を直し、行を選んで右の説明を書き、「上へ」「下へ」で並びを変え、「削除」で外せる。並びは、詳細パネルと複製と一括の「担当」の順である。各行には、空でない説明を1行だけ出す。行のどこを押してもその行を選ぶ。選んでいる行は左にアクセントの帯を出す。覆いを開いてから閉じるまで、⌘/Ctrl+Z で取り消し、⌘/Ctrl+Shift+Z または Ctrl+Y でやり直しができる。対象はこの覆いの下書きだけである。スケジュールの取り消しは動かない。「人を足す」で足した人は、`id` も決められる（`member-N` が入る）。説明は空で、焦点は説明欄へ移る。保存した人の `id` は変えられない。「保存」は、開いているカタログまたはファイルの本文だけを上書きする。ユーザ設定モードで使用中のカタログを保存したときだけ、同じカタログを使うウィンドウの担当表示が変わる。使用中の切り替えは設定のままである。「編集を戻す」は保存前の状態に戻す。「JSON を書き出す」は、編集中の内容をメンバー JSON として書き出す（デスクトップ版は保存ダイアログ、ブラウザ版はダウンロード）。書き出しだけでは使用中は変えない。

下書きがあるときに覆いを閉じる、別のカタログを選ぶ、「新しいカタログ」の前には、下書きを捨てるかを聞く。「コピーして作る」で下書きがあるときは、元のカタログには保存しないことを確認する。デスクトップ版のユーザ設定モードでは、同じカタログ ID の編集は同時に一つのウィンドウだけである。別のウィンドウが編集中のときは、そのウィンドウを前面にし、このウィンドウではカタログを選ばない。設定ファイルモードでは、同じ `members` ファイルの編集も同様である。編集中にそのカタログを設定で外したときは、下書きを捨てて覆いを閉じ、短い知らせを出す。設定でそのカタログを取り込み上書きしたときは、保存済みの人と違う内容だけ下書きを捨てて読み直し、覆いは開いたままにする。設定ファイルを読み直しても、人の内容が保存済みと同じなら下書きを残す。違うときだけ読み直す。

**項目の編集の制約** 表示名と説明が空白だけのとき、`id` が空か重複するときは、保存と書き出しができず、理由を出す。人を外しても、タスクの `assigneeId` は書き換えない。その `id` の担当は、一覧に無い id として扱う（VIEW-10）。

### SET-03 稼働日

**操作** 設定の「稼働日」で「取り込み…」または「外す」を押す。

**挙動** カレンダー JSON を1件だけ保存する。既にあるときは上書きを確認する。未設定のときは「使用中: 未設定（土日を塗る）」と出る。外すと未設定に戻る。検証や読み込みに失敗したときは土日表示に戻し、見出しに「カレンダー設定エラー」を出す。

**制約** スケジュール JSON には書かない。タスクの日付は暦日のままである。上限は 2MB。ブラウザの保存領域に書けないときは、本文と表示名のどちらも残さない。設定画面にその旨を出す。デスクトップ版では、取り込みや外しを他のウィンドウへ知らせ、受けた側はアプリデータを読み直す。FILE-10 で設定ファイルを開いたウィンドウでは、取り込みと外すは出さず、その設定ファイルの状態だけを読み取り専用で示す。

### SET-04 配色

**操作** 設定の「表示」で「システム設定に合わせる」「ライト」「ダーク」を選ぶ。

**挙動** 画面全体の色を変える。ライトは従来どおりの明るい配色である。ダークは暗い灰を基調にし、文字と区切りが読める配色にする。HTML と SVG の書き出しは、書き出した時点の画面と同じ配色にする。「システム設定に合わせる」では OS の明るさ設定（`prefers-color-scheme`）に従い、ダークならダーク、それ以外はライトにする。この選択中に OS の設定が変わったら、再起動しなくても画面を追従させる。「ライト」と「ダーク」は OS の設定より優先する。選んだ値は localStorage に残り、次の起動でも使う。「システム設定に合わせる」に戻すと保存値は消える。

**制約** チャートのズーム（NAV-02）と表示サイズ（SET-01）とは別である。スケジュール JSON には書かない。デスクトップ版では、同じオリジンの localStorage を他のウィンドウが読み直す。

### SET-05 JSON作成スキルを置く

**操作** 設定の「JSON作成スキルを置く」で、Cursor、Claude Code、GitHub Copilot のうち置く先を1つ以上選び、ユーザー全体か指定したフォルダかを選び、「置く」を押す。指定したフォルダのときは「フォルダを選ぶ…」で1つ示す。置く先を1つも選んでいないときは「置く」と「外す」は押せない。「外す」で、同じ選び方の場所から5つを削除する。

### SET-06 自動更新

**操作** デスクトップ版の設定の「更新」で「起動時に更新を確認する」をオンまたはオフにする。同じ欄の「更新を確認」で、その場で確認する。同じ欄の「変更履歴」で、同梱の CHANGELOG を読む。Windows と Ubuntu では、同じ欄の「インストーラを保存」で、公開中のベータの、この OS 用インストーラを別名保存する。手動の確認は、☰ の「更新を確認」、コマンドパレット、macOS のアプリメニューからも始められる。自動更新のオンオフに関係なく使える。

**挙動** 既定はオフである。保存値が無いときもオフとして読む。オフのときは、起動時の確認も入れ直しもしない。オンにした直後のその場では確認しない。次の起動で、起動時に読んでいた値がオンのときだけ、起動復旧が終わったあとに、ビルドに含まれる確認先の `updater-X` Release が載せる `latest.json` を見る。開いているウィンドウがすべて起動復旧を終えたあと、プロセスで1回だけ確認する。あとから開いたウィンドウでは確認しない。入っている版と同じメジャーの、より新しい安定版があり、署名が合うときは、すぐ入れ直さず、前面ウィンドウの状態バー直上に知らせを出す。文言は版番号付きで、「あとで」と「入れ直す」を選べる。設定ダイアログが開いているあいだ、または「更新」以外の節を見ているあいだは隅の知らせは出さず、同じ内容は「更新」欄だけに出す。設定を閉じ、まだ選んでいなければ隅だけに戻す。欄で選んだあとは隅は出さない。知らせは背面の操作を止めない。ダイアログの背面に残る。前面が替わったら知らせを移す。一つのウィンドウで「あとで」または「入れ直す」を選んだら、ほかのウィンドウからも消す。アプリが背面にあるときに知らせを出すときは、同じ文言の OS 通知を1回だけ出す。押すとそのウィンドウを前面にする。通知からは入れ直さない。「あとで」は、その起動では入れ直しを始めない。同じ起動の自動確認は繰り返さない。「入れ直す」のあと、終了時と同じ未保存の扱いに入る。入れ直しの途中は同じ箱に進行の文言だけを出す。メジャーが違う版、リモートがベータ、同じか古い版は入れない。`updater-X` がまだ無いとき、または上の条件で入れないときは、更新なしとして扱い、知らせは出さない。`latest.json` に Ubuntu 用の `linux-x86_64` または macOS（GitHub Releases 版）用の `darwin-aarch64` が無いときは失敗として扱う。起動時の自動確認では、隅に短く「更新の確認に失敗しました」を出す。手動の「更新を確認」では同じ文言を欄または隅に出す。GitHub Releases から入れた Windows 版で `latest.json` に `windows-x86_64` が無いときは、起動時の入れ直しの知らせは出さない。手動の「更新を確認」では、安定版は Microsoft Store で入手・更新する旨を欄または隅に出す。通信など、その他の確認失敗は、起動時は更新なしと区別できるときだけ隅に短く出し、手動では「更新の確認に失敗しました」。手動の「更新を確認」は、入れ直す版があるときは起動時と同じ知らせにする。無いときは「この版が最新です」。macOS（GitHub Releases 版）の入れ直しに管理者の確認は出ない。入れ直しで届く .app には隔離属性は付かず、入れ直し後の起動で Gatekeeper の警告は出ない。初回の Gatekeeper の警告は、dmg からアプリケーションフォルダへ入れたときだけ出る。確認中、入れ直し中、知らせが残っているあいだは、もう一度通信しない。押したときは今の表示を残す。ボタンは無効にしない。ダウンロード、入れ直しに失敗したときは、今の版のまま使う。失敗は画面の隅に短く出す。選んだ値は localStorage に残り、デスクトップ版では開いているウィンドウで同じになる。起動時には変更履歴を出さない。設定の「更新」を開いたとき、同梱の CHANGELOG の版の節を、ファイルの並びのまま新しい版からすべて出す。`[Unreleased]` とファイル冒頭の説明は出さない。各項目の Issue 番号はリンクである。履歴は欄の中だけでスクロールする。自動更新のオンオフや、手で入れたか自動更新かでは、履歴の有無を分けない。出る節は、入れている版に同梱されたものまでである。ベータの保存は、入っている版より新しい公開ベータがあるときだけファイルを選ばせる。保存したあとは欄にパスを出す。インストーラは起動しない。入れ直しもしない。安定版の入れ直し中に押しても保存は始めない。

**操作** 設定を開く。

**挙動** ダイアログの下に、左の欄を切り替えなくても、どのセクションでも同じ位置に今の版を 1 行出す。文言は `バージョン 1.3.1` の形である。番号の前に `v` は付けない。届いた文字列の先頭が `v` または `V` のときは外して出す。行は操作を持たない。押しても設定は閉じず、変更内容も開かない。文字列は選択してコピーできる。取得が終わるまで行は出さない。空文字、または取得に失敗したときは「バージョンを取得できませんでした」と出す。状態バーや隅の通知には出さない。設定を初めて開いたときに 1 回だけ読み、閉じてもう一度開いても取り直さない。デスクトップ版は `package_info` と同じ版番号である。ブラウザ版は `package.json` の `version` である。

### MCP-01 画面の状態を MCP で渡す

**操作** デスクトップ版の設定の「画面の状態を渡す」で、mcp.json に貼る JSON をコピーし、Cursor または Claude の mcp.json へ貼る。同じバイナリを `--mcp` で起動するのは、登録したクライアントである。設定からプロセスは起動しない。

**挙動** 開いているアプリ向けに、読み取り 7 ツールと `replace_schedule` を返す。まとめて呼ぶ必要はない。`replace_schedule` の引数はスケジュール JSON 全体である。

| `filtered_tasks` | オンになっている絞り込み条件と、それで残るタスク（折りたたみで行が隠れていてもタスクは減らさない）。帯の線はタスクを減らさない |
| `current_schedule` | 画面の確定したスケジュール JSON 全体。保存するときと同じ形。ディスク上のファイルは読まない。未保存の画面を返す |
| `replace_schedule` | 引数のスケジュール JSON 全体で、前面ウィンドウの確定した文書を置き換える（下記）。成功時は FILE-07 と同じ差分テキストだけ。確認ダイアログは出さない |

`replace_schedule` は、デスクトップ版の前面ウィンドウだけを対象にする。起動中に開いているスケジュールを変える依頼はここへ渡し、新しいスケジュールファイルの作成や、アプリが起動していないときのファイル書きには使わない。開くときと同じ検証に通ったときだけ画面の文書を置き換える。ディスク上のファイルは書かない。置き換えは取り消しの 1 ステップである。保存形式で今の画面と同じ内容のときは、未保存の判定を変えず、履歴にも積まない。成功時の差分は、置き換え後の画面と開いているファイルの FILE-07 差分である。パスが無いときは「比べるファイルがありません」を返し、失敗にはしない。差分テキストが応答の上限を超えたときは、置き換えは戻さず「差分が大きすぎるため、差分テキストは返せません。」を返し、失敗にはしない。絞り込み、折りたたみ、ズーム、スクロール、系統は変えない。選択中のタスクが新しい文書にあれば選択を残し、無いときだけ外す。外部更新を画面に残しているときの「ファイルに更新あり — 確認する」は消さない。同じファイルを開いている他のウィンドウは変えない。内容が変わったときだけ、約 4 秒「画面を置き換えました」と隅に出す。SYNC-01 で衝突がある確認だけが開いているときは置き換えられ、成功して画面が変わったときは確認を閉じ、約 4 秒「画面に反映しました。内容を確認して、問題なければ保存してください。」と出す。起点と同じ内容だけのときは「画面に反映しました。」と出る。保存形式が同じで画面が変わらなかったときは確認は閉じない。次のときは置き換えない。画面も履歴も変えない。起動の復旧が終わる前、および起動復旧の衝突・ファイル無し・不正控えのダイアログが開いているときは「起動の復旧が終わっていないので、置き換えられません。」詳細パネルまたは一括パネルの入力の途中、開く・保存・別名保存の途中、並べ替えのドラッグの途中、および衝突が無い確認や別のダイアログが開いているときは「画面の操作が途中なので、置き換えられません。」JSON として読めないときは「スケジュールの JSON として読めないので、置き換えられません。」検証に失敗したときは開くときと同じ読み込みエラー。入力が 10MB を超えるときは「スケジュールが大きすぎるため、置き換えられません。」`levels` が無い JSON は段数 3 として扱い、画面が 3 段以外のときは「入れ子の数が、開いている階層の段数と違うので、置き換えられません。」`levels` がある JSON で、渡した段数と入れ子が揃っていないときは「渡したスケジュールの段数と入れ子が揃っていないので、置き換えられません。」`levels` がある JSON で段数と入れ子が揃っているときは、画面の段数と違っても置き換える。

`baseline_diffs` の分類名は、画面のみ、ファイルのみ、同じ、異なる、削除と変更、追加と削除のいずれかである。衝突は、異なる、削除と変更、追加と削除だけである。先行は集合として比べる。並びは結果の id 順で分類する。FILE-07 が並び行を省くときも、結果の順が起点と違えば分類に書く。差分の文章を解釈して分類しない。日付や担当を計算して直さない。1回の呼び出しで、呼び出し開始時点の `baselineJson` と `currentJson` を先に取り、そのあとファイルを読む。

絞り込み条件は、初期値（すべて、空の検索、空のタグ、追加項目の条件なし、系統なし、帯の線が全部表示）を除き、パネルの並びで書く。担当者、ステータス、確度、期限、前後、マイルストン、タグ、帯の線（オフにした帯）、追加項目（効いている定義ごとに、札と同じ文言）、検索（タスク名）、検索（ノート）、系統。担当者、マイルストン、系統、帯の線では、画面が持つ名前を id と一緒に書く。`activeConditions` の担当者は表示名と id だけを書き、説明は載せない。担当の選び方に使う一覧は、同じ応答の `members`（`colors` の次、`fields` の前）に載せる。期限超過と割り当てなしの判定は、画面が使っている今日とメンバー一覧で行う。1回の呼び出しは、送り先 1 ウィンドウ分の応答を、呼び出しの開始時点の画面で組み立てる。送り先 webview からの応答を 5 秒待つ。Windows で名前付きパイプが使用中のときは、応答待ちの前に 5 秒まで接続を試し直す。それでも繋がらなければ、応答が無いときと同じ文を返す。応答が 10MB を超えるときは「応答が大きすぎるため、渡せません。」とし、`isError` にする。

失敗時は JSON-RPC のエラーにせず、ツール結果の `isError` にする。次の文をそのまま返す。

- アプリが開いていない、または GUI へ接続できない: 「スケジュールのウィンドウが開いていないので、渡せません。」
- `window` を省略し、前面に送れる webview が無い: 「前面のウィンドウが開いていないので、渡せません。」
- `window` を省略し、応答が無い、またはウィンドウの世代が合わない: 「前面のウィンドウが応答しなかったので、渡せません。」
- `window` を指定し、生きている webview が無い、または空文字・文字列以外: 「指定したウィンドウが開いていないので、渡せません。」
- `window` を指定し、応答が無い、またはウィンドウの世代が合わない: 「指定したウィンドウが応答しなかったので、渡せません。」

**制約** ブラウザ版には欄を出さない。別の MCP サーバーは立てない。待ち受け TCP ポートは持たない。ローカル連携は、macOS と Linux ではアプリデータの Unix ドメインソケット `mcp.sock`（所有者のみ）、Windows では現在のユーザーの SID を含む名前付きパイプである。リモートからの接続は拒否する。読み取り 7 ツールは画面とファイルを変えない。`replace_schedule` は前面ウィンドウのメモリ上の文書だけを変え、ファイルには書かない。ツール結果に、開いているファイルの絶対パスとホームディレクトリは足さない。`window` を省略した読み取りは、記録の前面、OS の前面、直近の前面順の順で 1 ウィンドウだけ。`--mcp` の起動は 2 つ目のプロセスを既存ウィンドウへ戻す処理に含めない。コピーする JSON は、`mcpServers` の `schedule-viewer` に、実行ファイルのパスを `command`、`--mcp` を `args` として出す。GitHub Releases 版では絶対パスを書く。Microsoft Store 版では `schedule-viewer.exe` の実行エイリアスを書く。パスは JSON の文字列として書き、シェルの引用は付けない。

### MCP-02 MCP を使えないとき、スキルとコマンドで画面の状態を渡す

**操作** デスクトップ版の設定の「画面の状態を渡す」の「MCP を使えないときに渡す」で、Cursor、Claude Code、GitHub Copilot のうち置く先を1つ以上選び、「置く」を押す。置く先を1つも選んでいないときは「置く」と「外す」は押せない。「外す」で、同じ選び方の場所から `read-screen` だけを削除する。

**挙動** 同梱の `read-screen` スキルを、ユーザー全体の `~/.cursor/skills/read-screen/`、`~/.claude/skills/read-screen/`、または `~/.copilot/skills/read-screen/` に置く。指定したプロジェクトフォルダへは置かない。スキル本文には、画面の読み取りと、開いている画面への `replace_schedule` 相当の更新手順を書く。選んだツールすべてへ同じ内容を置く。置くときに、このパソコンの実行ファイルの呼び方をスキル本文へ書き込む。Windows でそのパスが Local AppData 配下のときは、本文に絶対パスを書かない。コマンド例は `"$LOCALAPPDATA/"` に続く相対パスと、`--screen` とツール名を、同じ1行に書く。それ以外のパスは絶対パスのまま書き、実行ファイルの行と `--screen` とツール名の行に分ける。このときはシェル引用で包まず、パスと引数を同じ行に書かない。プレースホルダが残るときは置かない。先に同名フォルダがあれば、置き換えるか設定の中で確認する。中身はマージしない。終わったら置いたパスと、検出した実行ファイルのパスを示す。Windows で Local AppData 配下のとき、スキル本文に書くのは `$LOCALAPPDATA` から続くコマンドであり、検出した絶対パスそのものではない。「外す」は、置くのと同じツール選びで、存在する `read-screen` だけを消す。消す前に確認する。skills フォルダや別名のスキルは残す。`.cursor` と `.claude` と `.copilot` と、それぞれの中の `skills` がシンボリックリンクのときは置かず、外さない。

コマンドは、次の 2 形だけを受け付ける。`--screen` とツール名、または読み取り 6 つに `--window` と内部ラベル。使えるツール名は `open_windows`、`schedule_diff`、`baseline_diffs`、`selected_task`、`selected_tasks`、`filtered_tasks`、`current_schedule`、`replace_schedule` である。`open_windows` と `replace_schedule` に `--window` は付けない。`--screen open_windows --window` と `--screen replace_schedule --window` を付けたときは待ち受けへ送らず、標準エラーに「open_windows は --window を受け付けません。」または「replace_schedule は前面ウィンドウだけを置き換えます。--window は使えません。」を出し、終了コードは 1 である。`replace_schedule` は引数に `--screen replace_schedule` だけを渡し、スケジュール JSON 全体は標準入力から読む。背面を読むときは `--screen <読み取り6つ> --window <label>` とする。Windows で実行ファイルが Local AppData 配下のときは、1 行のコマンド例のうしろに `--window` とラベルを足す。それ以外は、実行ファイルの行、`--screen` とツール名の行に続け、`--window` とラベルを別の行に書く。中身は MCP-01 と同じ待ち受けへ送り、成功時はツール結果のテキストを標準出力へ出す。`isError` のときはその文を標準エラーへ出し、終了コードは 1 である。形が合わないとき、またはツール名が上のどれでもないときは待ち受けへ繋がない。標準入力が 10MB を超えるときは、待ち受けへ送る前に拒否する。

**制約** ブラウザ版には「画面の状態を渡す」欄が無い。指定したプロジェクトフォルダへは置かない。MCP-01 の登録を終えても、このスキル置きは終わらない。逆も同じである。スケジュール JSON を作る SET-05 の 4 スキルとは別である。絞り込みの別実装はスキルに書かない。

## ダイアログ

共通の枠は Escape で閉じ、フォーカスをダイアログ内に留める。開いているあいだは背面を操作できない。

| ダイアログ | 出る条件 | 選択肢と結果 |
| --- | --- | --- |
| タスクの詳細パネル | タスクを選ぶ。バーの本体のダブルクリック、選択中の Enter、右クリックの「編集」 | 項目を確定すると反映。パネルは選択が外れるまで開く。端の当たりでは開かない |
| ノート | ノートアイコン、右クリックの「ノート」、選択中の ⌘/Ctrl+N | 保存でノートを更新。空白だけなら削除 |
| マイルストンの編集 | ひし形またはその右の名前のダブルクリック、右クリックの「編集」 | 保存で名前、日付、確度を更新 |
| マイルストンの追加 | 「マイルストン追加」。日付ヘッダー、マイルストン帯の空き、チャート本体の空きの右クリックの「マイルストンを追加」 | 名前と日付が有効なら末尾に追加。無効なら開いたまま |
| タスクの追加 | 「追加」 | 条件を満たせば末尾に追加 |
| タスクの複製 | 右クリックの「複製」 | 「追加」で同じグループの直後に足す。無効なら開いたまま。閉じると破棄 |
| タスク削除 | 「削除」、Delete、Backspace、右クリックの「削除」 | 「削除」で消す。「キャンセル」で残す |
| カテゴリ・グループの追加 | 左の行の右クリックの追加項目 | 「追加」で足す。無効なら開いたまま。閉じると破棄 |
| カテゴリ・グループ削除 | 左の行の右クリックの「削除」 | 「削除」で消す。「キャンセル」で残す |

| 設定 | ☰ の「設定」 | 表示（サイズと配色）、メンバー、ステータス、稼働日、更新（デスクトップ版）、画面の状態を渡す（デスクトップ版）、JSON作成スキルを置く。メンバーとカレンダーと JSON スキルの上書き確認は設定の中に出る。下に今の版が 1 行出る |

| 書き出し | ☰ の「書き出し」 | HTML、SVG、または Excel（デスクトップ版）を選んで「書き出す」 |
| スケジュールを読み込めません | 開くときの検証、監視、控え、書き出しの失敗 | 「閉じる」。タイトルは失敗の種類で変わることがある |
| 保存できません | 保存の失敗（階層の不一致、検証、書き込み、保存前の確認） | 「閉じる」。本文に理由を出す |
| 未保存の変更 | 未保存で別ファイルを開く。サンプルの未保存で閉じる。サンプルの未保存で更新を入れ直す | 「破棄して開く」、閉じるときの破棄、または入れ直すときの破棄。「キャンセル」で中止 |
| ファイルが更新されています（保存時） | 保存直前にディスクが変わっている | 「上書き保存」「別名保存」「取り消し」 |
| ファイルが更新されています（監視） | 外部更新があり、未保存か編集中 | 分類に応じて「読み直す」「画面の編集を残す」「両方を画面へ反映」または「依頼文をコピー」。同じ変更だけのときは「画面の編集を残す」と「読み直す」 |
| 前回の未保存の編集 | 起動時、控えとディスクが違う。またはファイルが無く未保存がある | 「ファイルを開く」「未保存の編集を戻す」 |
| ファイルが見つかりません | 起動時、前回のファイルが無く未保存も無い | 「閉じる」。サンプルにする |
| 復旧用の控え | 控えが壊れている、またはファイルはあるが検証できない | 「閉じる」「控えを破棄」 |
