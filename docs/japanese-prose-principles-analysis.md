# 日本語ルール — 会話がつらい理由の分析（D1）

利用者が Cursor の Grok エージェントと**直接会話**するとき、日本語ルールは `.cursor/rules/japanese-prose.mdc` と `consult.mdc` に書いてあるが、体感とずれることがある。D1 では AGENTS と同型に、毎回読み込むファイルには短い **J1–J5** だけを置き、具体例は [japanese-prose-examples.md](japanese-prose-examples.md) に分けた。

## 要約（つらさ → 原因 → 原則）

| つらさ | 根本原因 | 原則 |
| --- | --- | --- |
| 結論が後ろに回る | ルールが「段落の書き方」から始まり、チャットで先に結論が目立たない | **J1** |
| 仕様書・英語論文みたい | 英語 blog 調の user rule と日本語チャットが同時に効き、優先が不明 | **J2** |
| 「正本」「入口」が何指すか分からない | 禁止リストが短く、言い換えの型が少ない | **J3** + examples |
| 相談と通常チャットのルールが二重 | consult が毎回読み込まれ、見出し型が目立つ | consult はモード時のみ、examples は型見本 |
| 例が出る／出ないが不安 | 「例は出さない」と直し例が同居 | **J4** |
| プルリクエストだけ直る | 「チャット」節がファイル後方にあった | 冒頭でチャットを明示 |
| ルールが長くて守れない | 50行超を1ファイルに集約 | J1–J5 短文化 + examples |

## 旧ルールの塊 → 原因 → 原則

| 旧 japanese-prose / consult の塊 | 根本原因 | 原則 |
| --- | --- | --- |
| 「どの文章でも」箇条書き | 編集向けチェックがチャットにも効くが、優先順位が無い | J1 |
| 「使わない」 | 比喩語で指すものが決まらない | J3 |
| 「直し方の例」（2ファイル重複） | 1話題の長文見本だけでは他話題に汎化されない | J3 + examples |
| AGENTS 向けの言い換え表（旧 prose） | 実装用語の言い換えが prose に散在 | examples |
| 「チャットの回答」 | 会話調が後ろにあり、英語だけの依頼で英語出力になりやすい | J2 |
| consult「返答の順」 | 相談専用の構造は prose と別物 | session.md（モード時は consult.mdc が誘導） |
| consult「仕様と設計の相談」 | 設計相談の姿勢（推す案一つ） | session.md |
| write-* の日本語 | JSON 不足を推測で埋めない | AGENTS 原則 2 + examples 末尾 |

## 新構造が会話に効く理由

1. **毎回読み込む japanese-prose が 5 原則だけ** — チャット1ターン目から J1 J2 が読める。
2. **examples は参照** — 長い規則を毎ターン生成しなくてよい。
3. **consult はモード限定** — 通常の作業依頼には返答の順を強制しない。
4. **棚卸し** — 旧条文の行き先は [japanese-prose-d1-inventory.md](japanese-prose-d1-inventory.md) に追跡。D1 初版では意味が落ちた文があり、Geo レビュー後に J3 と examples へ復帰した。
