# 回帰確認の通し

自動テストを流したあと、この文書の手動シナリオを順に行う。自動とこの手動が通れば、全機能の確認を終えたことにする。機能の対応は下の一覧、既存の手動ケースの全文と行き先は [regression-tc.md](regression-tc.md) である。

見本は [examples/regression/smoke.schedule.json](../examples/regression/smoke.schedule.json) である。開けないことの確認だけ [examples/regression/open-fail.schedule.json](../examples/regression/open-fail.schedule.json) を使う。階層の線は [examples/hierarchy/](../examples/hierarchy/) の JSON を使う。メンバーとカレンダーは `examples/playground.members.json` と `examples/jp-2026.calendar.json` を使う。

## 自動を先に流す

リポジトリの直下で、Node.js 24 を使う。

1. `npm test`
2. `npm run lint`
3. `npm run check:operation-entries`
4. `npm run check:regression-coverage`
5. `npm run check:madge-circular-baseline`
6. `npm run check:architecture-warn`
7. `npm run test:coverage`
8. `npm run check:schedule`
9. `npm run check:schedule -- examples/regression/smoke.schedule.json`

デスクトップ版の起動が要る確認は、このあとの手動である。カバレッジが床を下回ったら、先に自動を直してから手動へ進む。

## 短い通しと、全体

短い通しは RG-S1 から RG-S5 である。目安は 45 分である。全体は短い通しのあとに RG-F1 から RG-F14 を続ける。目安は 3 時間 30 分である。時間は、見本を開いて手順どおりに進む場合の目安で、不具合の調査は含まない。

各シナリオで、手順の番号ごとに合否と、違ったときは見えた文を記録する。記録の型は末尾にある。

## RG-S1 起動と初回の案内

目的は、初回のカードと案内が、今の文言で出ることである。対象はデスクトップ版の初回相当（開発なら `npm run tauri:dev:fresh`）である。目安は 8 分である。

1. アプリを起動する。サンプルが出る。右下に「はじめての起動」のカードが出る。見出しはサンプルを表示している旨で、項目は「スケジュールを用意する」「操作の案内を読む」「LLM（MCP）とつなぐ」である。「LLM で作る」と「ある JSON を開く」がある。
2. 「操作の案内を読む」を押す。案内に「最初にやる 3 つ」「開く・保存」「画面の見方」「もう少し知りたいとき」がある。閉じる。
3. カードの閉じるを押す。カードが消える。もう一度起動しても、同じ環境ではカードが出ない。
4. タスクを 1 件だけ変える。状態バーに「保存は ☰ または Ctrl+S」（Mac では ⌘S）が出る。保存すると、同じ環境では出なくなる。

記録するのは、カードの有無、案内の 4 見出し、保存ヒントの文言である。

## RG-S2 表示と色

目的は、見本を開いたとき、スクロールと表示の切り替えと、意味のある色が薄くなりすぎないことである。対象はデスクトップ版である。見本は `examples/regression/smoke.schedule.json` である。目安は 10 分である。

1. 見本を開く。タイトルは「回帰確認」である。「調査」「設計」「期限超過の作業」と、空の「後半」、空の分類が見える。
2. チャートをドラッグして動かし、Shift とホイール、日・週・月・全体・今日を押す。左の一覧と縦位置が一緒に動く。
3. ライトとダークを切り替える。進行中の色、期限超過の赤、「調査」の未割当、土日の塗りが、地に溶けて読めなくならない。
4. 左の境界をドラッグして幅を変える。行の名前が、バーと大きく横にずれない。

記録するのは、ずれた箇所と、薄すぎた色の名前である。

## RG-S3 ドラッグと、右クリックの直後

目的は、ポインタでしか見られない確定と、メニューの直後のドラッグである。対象はデスクトップ版である。見本は RG-S2 と同じファイルである。目安は 12 分である。

1. 「設計」のバー本体を 8px を超えて横へ動かし、離す。開始と終了が同じ日数だけ動く。ドラッグ中に月日が出る。Escape で離す前の位置に戻り、取り消しの履歴には乗らない。
2. 端をドラッグして期間を変える。1 日より短くならない。未選択の端をクリックしても、詳細の名前欄へフォーカスが移らない。
3. バーを右クリックする。項目と「ノート」の横のショートカットが出る。メニューを閉じずに、そのままバーを横へドラッグして離す。日付が確定し、取り消し 1 回で戻る。
4. 選択中のハンドルとそのすぐ内側を右クリックする。メニューは出ず、選択も変わらない。
5. 空の「後半」ではない、タスクのある行を 2 件選んで右クリックする。削除だけである。チャートの空白を右クリックすると「マイルストンを追加」だけである。

記録するのは、離したあとの日付と、メニューが出たかである。項目の文言そのものは自動テストで見ている。

## RG-S4 保存して開き直す

目的は、ファイルダイアログを通した保存と、開き直しである。対象はデスクトップ版である。見本は RG-S2 と同じファイルである。目安は 8 分である。

1. バーを 1 本だけ動かす。見出しが未保存になる。状態バーの「未保存」で差分列が開く。
2. 保存する。初めてその見本を保存するときは保存先を聞く。保存後、差分列の差は消える。
3. アプリを終了して起動する。同じファイルが保存済みで開く。
4. 未保存のまま閉じる。次の起動で、その未保存に戻る。

記録するのは、保存先を聞いたか、再起動後のファイル名、未保存が戻ったかである。JSON の中身の一致は自動テストで見ている。

## RG-S5 ブラウザ版との差

目的は、ブラウザ版にデスクトップだけの案内が出ないことである。対象は `npm run dev` のブラウザ版である。見本は同じ JSON をブラウザの開き方で読む。目安は 6 分である。

1. ブラウザ版を開く。初回カードも、保存ヒントも出ない。
2. 設定を開く。「画面の状態を渡す」が無い。
3. 見本を開き、バーはドラッグできる。ファイルの監視では、別のエディタで保存しても画面は変わらない。

記録するのは、無かった欄の名前である。

## RG-F1 日本語変換

目的は、変換中の Enter と Escape が、確定やキャンセルにならないことである。対象はデスクトップ版で、日本語変換が使える OS である。見本は RG-S2 と同じファイルである。目安は 15 分である。短い通しには入れない。

1. 「調査」の詳細で名前を編集し、変換中に Enter を押す。確定しない。変換を確定してから Enter で閉じる。
2. 変換中に Escape を押す。変換がキャンセルされ、欄の確定キャンセルとは別である。閉じたあとの blur で、変換前の文字が保存されない。
3. 見出しのタイトル編集でも、同じことを 1 回行う。
4. 絞り込みの候補を開いたまま変換し、変換中の矢印で強調行が動かない。Enter で候補が確定しない。

記録するのは、誤って確定した欄の名前である。

## RG-F2 メニューと狭い窓

目的は、メニューとショートカット一覧が、狭い窓でも読めることである。対象はデスクトップ版である。見本は RG-S2 と同じファイルである。目安は 10 分である。短い通しには入れない。

1. 窓の幅を狭くする。ツールバーの「案内」「日」「週」「月」「追加」は短いラベルのまま、ボタンの説明は正式名である。
2. ? または F1 でショートカット一覧を開く。1 列に畳まれ、文字が切れない。
3. タスクを右クリックする。メニューが上下に往復せず、画面の中に収まる。
4. ☰ を開き、上下と Home と End で項目を移動できる。Escape で閉じる。

記録するのは、切れたラベルと、画面の外に出たメニューである。

## RG-F3 絞り込みの画面

目的は、絞り込みの操作が画面の上で揃うことである。対象はデスクトップ版である。見本は RG-S2 と同じファイルである。目安は 12 分である。短い通しには入れない。

1. 名前の一部で残す。系統を出す。すべて解除しても、系統は残る。
2. ⌘F または Ctrl+F で検索欄に入る。
3. 担当、ステータス、期限、タグ「回帰」のうち 2 つを試し、札が出る。札を押すと、その条件だけ外れる。
4. 絞り込みを変えると、選択が外れる。

記録するのは、札の文言と、選択が残ってしまった操作である。条件の計算そのものは自動テストで見ている。

## RG-F4 線の見た目

目的は、前後の線と、ドラッグ中の破綻した線が見えることである。対象はデスクトップ版である。見本は RG-S2 と同じファイルである。「設計」は「調査」の後続である。目安は 10 分である。短い通しには入れない。

1. 前後の折れ線が見える。線の上で Delete を押すと線だけ外れ、タスクは残る。取り消しで線が戻る。
2. 「線を引く」で、結ぶと破綻する相手へドラッグする。破綻しそうな線だけが赤く太くなる。Escape で中止する。
3. マイルストン「承認」のひし形と名前が見える。未確定のひし形は中空である。

記録するのは、線が見えなかった箇所と、色が地に溶けた箇所である。

## RG-F5 書き出しの見た目

目的は、書き出した図が画面と大きく違わないことである。対象はデスクトップ版である。見本は RG-S2 と同じファイルと、`examples/hierarchy/levels-3.schedule.json` である。目安は 10 分である。短い通しには入れない。

1. 見本を HTML と SVG で書き出す。左の名前とバーの対応が、画面と大きく違わない。
2. 階層の JSON を HTML で書き出す。段の字下げと親バーが、画面の行と対応する。
3. 書き出し先を空にして確定する。書き出せず、理由が出る。

記録するのは、画面と違った部品の名前である。

## RG-F6 設定の覆い

目的は、メンバー、ステータス、色の編集覆いが、保存後も開き、チャートへ反映されることである。対象はデスクトップ版である。見本は RG-S2 と同じファイルである。メンバーは `examples/playground.members.json`、カレンダーは `examples/jp-2026.calendar.json` を取り込む。目安は 15 分である。短い通しには入れない。

1. 設定のメンバーで「項目を編集…」を開き、表示名を 1 か所変えて保存する。覆いは開いたまま、チャートの担当表示が変わる。
2. ステータスと色でも、同じように 1 か所変えて保存する。バーの色が変わる。
3. 覆いを開いたまま、別のプログラムでスケジュールを更新し、読み直しを選ぶ。読み直しの前に覆いが閉じ、下書きはカタログへ書かない。

記録するのは、反映しなかった種類と、覆いが残ったかである。

## RG-F7 外部更新の対話

目的は、別のエディタで保存したときの確認である。対象はデスクトップ版である。見本を一度保存したパスを使う。目安は 15 分である。短い通しには入れない。

1. 未保存が無い状態で、別のエディタからその JSON を保存する。しばらくして画面が変わり、「ファイルを反映しました」と出る。
2. バーを動かして未保存にし、別のエディタでも別のタスクの日付を変えて保存する。確認が出る。「画面の編集を残す」を選ぶと、状態バーに確認へ戻る操作が出る。
3. 同じタスクの同じ項目を、画面とファイルの両方で変えてから確認を開く。「両方を画面へ反映」は出ない。

記録するのは、確認の見出しと、選んだあとの未保存である。

## RG-F8 起動復旧のタイミング

目的は、起動の復旧が終わる前のドラッグが、日付を確定しないことである。対象はデスクトップ版である。保存済みの見本を使う。目安は 8 分である。短い通しには入れない。

1. 保存して終了し、すぐ起動する。復旧が終わる前にバーをドラッグする。終わるまで日付は変わらない。終わったあと、ドラッグできる。
2. 未保存のまま閉じ、起動する。その未保存の内容に戻る。

記録するのは、ドラッグが効き始めたタイミングと、戻ったファイル名である。

## RG-F9 複数のウィンドウ

目的は、新しいウィンドウと、最近開いたファイルである。対象はデスクトップ版である。見本とは別に、`examples/playground.schedule.json` を使う。目安は 12 分である。短い通しには入れない。

1. 見本を開いたまま、「新しいウィンドウで開く」で playground を開く。元のウィンドウは残る。
2. ☰ の「最近開いたファイル」に両方が出る。履歴が空の開発環境では、開く前は項目が押せない。
3. 同じカタログを編集中に、別ウィンドウからそのカタログを選ぶ。編集中のウィンドウが前面になり、新しい方では選ばれない。

記録するのは、残ったウィンドウと、履歴の並びである。

## RG-F10 階層の線

目的は、段の多い一覧の線と見出しが、画面で揃うことである。対象はデスクトップ版である。ファイルは `examples/hierarchy/levels-5.schedule.json` と `levels-3.schedule.json` である。目安は 12 分である。短い通しには入れない。

1. 5 段を開く。左の縦線が行の境で切れず、折りたたんだ枝の下へ線が続かない。
2. 見出しを右クリックする。段の名前で追加が出る。1 件追加し、取り消し 1 回で戻る。
3. 「階層編集」を開く。段の欄の左端が揃う。意味を空にして適用できない。閉じて、下書きはファイルに残らない。

記録するのは、線が切れた段と、ダイアログで揃わなかった欄である。追加した JSON の形は自動テストで見ている。

## RG-F11 差分列の配置

目的は、差分列が詳細パネルと重ならず、キーの向きが一覧とチャートで分かれることである。対象はデスクトップ版である。見本を保存したパスを使う。目安は 10 分である。短い通しには入れない。

1. 日付を変えて、差分の取っ手を押す。列が開き、変えたタスクの旧値と新値が出る。
2. 詳細パネルを開いたまま列を開く。チャートの幅は、両方を除いた残りになる。
3. 差分の一覧にフォーカスがあるあいだ、上下キーでタスク選択は動かない。チャートへ戻すと動く。
4. コピーの知らせが、差分列の上に重ならない。

記録するのは、重なった部品と、キーがタスク選択を動かしたかである。差分の文面の規則は自動テストで見ている。

## RG-F12 本物の LLM

目的は、人が読んで分かる説明が、画面とチャットの両方に出ることである。対象はデスクトップ版で、Cursor または Claude に MCP を登録してあることである。見本を開いたままにする。目安は 20 分である。短い通しには入れない。クライアントが無いときは、このシナリオを保留と記録する。

1. 設定の「画面の状態を渡す」で JSON をコピーし、クライアントへ登録する。アプリは設定からプロセスを起動しない。
2. 「設計」を選び、「選んでいるタスクを 2 日後ろにずらして」と送る。画面は未保存になり、ファイルの更新時刻は変わらない。「やっぱり戻して」で 1 段戻る。
3. タスクが 2 件以上変わる依頼をする。チャート上の説明用の絞り込みと半透明の両方が出る。チャットでも、何をなぜ変えたかが続く。
4. バーをドラッグしている途中に、破棄なしで計画の更新を頼む。拒否される。離したあとも、拒否前の日付は入らない。

記録するのは、クライアント名、拒否の文、説明が両方出たか、チャットの文が読んで分かったかである。ツールの成功と拒否の計算は自動テストで見ている。

## RG-F13 開けないファイルとエラー

目的は、壊れたファイルと、設定のエラーが見えることである。対象はデスクトップ版である。ファイルは `examples/regression/open-fail.schedule.json` と、見本である。目安は 8 分である。短い通しには入れない。

1. open-fail を開く。開かず、理由が出る。それまで開いていたファイルは残る。
2. メンバー一覧を外した状態で、担当 ID のあるファイルを開く。担当が「メンバー不明」になる。
3. 壊れたカレンダーを設定で読む。カレンダーのエラーが出て、スケジュール自体は開いたままである。

記録するのは、出た理由の文である。

## RG-F14 更新の知らせ

目的は、更新の確認と、Windows の初回起動の警告を、配布物で見ることである。対象は、署名した Windows の配布物があるときだけである。開発ビルドでは行わない。目安は 5 分である。短い通しには入れない。

1. 設定の「更新」で確認する。今の版が最新なら、入れ直す案内は出ない。
2. 初めてその PC で起動するとき、SmartScreen が出たら、出た文言を記録する。開発ビルドでは、この手順を対象外と書く。

記録するのは、出た文言と、対象外にした理由である。
