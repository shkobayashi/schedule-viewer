# チュートリアル

[操作マニュアル](../user-manual.md) の、LLM 連携の流れです。スキルで JSON を作り、アプリで開いて一部を直し、MCP で画面の状態を読んで JSON を直し、ファイルを取り込み直す、という順で進みます。途中の章だけ読んでも構いません。画面の細かい操作は [全機能](features.md) を参照してください。

## スキルを置く

スケジュール JSON・メンバー JSON・カレンダー JSON は、リポジトリにあるスキルを LLM に渡して作ります。スキルは、手順書と検証スクリプトをまとめたフォルダです。

![設定の「JSON作成スキルを置く」欄。置く先と範囲の選択が見える](images/ui-settings-skills.png)

デスクトップ版の設定「JSON作成スキルを置く」で、Cursor、Claude Code、GitHub Copilot のうち置く先を選び、ユーザー全体か指定したフォルダかを選び、write-schedule、write-members、write-calendar、write-workspace、write-fields、write-colors の 6 つをまとめて置けます。GitHub Copilot はユーザー全体なら `~/.copilot/skills/`、チームで残すなら指定したフォルダの `.github/skills/` です。手で `.cursor/skills/` などへコピーして使うこともできます。

上書きの確認、外す、シンボリックリンクのときの扱いは [全機能の「設定」](features.md#設定) にあります。

## メンバーを取り込む

メンバー JSON は `write-members` スキルで LLM に作らせます。書くのは渡した ID と表示名だけで、ID は名前から推測しません。

![設定の「メンバー」欄。取り込みと項目を編集](images/ui-settings-members.png)

できた JSON は、設定の「メンバー」で取り込みます。使うカタログを 1 つ選ぶと、タスクの担当者 ID が名前で表示されます。「項目を編集…」から、主画面の覆いでメンバーを足したり直したりできます。`write-schedule` に渡すプロンプトには、使う担当の ID 一覧も書きます。担当が「メンバー不明」になるときの直し方は [全機能の「困ったとき」](features.md#担当がメンバー不明になる) にあります。

休日の塗りだけを変えたいときは、`write-calendar` でカレンダー JSON を作り、設定の「稼働日」で取り込みます。タスクの日付の計算は変わりません。詳細は [全機能の「設定」](features.md#設定) にあります。

## 色の一覧を取り込む

行の地を塗る色の一覧 JSON は `write-colors` スキルで LLM に作らせます。`id` は、利用者が指定したときだけ書き、名前から作りません。各項目の `description` は、その `id` を選ぶ状態だけを書きます。色の名前や十六進の値は説明に書きません。ライトとダークの地色は、スキルの手順どおりの明るさの範囲に収め、範囲外を黙って置き換えません。

できた JSON は、設定の「色」で取り込み、使う一覧を1つ選びます。設定ファイルでまとめて開くときは、`write-workspace` の `colors` に相対パスを書きます。色の一覧は既定では無く、無くてもスケジュールは使えます。

`write-schedule` は、色を付ける依頼のときだけ、各項目の `description` に合う `id` をタスクの `colorId` に書きます。合う項目が無いときは書きません。二つ以上に合いそうなときは尋ね、答えがあるまで書きません。色の話でない更新では、今ある `colorId` を残します。タスクへの色の割り当ては [全機能の「タスクへの色」](features.md#タスクへの色) にあります。

## スケジュールを作って開く

スケジュール JSON は `write-schedule` スキルで作ります。担当を付けるタスクには、メンバー JSON にある ID だけを使います。ID の一覧を渡していないとき、確度が入力から分からないときは、スキルは JSON を書かず、足りない項目を返します。日付や担当を推測しません。

次のような文を LLM に渡し、角括弧の中を自分の値に置き換えます。

```text
write-schedule スキルに従い、schedule-viewer 用のスケジュール JSON を1ファイルで作ってください。

- プロジェクトの title: （例: 〇〇プロジェクト）
- カテゴリ、グループ、タスクの階層と並び: （WBS の構造を書く）
- 各タスク: name、start、end、confidence（日付を合意したなら committed、まだなら tentative）、assigneeId（未割当は null。一人は id の文字列。二人以上は入れた順の id 配列）、status、progress、predecessors（先行タスクの id。無ければ空）
- 任意: ルートの `connections`（2タスク間の繋がり。`predecessors` とは別。各要素は `taskIds` と `label`）
- 担当者 ID の一覧（assigneeId に使ってよい id だけ）: （メンバー JSON の id を列挙）
- 色の一覧を使うときだけ、各項目の description に合う id を colorId に書く（必須にしない）
- マイルストン（あれば）: name、date、confidence、groupId

検証スクリプトを通してからファイルを渡してください。
```

スキルは書いたあとに同梱の検証スクリプトで中身を確かめます。形式の詳細は [データ仕様](../data-format.md) にあります。

できたファイルを、アプリの ☰ の「開く」で読み込みます。開き方は [全機能](features.md#ファイルを開く保存する) と [はじめに](getting-started.md#ファイルを開く保存する) にあります。

スケジュール、メンバー、カレンダーを同じフォルダに置いてまとめて開くときは、`write-workspace` で `workspace.json` を作ります。任意で `statuses` にステータス一覧 JSON への相対パス、`colors` に色の一覧 JSON への相対パスを書けます。`write-schedule` にその設定ファイルのパスを渡せば、アプリを起動しなくても `schedule` の相対パス先へ書けます。`members` があるときは、そのファイルの id を担当の一覧に使います。`statuses` があるときは、そのファイルの項目の `id` をステータスに使います。`calendar` はスケジュール JSON の日付には使いません。アプリの ☰ の「設定ファイルを新しいフォルダへ書き出す」は、今の画面の写しを空のフォルダへ作る操作であり、開いている設定ファイルは更新しません。設定でチェックしている拡張項目も、同じフォルダに JSON として書き、`workspace.json` の `fieldExtensions` に並べます。`write-schedule` は、その設定ファイルの `fieldExtensions` と任意の `editableFieldExtension` を読み、定義どおりの合成キーで `fieldValues` を書けます。アプリを起動しなくても、スケジュールの追加項目の値を直せます。

![左の一覧、上のツールバー、右のチャート、下の状態バーが並ぶ画面全体（サンプルと同じレイアウトの見本）](images/ui-overview.png)

## 画面で一部を直す

チャートのバーをドラッグして期間を動かすか、タスクを選んで詳細パネルで日付や進捗を直します。

![タスクを選んで開いた詳細パネル。先行、対応マイルストン、タグの欄が見える](images/ui-task-detail.png)

このあと MCP の `schedule_diff` で画面とファイルの違いを読むので、まだ「保存」は押さなくて構いません。編集の詳細は [全機能の「編集する」](features.md#編集する) にあります。

## MCP で一部だけ直す

差分のコピーは、人がテキストを LLM に渡す方法です。MCP は、開いているデスクトップ版の前面ウィンドウを LLM が読み、チャットからの更新を未保存として置き換える方法です。ファイルには自動では書きません。保存するか、取り消すか、手直しするかは人が決めます。

![設定の「画面の状態を渡す」欄。mcp.json への登録と MCP を使えないときのスキル置きが見える](images/ui-settings-mcp.png)

設定の「画面の状態を渡す」で mcp.json に貼る JSON をコピーし、Cursor または Claude の mcp.json へ貼ります。スケジュールのウィンドウを開いたまま、クライアントが同じバイナリを `--mcp` で起動します。設定からプロセスは起動しません。MCP を使えない環境では、同じ欄の「MCP を使えないときに渡す」で `read-screen` スキルを置きます。登録とスキル置きは別の操作です。登録の細部は [全機能の「設定」](features.md#設定) にあります。

読み取りは次の 6 つで、必要なものだけ呼べます。まとめて呼ぶ必要はありません。更新は `replace_schedule` です。

| ツール名 | 渡す内容 |
| --- | --- |
| `open_windows` | 開いているウィンドウ一覧（ファイル名と親フォルダ名。絶対パスは含みません） |
| `schedule_diff` | 今の画面と開いているファイルとの差分テキスト（「差分を表示」と同じ内容） |
| `baseline_diffs` | 最後に開いた・保存した・読み直した起点と、画面とファイルの差分と、変わった id ごとの分類 |
| `selected_task` | 選択がちょうど1件のときのタスク。選択が無いときと2件以上のときは null。選択数が不明なときは `selected_tasks` を使う |
| `selected_tasks` | 編集の選択をタスクの配列で返す。選択が1件でも配列である。選択が無いときは空の配列。選択数が不明なときはこのツールを使う |
| `filtered_tasks` | オンになっている絞り込み条件と、それで残るタスク |
| `current_schedule` | 画面のスケジュール JSON 全体 |
| `replace_schedule` | デスクトップ版が起動しているとき、開いているスケジュールの更新用。スケジュール JSON 全体で前面の未保存を置き換える。成功時は差分テキストだけ返す。新しいファイルの作成には使わない |

引数を省略した読み取りは前面のウィンドウです。別のウィンドウを読むときは `open_windows` で一覧を取り、`window` に `label` を渡します。置き換えは前面だけです。スケジュールのウィンドウが開いていないときは渡せません。ブラウザ版には「画面の状態を渡す」欄はありません。

チャットで起動中のスケジュールを更新するときは、`baseline_diffs` で衝突が無いことを確かめ、JSON の形は `write-schedule` の出力形に従って全体を組み立て、`replace_schedule` で未保存を置き換えます。ファイルは書きません。戻った差分を見て、よければそのまま未保存のままにし、違えば ⌘/Ctrl+Z で取り消すか、画面を手直しします。保存はこの手順ではしません。

```text
schedule-viewer の MCP で baseline_diffs、current_schedule、selected_tasks、filtered_tasks を読み、衝突が無ければ write-schedule の出力形に従ってスケジュール全体を組み立て、replace_schedule で前面の未保存を置き換えてください。ファイルは書きません。戻った差分を見て、更新内容を説明してください。保存はしません。
```

## 取り込み直す

JSON をファイルに書き直したあとは、画面へ反映します。MCP の `replace_schedule` で置き換えただけでは、ディスク上のファイルは変わりません。読み直しでチャットの更新が入ることはありません。

デスクトップ版で、未保存の画面編集が残っているときは、別のプログラムがファイルを書き換えると「ファイルが更新されています」が開きます。あとから同じ確認へ戻るときは、状態バーの「ファイルに更新あり — 確認する」を使います。一覧では画面の変更とファイルの変更が分かれて見えます。画面とファイルが別の箇所だけを変えていて衝突が無いときは「両方を画面へ反映」を選び、保存でファイルへ書きます。同じ箇所がぶつかっているときは「依頼文をコピー」で文をチャットへ貼り、チャットが `baseline_diffs` を読んでどちらを採るか聞いてから `replace_schedule` で画面の未保存を置き換えます。衝突がある確認だけが開いているときは置き換えられます。画面が変わったときは確認が閉じ、未保存になり、約4秒「画面に反映しました。内容を確認して、問題なければ保存してください。」と出ます。起点と同じ内容だけのときは「画面に反映しました。」と出ます。保存形式が同じで画面が変わらなかったときは確認は閉じません。未保存が無いときにスキルが同じファイルを書き換えたときは、内容に問題が無ければ画面へ反映され、隅に「ファイルを反映しました」と数秒出ます。

ブラウザ版では、☰ の「開く」で同じファイルを選び直します。

手順の詳細は [全機能の「ほかのプログラムがファイルを書き換えたとき」](features.md#ほかのプログラムがファイルを書き換えたとき) にあります。

## MCP を使わず差分を渡す

MCP を置いていないときは、☰ の「差分を表示」か、状態バーの「未保存」で、開いているファイルとの違いをチャート右の差分列で見られます。未保存で差があるあいだは取っ手だけ出ます。列の「コピー」か ⌘ または Ctrl+Shift+D で全文をコピーできます。写したテキストを LLM に渡します。デスクトップ版が起動していて、設定で `read-screen` を置いているときは、その画面更新の手順に従い、ファイルは書きません。MCP や `read-screen` が使えないときだけ、`write-schedule` で JSON ファイルを更新します。スケジュール全文を二つ渡さなくても、伝わるのは変更だけです。

![画面と開いているファイルの違いが、チャート右の差分列に出ている状態](images/ui-diff.png)

差分の操作の詳細は [全機能の「ファイルを開く・保存する」](features.md#ファイルを開く保存する) にあります。

## 残した行を書き出す

絞り込みと折りたたみで残した行だけを、☰ の「書き出し」で HTML または SVG にできます。HTML と SVG には、前後の折れ線は入りますが、前後ではない繋がりの円弧と言葉は入りません。行数と図の大きさの上限、書き出しに入る行の範囲は [全機能の「書き出す」](features.md#書き出す) にあります。
